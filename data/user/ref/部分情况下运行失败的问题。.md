## 初步判断

这600个成员中共有30次失败，且**全部集中在115个成员内**：

|区域|失败率|95%精确置信区间|占全部失败|
|---|--:|--:|--:|
|`SLAREF ≤ 270.56`且`TRIFL ≤ 0.68`|31.5%|22.0%–42.2%|93.3%|
|`SLAREF > 270.56`且`SLAVR > 321.81`|7.7%|0.9%–25.1%|6.7%|
|其他组合|0%|上限约0.76%|0%|

第一组合之外只有2/511次失败，失败率为0.39%；第一组合的失败风险约为其余成员的**80倍**。因此第一组合确实是明确的高风险区。

但它仍不是充分条件，因为该区域内还有61个成员正常运行。更准确的表述应当是：

> `SLAREF ≤ 270.56`与`TRIFL ≤ 0.68`共同标识了一个模型脆弱区，真正触发失败的还包括`SLAVR`、其他冠层参数、季节环境或输出提取条件。

# 一、最可能的原因：`SLAREF`和`SLAVR`被错误地当作两个独立参数

这是首先应检查的问题。

在CROPGRO中：

- `SLAREF`是物种文件中的参考比叶面积；
    
- `SLAVR`是品种在标准生长条件下的比叶面积；
    
- 程序内部将品种变量`SLAVR`读作`SLAVAR`。
    

官方代码并不是独立使用二者，而是首先计算：

# [  
M_{\mathrm{SLA}}

\frac{SLAVR}{SLAREF}  
]

然后用这个比例同时缩放：

[  
\begin{aligned}  
F_{\mathrm{initial}} &=  
M_{\mathrm{SLA}}\times FINREF\  
F_{\mathrm{veg}} &=  
M_{\mathrm{SLA}}\times SLAMAX\  
SLA_{\min} &=  
M_{\mathrm{SLA}}\times SLAMIN\  
SLA_{\max} &=  
M_{\mathrm{SLA}}\times SLAMAX  
\end{aligned}  
]

DSSAT源代码中明确采用`DUMFAC = SLAVAR / SLAREF`，并用它缩放上述变量。

因此，同时独立率定`SLAREF`和`SLAVR`会产生：

1. **参数不可辨识**：很多不同的参数组合产生近似相同的比值；
    
2. **极端比值**：一个取下限、另一个取上限时，会把有效SLA推到极端；
    
3. **后验参数相关性**：二者可能出现很强的正相关；
    
4. **数值或生理不一致**：有效SLA超出CROPGRO原有叶面积计算体系的稳定范围。
    

官方番茄文件中，`SLAREF`为300，`SLAVR`也为300；而且番茄品种文件将`SLAVR`标记为不参与标准遗传参数率定，最小值和最大值均固定为300。

这并不表示茄子必须使用300，但说明：

> 原始CROPGRO-Tomato参数体系并不是为“同时自由变化`SLAREF`和`SLAVR`”设计的。

---

## 你的阈值意味着多大的缩放

假设：

[  
SLAREF=270.56,\qquad SLAVR=300  
]

则：

[  
M_{\mathrm{SLA}}=\frac{300}{270.56}=1.109  
]

官方番茄物种文件中的：

[  
SLAMAX=720,\quad SLAMIN=385,\quad FINREF=220  
]

就会被放大为大约：

[  
798,\quad427,\quad244  
]

如果：

[  
SLAREF=270.56,\qquad SLAVR=321.81  
]

则：

[  
M_{\mathrm{SLA}}=1.189  
]

相应参数将被放大约19%。

因此，`SLAREF ≤ 270.56`不只是“参考SLA略低”，而可能通过分母效应使整个有效SLA体系明显增大。

---

# 二、`TRIFL`与SLA体系控制的是两条不同的叶面积形成路径

`TRIFL`在CROPGRO中的定义是：

> 主茎叶片出现速率，单位为叶片数/热力日。

程序将`TRIFL`读作`TRIFOL`，并传入`VSTAGES`计算营养生长阶段`VSTAGE`。

与此同时，`SLAREF`和`SLAVR`控制的是：

> 单位叶片干物质可以形成多少叶面积，以及形成目标叶面积需要多少叶片干物质。

CROPGRO在早期营养生长阶段首先根据`VSTAGE`计算潜在叶面积增量，然后使用SLA变量`F`将叶面积增量转换为叶片干物质需求：

[  
GAINWT=\frac{GAINNW}{F}  
]

并进一步计算分配到叶片的干物质比例`FRLF`。

所以模型中存在两个彼此耦合的约束：

1. **叶片出现和叶序约束**：由`TRIFL → VSTAGE`控制；
    
2. **叶面积—叶片质量约束**：由`SLAVR/SLAREF → F`控制。
    

---

## 第一类失败组合的可能机制

你的高风险条件是：

[  
SLAREF\le270.56  
\quad\text{且}\quad  
TRIFL\le0.68  
]

在其他条件不变时：

- 较小的`SLAREF`倾向于增大(SLAVR/SLAREF)，提高有效SLA；
    
- 较小的`TRIFL`会降低叶片出现速率，使`VSTAGE`增长较慢；
    
- 作物会更长时间停留在早期、由`VSTAGE`约束叶面积形成的计算阶段；
    
- 同时，模型又认为较少的叶片干物质可以形成较大的叶面积。
    

这可能造成以下不一致：

### 1. 叶片数、叶面积和叶片干重不匹配

可能出现：

- 叶片数较少；
    
- 叶片干重较低；
    
- 但模拟LAI相对较高；
    
- 单株平均叶片面积或有效SLA异常。
    

这种组合在计算上未必立即报错，但可能在后续产生异常的：

- 冠层光截获；
    
- 自遮阴；
    
- 叶片氮需求；
    
- 呼吸消耗；
    
- 叶片衰老；
    
- 碳分配。
    

### 2. 早期源—库转换不协调

CROPGRO源代码特别说明，早期叶面积增长由`VSTAGE`限定，之后才逐渐转为受可利用碳和SLA控制；番茄物种文件中的注释也指出，早期LAI对这一转换非常敏感。

低`TRIFL`延缓`VSTAGE`，而高有效SLA改变叶面积所需的碳量，两者可能使源—库转换发生在不协调的冠层状态。

### 3. 作物没有产生PEST要求的目标输出

所谓“成员失败”不一定是DSSAT程序发生浮点崩溃。还可能是：

- 作物未达到某个生育阶段；
    
- 未形成有效果实或产量；
    
- 某个输出变量保持缺失值；
    
- 模拟结束前没有成熟；
    
- 输出文件中缺少PEST指令文件要求读取的记录；
    
- 后处理程序遇到空表、缺失日期或非有限值。
    

在这种情况下，真正失败的是PEST输出提取过程，而不是DSSAT主程序。

---

# 三、不要把`TRIFL ≤ 0.68`直接解释为生理上过低

官方CROPGRO-Tomato生态型文件中：

- 默认`TRIFL`为0.45；
    
- 所列范围为0.40～0.50。
    

因此，相对于原始番茄模板，0.68并不低。

这里的“≤0.68”很可能只是：

> 相对于你本次参数集合中的其他成员较低，或决策树为区分失败与成功而选出的经验切分点。

它不是DSSAT的数值边界，也不是已知的茄子生理临界值。270.56、0.68和321.81这类小数阈值很可能是相邻样本值之间的决策树切点，不应直接作为最终参数上下限。

---

# 四、为什么第一组合中仍有68.5%的成员成功

这说明`SLAREF`和`TRIFL`只是失败的主要条件之一，至少还存在第三个控制因素。

最值得检查的是以下变量。

## 1. `SLAVR/SLAREF`比例

在第一组合内部，将失败和成功成员分别计算：

[  
M_{\mathrm{SLA}}=\frac{SLAVR}{SLAREF}  
]

如果失败成员的该比例明显更高，那么真正的风险条件可能是：

[  
\frac{SLAVR}{SLAREF}>M_{\mathrm{critical}}  
\quad\text{且}\quad  
TRIFL<T_{\mathrm{critical}}  
]

而不是简单的`SLAREF`阈值。

## 2. `SIZLF`

`SIZLF`决定最大完全展开叶片面积。官方模型的早期潜在叶面积还会根据`SIZLF/SIZREF`缩放。

如果同时出现：

- 较低`TRIFL`；
    
- 较高有效SLA；
    
- 较大`SIZLF`；
    

则少量叶片可能被模拟成极大的单叶，进一步放大冠层结构异常。

## 3. `LFMAX`

高有效SLA可能形成较高LAI；如果同时具有较高`LFMAX`，可能造成早期生物量快速增长和后期强烈自遮阴。反之，如果`LFMAX`较低，低叶片出现速率可能导致冠层建立不足。

因此，失败可能发生在`LFMAX`的某一端，而不是简单的线性效应。

## 4. `VSSINK`

官方番茄物种文件明确指出，`VSSINK`对早期LAI发展和由叶面积库限制向碳源限制的转换影响很大。

如果你也率定了`VSSINK`，它应当是重点排查参数。

## 5. 初始叶面积和移栽苗状态

对于移栽茄子，还应检查：

- 初始叶片数；
    
- 初始LAI；
    
- 初始叶片干重；
    
- 苗龄；
    
- 初始`VSTAGE`；
    
- 移栽缓苗参数。
    

低`TRIFL`在直播作物与已有多片真叶的移栽苗上，会产生不同的后果。

# 五、第二个失败区暂时不能作强解释

第二组合为：

[  
SLAREF>270.56  
\quad\text{且}\quad  
SLAVR>321.81  
]

只有26个成员、2次失败，因此7.7%的估计非常不稳定，其95%置信区间约为0.9%～25.1%。

更重要的是，模型主要使用：

[  
\frac{SLAVR}{SLAREF}  
]

而不是两个参数都“大”这一事实。

例如：

[  
\frac{322}{350}=0.92  
]

并不极端；而：

[  
\frac{350}{275}=1.27  
]

则可能很极端。两个组合都满足或接近你的树节点条件，但模型行为完全不同。

因此，这2个失败成员应逐个检查：

- `SLAVR/SLAREF`；
    
- `TRIFL`；
    
- `SIZLF`；
    
- `VSSINK`；
    
- 具体失败季节；
    
- DSSAT退出码和输出文件。
    

目前不建议设置：

```text
SLAREF <= 270.56
或者
SLAVR <= 321.81
```

这样的机械边界。

# 六、先确定“失败”的具体类型

仅靠这张表还不能区分以下四种情况。

## 类型A：DSSAT非零退出或生成错误信息

重点查看：

- DSSAT标准输出和错误输出；
    
- `WARNING.OUT`；
    
- `ERROR.OUT`；
    
- worker目录中的运行日志；
    
- 可执行文件退出码。
    

这通常表示真正的输入、数组范围或模型数值问题。

## 类型B：DSSAT正常结束，但没有达到目标阶段

表现为：

- 没有初花、坐果或成熟日期；
    
- 没有收获记录；
    
- 某些输出为`-99`；
    
- 模拟结束时作物仍未达到目标阶段。
    

这更可能是低冠层增长、物候持续时间或模拟终止日期问题。

## 类型C：DSSAT输出存在，但PEST读取失败

常见原因包括：

- 输出行缺失；
    
- 列位置变化；
    
- 后处理脚本遇到空值；
    
- `NaN`或无穷值；
    
- 三个季节输出合并时观测名缺失；
    
- 上一次运行的残留文件被错误读取。
    

## 类型D：并行运行污染

如果多个PEST++ worker修改了同一个：

- `.SPE`；
    
- `.ECO`；
    
- `.CUL`；
    
- 模型输出文件；
    

可能发生文件竞争。不过，因为你的失败与参数区域高度相关，这不太像主要原因，但仍应通过单worker复现排除。

---

# 七、多季节条件下必须按季节拆分失败标志

建议将一个总的`failed`拆成：

```text
failed_2025_spring
failed_2025_autumn
failed_2026_spring
failed_postprocess
```

其诊断意义不同：

|失败模式|更可能的解释|
|---|---|
|同一成员三个季节都失败|参数结构或数值可行性问题|
|只在低温、低辐射季节失败|冠层建立与环境交互|
|只在高温季节失败|呼吸、光合或生殖温度响应问题|
|只在固定一个试验失败|该季节输入或输出提取问题|
|DSSAT均正常，最终合并失败|后处理脚本问题|

如果第一组合主要在某一个季节失败，就不能把它简单定义为“无效遗传参数区域”，而应分析：

[  
P(\mathrm{failure}\mid  
SLAREF,TRIFL,\mathrm{season})  
]

# 八、推荐使用派生变量重新分析

不要只把三个原始参数输入决策树。建议增加：

# [  
R_{\mathrm{SLA}}

\frac{SLAVR}{SLAREF}  
]

以及：

# [  
I_{\mathrm{SLA-TRIFL}}

\frac{SLAVR/SLAREF}{TRIFL}  
]

还可以加入潜在叶面积出现指标：

# [  
I_{\mathrm{leaf}}

TRIFL\times SIZLF  
]

建议建立如下失败概率模型：

# [  
\operatorname{logit}  
P(\mathrm{fail})

\beta_0+  
\beta_1\log R_{\mathrm{SLA}}+  
\beta_2TRIFL+  
\beta_3  
\left(  
\log R_{\mathrm{SLA}}\times TRIFL  
\right)  
]

由于只有30个失败样本，建议使用：

- Firth校正逻辑回归；
    
- 带正则化的逻辑回归；
    
- 深度不超过2～3的决策树；
    
- bootstrap验证切点稳定性。
    

不要用深树继续寻找很多小样本组合，否则容易把随机特征识别成临界条件。

简单的数据准备方式是：

```python
df["sla_ratio"] = df["SLAVR"] / df["SLAREF"]
df["sla_trifl_index"] = df["sla_ratio"] / df["TRIFL"]
df["leaf_appearance_area"] = df["TRIFL"] * df["SIZLF"]
```

然后分别比较失败和成功成员的分布。

# 九、最建议的参数重构方式

## 方案一：固定`SLAREF`，只率定`SLAVR`

例如固定物种参考值：

[  
SLAREF=300  
]

只率定品种或茄子材料的`SLAVR`。

这与原始CROPGRO参数层级最接近。

## 方案二：固定`SLAVR`，只率定`SLAREF`

当你的目标是开发一个新的茄子物种文件，并且有多个品种共同使用时，可以率定物种层面的`SLAREF`，暂时固定品种修正值。

## 方案三：直接率定一个SLA倍率

这是PEST++实现上最稳妥的方式：

# [  
M_{\mathrm{SLA}}

\frac{SLAVR}{SLAREF}  
]

固定：

[  
SLAREF=300  
]

由运行脚本计算：

[  
SLAVR=300M_{\mathrm{SLA}}  
]

这样参数集合中只存在一个SLA参数，不会出现`SLAREF`和`SLAVR`之间的不可辨识性。

---

# 十、对`TRIFL`应使用观测直接约束

`TRIFL`不宜主要依靠最终产量或LAI间接率定。应根据叶片数观测计算：

[  
TRIFL  
\approx  
\frac{\Delta N_{\mathrm{leaf}}}  
{\Delta PT}  
]

其中：

- (\Delta N_{\mathrm{leaf}})：一段时期内主茎新增叶片数；
    
- (\Delta PT)：同一时期内DSSAT温度函数计算的热力时间。
    

如果茄子具有明显分枝，应确保：

- `TRIFL`只对应主茎叶片；
    
- 分枝叶片不能全部计入主茎叶片出现速率；
    
- 总叶片数与主茎叶片数分开观测。
    

这会显著缩小`TRIFL`的先验范围，减少高风险组合。

---

## 最终判断

目前最有依据的解释是：

> `SLAREF`和`SLAVR`在CROPGRO中主要通过比值共同作用，同时独立率定两者造成了冗余和极端有效SLA；当这种SLA缩放与`TRIFL`控制的叶片出现和`VSTAGE`进程不协调时，早期冠层的叶面积、叶片干物质和碳分配关系进入脆弱区域，从而增加模型未形成完整输出或后处理失败的概率。

建议不要直接把决策树的三个小数阈值写成物理边界。更稳妥的下一步是：

1. 固定`SLAREF`或`SLAVR`中的一个；
    
2. 改为率定(SLAVR/SLAREF)；
    
3. 用主茎叶片数观测约束`TRIFL`；
    
4. 按季节和失败类型拆分失败记录；
    
5. 对28个失败成员和条件内61个成功成员比较`SLA比值、SIZLF、VSSINK、LFMAX`及逐日LAI和叶片干重。
