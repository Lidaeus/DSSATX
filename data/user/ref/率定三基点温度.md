## 结论

**可以检验春、秋季采用不同的温度响应，但不建议直接把春季和秋季分别率定成两套“遗传基点温度”，并将其作为最终品种参数。**

更合理的处理是：

> 三个生育时期分别拥有自己的基点温度，但首先在所有季节间共享；然后把“秋季相对于春季的温度响应偏移”作为一个受约束的附加假设，通过PEST++进行模型比较。

也就是区分两种变化：

[  
\underbrace{T_{b,1},T_{b,2},T_{b,3}}_{\text{生育阶段差异}}  
\qquad\neq\qquad  
\underbrace{T_{b,j,\mathrm{spring}},T_{b,j,\mathrm{autumn}}}_{\text{季节差异}}  
]

前者是DSSAT已有的模型结构；后者属于你额外引入的温度驯化或季节适应机制。

---

# 一、分时期的基点温度是合理的

CROPGRO框架确实使用不同的温度响应函数描述：

- 营养生长期；
    
- 早期生殖生长期；
    
- 晚期生殖生长期。
    

DSSAT文档明确将这些温度响应曲线放在物种文件中，并允许开花前和开花后具有不同的基温、最适温度等温度响应；而品种文件和生态型文件主要保存各个生育阶段所需的生理日数、光周期敏感性以及生长和产量性状。

因此，对于茄子采用：

[  
T_{b,\mathrm{veg}},\quad  
T_{b,\mathrm{early-rep}},\quad  
T_{b,\mathrm{late-rep}}  
]

三个不同参数，是有生理和模型结构依据的。

不同阶段的温度敏感性本来就可能不同，例如：

- 营养生长期主要涉及叶片出现、叶面积扩展和茎生长；
    
- 开花坐果阶段对花粉活力、授粉和果实形成更敏感；
    
- 果实生长期受果实生长速率、呼吸消耗和同化物供应影响。
    

在CROPGRO-Tomato的温度响应改进研究中，也不是简单把整个季节的基点温度改变，而是单独修改了果实形成、果实生长及高温下花器官育性等过程的温度函数。([美国园艺科学学会期刊](https://journals.ashs.org/view/journals/hortsci/47/8/article-p1038.xml?utm_source=chatgpt.com "Improving the CROPGRO-Tomato Model for Predicting ..."))

---

# 二、有温度驯化，不等于应该使用春秋两套固定基点温度

你的生理判断没有问题：同一品种在不同生长温度下可以发生驯化，包括：

- 酶系统和膜系统调整；
    
- 光合最适温度变化；
    
- 呼吸温度响应变化；
    
- 叶片形态与比叶面积变化；
    
- 花粉活力和坐果温度响应变化；
    
- 碳分配和源库关系变化。
    

但这些变化并不一定主要表现为**发育基点温度 (T_b) 的变化**。

## 1. 基点温度只是温度响应曲线的一个组成部分

一个生育阶段的发育进程通常可以表示为：

[  
D_j=  
\sum_t f_j  
\left(  
T_t;  
T_{b,j},T_{\mathrm{opt},j},T_{\max,j}  
\right)  
]

当：

[  
D_j \ge P_j  
]

时，作物进入下一个阶段。其中：

- (T_{b,j})：阶段 (j) 的基点温度；
    
- (T_{\mathrm{opt},j})：最适温度；
    
- (T_{\max,j})：最高温度；
    
- (P_j)：完成该阶段所需的生理日数；
    
- (f_j)：DSSAT中的温度响应函数。
    

温度驯化可能改变：

- 基点温度；
    
- 最适温度；
    
- 高温上限；
    
- 温度响应曲线的斜率；
    
- 最大相对发育速率；
    
- 完成阶段所需的生理日数。
    

因此，仅允许 (T_b) 随季节改变，可能把实际发生在最适温度、呼吸、光合或坐果过程中的变化错误归因于基点温度。

---

## 2. 春季和秋季不是两个稳定温度处理

春季通常是：

[  
\text{较冷} \rightarrow \text{较暖}  
]

秋季通常是：

[  
\text{较暖} \rightarrow \text{较冷}  
]

作物驯化更可能取决于过去若干天或若干周的温度历史，而不是“春季”或“秋季”这个标签。

例如，同一个秋季试验中：

- 定植至开花可能经历高温；
    
- 开花至采收可能经历降温；
    
- 不同生育阶段的驯化方向甚至可能相反。
    

因此，“秋季整季使用一套 (T_b)”本身仍是较粗糙的近似。

---

# 三、目前的数据不足以确认“秋季特异基点温度”

你现有的数据结构是：

- 2025春；
    
- 2025秋；
    
- 2026春。
    

也就是：

[  
n_{\mathrm{spring}}=2,\qquad  
n_{\mathrm{autumn}}=1  
]

这意味着“秋季效应”与以下因素完全混杂：

- 2025年度效应；
    
- 秋季温度效应；
    
- 秋季辐射条件；
    
- 温室覆盖材料和透光率变化；
    
- 苗龄及定植苗大小；
    
- 土壤连续种植效应；
    
- 病虫害；
    
- 整枝和打叶；
    
- 授粉和坐果管理；
    
- 灌溉施肥差异；
    
- 温室通风和湿度条件。
    

因此，即使PEST++得出：

[  
T_{b,\mathrm{autumn}}  
\neq  
T_{b,\mathrm{spring}}  
]

也不能仅凭现有数据证明这是普遍的“秋季温度适应”。它也可能只是2025秋季这一个试验的补偿参数。

特别需要注意的是，DSSAT当前正式支持的作物列表中并没有独立的茄子模型，只有番茄和甜椒等CROPGRO模型。因此，你使用的茄子模型很可能是从CROPGRO-Tomato、CROPGRO-Pepper或其他模板改造而来；此时温度参数实际上属于自定义的物种层参数，而不是DSSAT已有的茄子品种遗传参数。([DSSAT.net](https://dssat.net/plant-growth-modules-in-dssat-csm/ "Crops currently simulated in DSSAT-CSM - DSSAT.net"))

# 四、建议比较三个模型假设

## 模型M0：三个时期不同，但所有季节共享

这是主模型：

[  
T_{b,j,s}=T_{b,j}  
]

其中：

[  
j=  
\mathrm{veg,\ earlyrep,\ laterep}  
]

参数为：

```text
TB_VEG
TB_EREP
TB_LREP
```

三个季节均使用同一组参数。

这是目前最适合作为正式遗传参数率定结果的模型。

---

## 模型M1：共享基点温度＋秋季偏移量

将秋季温度响应写成：

# [  
T_{b,j,s}

T_{b,j}  
+  
I_{\mathrm{autumn},s}\Delta T_{b,j}  
]

其中：

- 春季：(I_{\mathrm{autumn}}=0)；
    
- 秋季：(I_{\mathrm{autumn}}=1)；
    
- (\Delta T_{b,j})：秋季相对于春季的偏移。
    

具体为：

[  
\begin{aligned}  
T_{b,\mathrm{veg,aut}}  
&=T_{b,\mathrm{veg}}+\Delta T_{b,\mathrm{veg}}\  
T_{b,\mathrm{erep,aut}}  
&=T_{b,\mathrm{erep}}+\Delta T_{b,\mathrm{erep}}\  
T_{b,\mathrm{lrep,aut}}  
&=T_{b,\mathrm{lrep}}+\Delta T_{b,\mathrm{lrep}}  
\end{aligned}  
]

但是，不建议一开始就增加三个秋季偏移量。先使用一个共同偏移参数：

# [  
T_{b,j,\mathrm{aut}}

T_{b,j}+\Delta T_{b,\mathrm{aut}}  
]

即所有阶段的基温同时小幅移动。

参数为：

```text
TB_VEG
TB_EREP
TB_LREP
DTB_AUT
```

只有在数据明确显示不同阶段的季节偏移方向不同时，再扩展为：

```text
DTB_VEG_AUT
DTB_EREP_AUT
DTB_LREP_AUT
```

M1适合用于检验“季节驯化是否必要”，但在增加另一个独立秋季试验以前，不适合直接作为最终品种参数模型。

---

## 模型M2：连续的温度驯化模型

从生理角度看，更合理的是令温度响应取决于前期生长温度，而不是春秋标签。

例如定义温度驯化状态：

[  
A_t=  
\overline T_{t-L:t}-T_{\mathrm{ref}}  
]

其中：

- (\overline T_{t-L:t})：过去 (L) 天的平均冠层温度；
    
- (L)：驯化时间窗口，如7～14天；
    
- (T_{\mathrm{ref}})：参考生长温度。
    

然后：

[  
T_{b,j,t}=T_{b,j}+\beta_{b,j}A_t  
]

或者更可能：

# [  
T_{\mathrm{opt},j,t}

T_{\mathrm{opt},j}  
+  
\beta_{\mathrm{opt},j}A_t  
]

这种表达比“春季一套、秋季一套”更符合连续的生理驯化过程。

但是你目前只有三个季节，不适合同时估计多个 (\beta_{b,j}) 和 (\beta_{\mathrm{opt},j})。参数会高度不可辨识。除非以后增加：

- 多个定植日期；
    
- 多个温度处理；
    
- 至少两个独立秋季；
    
- 人工控制的昼夜温度试验。
    

因此M2可以作为后续模型改进方向，目前不宜作为主要率定模型。

---

# 五、PEST++中如何实现季节偏移

PEST++本身不在模板文件中计算参数相加，所以由Python运行脚本完成。

## 1. PEST参数

例如：

```text
tb_veg
tb_erep
tb_lrep
dtb_aut
```

其中：

- `tb_veg`、`tb_erep`、`tb_lrep`是共享参数；
    
- `dtb_aut`是秋季偏移量。
    

## 2. Python中生成季节温度参数

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class TemperatureParameters:
    tb_veg: float
    tb_erep: float
    tb_lrep: float


def get_season_temperature_parameters(
    season: str,
    pars: dict[str, float],
) -> TemperatureParameters:
    is_autumn = season == "2025_autumn"
    offset = pars["dtb_aut"] if is_autumn else 0.0

    return TemperatureParameters(
        tb_veg=pars["tb_veg"] + offset,
        tb_erep=pars["tb_erep"] + offset,
        tb_lrep=pars["tb_lrep"] + offset,
    )
```

随后分别将结果写入三个季节对应的DSSAT物种文件副本：

```python
for season in [
    "2025_spring",
    "2025_autumn",
    "2026_spring",
]:
    temperature_pars = get_season_temperature_parameters(
        season,
        pest_parameters,
    )

    write_species_file(
        season=season,
        tb_veg=temperature_pars.tb_veg,
        tb_erep=temperature_pars.tb_erep,
        tb_lrep=temperature_pars.tb_lrep,
    )

    run_dssat(season)
```

每个PEST++工作进程必须使用独立目录，避免不同集合成员同时修改同一个物种文件。

---

## 3. 对秋季偏移施加强先验约束

对：

```text
dtb_aut
```

不应给予与基础温度相同的宽范围。应使它围绕0变化：

[  
\Delta T_{b,\mathrm{aut}}  
\sim N(0,\sigma_\Delta^2)  
]

这相当于表达：

> 默认认为不存在季节差异，只有数据提供足够证据时才允许出现偏移。

在PEST++中可以通过以下方式实现：

- 参数上下限设得较窄；
    
- 在PESTPP-IES先验参数集合中使`dtb_aut`均值为0、标准差较小；
    
- 在GLM中加入指向0的先验信息方程；
    
- 对偏移参数单独设立参数组。
    

概念上的先验信息为：

[  
1.0\times \Delta T_{b,\mathrm{aut}}=0  
]

权重由你允许的季节差异大小决定。

不建议没有试验依据就允许秋季基点温度上下变化5～10 ℃，因为PEST++很容易利用这一自由度补偿其他误差。

# 六、基点温度与阶段持续时间可能严重相关

DSSAT中的物候预测同时受以下两类参数控制：

1. 温度响应曲线；
    
2. 完成阶段所需的生理日数。
    

例如营养生长期：

# [  
\sum_t f_{\mathrm{veg}}(T_t,T_{b,\mathrm{veg}})

P_{\mathrm{veg}}  
]

在有限温度范围内，以下两种改变可能产生相似的开花日期：

- 降低 (T_{b,\mathrm{veg}})，使每日发育进程增加；
    
- 减小 (P_{\mathrm{veg}})，使完成该阶段所需积累量减少。
    

因此：

[  
T_{b,\mathrm{veg}}  
\longleftrightarrow  
P_{\mathrm{veg}}  
]

容易出现参数等效性。

如果同时自由率定：

```text
TB_VEG
EM_FL
DTB_AUT
```

但只有三个季节的开花日期，参数通常难以唯一识别。

建议分两步：

### 第一步

固定或严格限制阶段持续时间，率定三个阶段基点温度。

### 第二步

在确定基点温度的合理范围后，率定品种阶段持续时间。

或者反过来：

- 先依据独立温度试验确定基点温度；
    
- 再使用多季节田间或温室数据率定品种生理日数。
    

第二种方法在生理解释上通常更可靠。

---

# 七、什么情况下可以接受秋季偏移

至少需要满足以下大部分条件。

## 1. 偏差出现在物候变量，而不只是产量

如果秋季只有产量拟合不好，而：

- 开花日期；
    
- 坐果日期；
    
- 首次采收日期；
    
- 叶片出现速率；
    

均拟合良好，就不应该通过改变基点温度解决产量偏差。

此时更应检查：

- 花粉育性温度函数；
    
- 高温或低温坐果率；
    
- 果实添加速率；
    
- 果实潜在生长速率；
    
- 光合温度函数；
    
- 夜间呼吸；
    
- 辐射和温室透光率。
    

## 2. 多个物候阶段出现同方向偏差

例如共享参数模型在2025秋季中同时表现为：

- 模拟开花偏晚；
    
- 模拟坐果偏晚；
    
- 模拟首次采收偏晚；
    
- 偏差随低温暴露程度增加。
    

这种情况下，秋季温度响应差异的解释才更有依据。

## 3. 偏移量后验明显离开0

应检查：

[  
P(\Delta T_{b,\mathrm{aut}}>0)  
]

或：

[  
P(\Delta T_{b,\mathrm{aut}}<0)  
]

是否非常集中，而不是后验区间仍跨越0。

同时应更换：

- 参数先验范围；
    
- PEST++随机种子；
    
- 参数集合规模；
    
- 观测权重；
    

检查偏移量方向是否稳定。

## 4. 改进不只发生在率定数据

这是你目前最难满足的条件。

由于只有一个秋季试验，秋季偏移参数必然会利用2025秋季数据率定，同时又用2025秋季数据评价，因此不存在独立的秋季验证。

在增加2026秋或2027秋数据之前，只能把它表述为：

> 2025秋季条件下的温度响应修正。

不能稳健地表述为：

> 该茄子品种普遍存在春秋季不同的基点温度。

---

# 八、优先检查温室温度输入

在引入季节性基点温度之前，应优先确认使用的是：

- 温室内温度，而不是室外气象站温度；
    
- 冠层附近温度，而不是温室顶部温度；
    
- 小时温度，而不仅是日最高和最低温度；
    
- 夜间温度记录；
    
- 通风、加温、保温幕启闭后的实际温度；
    
- 传感器经过校准且三个季节安装位置一致。
    

CROPGRO的发育温度和光周期效应以小时尺度计算，因此温室内部的逐时温度轨迹比简单日均温更重要。([DSSAT.net](https://dssat.net/csm-cropgro-soybean/?utm_source=chatgpt.com "CSM-CROPGRO-Soybean"))

温室中还可能出现：

[  
T_{\mathrm{leaf}}  
\neq  
T_{\mathrm{air}}  
]

特别是在：

- 春季高辐射、通风不足；
    
- 秋季低辐射、高湿度；
    
- 覆盖材料改变；
    
- 补光或加温条件变化；
    

的情况下。若实际生长点或冠层温度与输入气温存在季节性偏差，PEST++会把这种输入误差吸收到 (T_b) 中。

---

# 九、针对你现有数据的推荐方案

## 正式率定模型

使用三个共享的阶段性基点温度：

[  
T_{b,\mathrm{veg}},  
\quad  
T_{b,\mathrm{erep}},  
\quad  
T_{b,\mathrm{lrep}}  
]

同时用于2025春、2025秋、2026春。

这组结果作为正式的物种或温度响应参数。

## 对照模型

增加一个受强约束的秋季偏移量：

[  
\Delta T_{b,\mathrm{aut}}  
]

先只使用一个共同偏移量，而不是三个阶段各一个。

比较：

[  
M_0:  
\quad  
T_{b,j,s}=T_{b,j}  
]

与：

# [  
M_1:  
\quad  
T_{b,j,s}

T_{b,j}  
+  
I_{\mathrm{autumn},s}\Delta T_{b,\mathrm{aut}}  
]

## 评价内容

重点比较：

|评价项目|M0共享模型|M1秋季偏移模型|
|---|--:|--:|
|春季物候误差|检查|检查|
|秋季物候误差|检查|检查|
|2026春独立验证|检查|检查|
|参数后验宽度|检查|检查|
|参数相关性|检查|检查|
|秋季偏移是否跨0|—|检查|
|是否只改善产量|—|检查|
|是否产生不合理温度参数|检查|检查|

现阶段最稳妥的论文表达是：

> 本研究首先假定同一品种的阶段性温度响应在季节间保持一致，同时构建包含秋季温度响应偏移量的扩展模型，以检验季节性温度驯化假设。由于仅包含一个秋季试验，季节偏移参数作为结构不确定性和敏感性分析结果，而不直接作为稳定遗传参数。

因此，**分三个生育时期率定不同基点温度是合理的；春秋两套基点温度可以作为待检验模型，但以目前“两春一秋”的数据结构，不建议直接作为最终遗传参数。**最需要补充的是另一个独立秋季试验，或者多个受控温度处理。
