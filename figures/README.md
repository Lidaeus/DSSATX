# figures/ — diagnostic and paper figure outputs

This directory holds generated figures, kept separate from `workspace/runs/`
(which holds raw simulation/calibration artifacts). Two sub-tracks mirror the
project's dual-track figure rule (see `docs/科研图表设计与开发计划.md`):

- `figures/diagnostics/<batch_name>/` — **Python run-diagnostics** (`timeseries_*`,
  `scatter_*`, `residual_*`, `bar_*`). One subdirectory per calibration batch,
  named after the calibration run. These are internal diagnostics; they never
  carry `Fig`/`FigS` numbers and never enter the paper.
- `figures/paper/` — **R paper figures** (`Fig*`/`FigS*` + source CSV + manifest),
  produced by the `paper/R/` track from frozen `paper_data` bundles (Track B).

Each batch's diagnostic set is (re)generated by:

```bash
python tools/calibration/run_dynamics_pipeline.py --tag <batch_tag>
```

where `<batch_tag>` maps to a calibration run (see `BATCHES` in that script).

The diagnostic batch root also contains `response_structure_audit.png` and
`response_structure_audit.csv`. This results-first audit compares the final
observed/simulated value for each W×N treatment and reports
SD(simulated-treatment values) / SD(observed-treatment values); values below
one indicate compressed treatment response. It is a diagnostic artifact only,
not a paper figure.

The cumulative-yield panels separate the continuous model fruit-mass trajectory
from observed harvest events: the model is drawn as a blue line, while observed
cumulative harvest is shown only as W×N points with audited +/-1 SE error bars;
observed points are not connected. The
batch root also contains `yield_curve_source_audit.csv`, which records whether
`PlantGro.OUT` `GWAD` passed the monotonicity/scale gate or whether the figure
used the auditable `FreshWt.OUT` reconstruction. These visual trajectories are
diagnostic only and never replace the raw harvest-event pairs used for metrics.
