| 季节 | 路径 | 关键列 |

### 7.2 FreshWt.OUT（模拟日数据）—— 产量

每季 `_seasons/<season>/FreshWt.OUT`，`*RUN N` 分块，`@YEAR DOY ... CHPDT CHFPW`：
- `CHPDT`/`CHFPW` 为累计量；在非采收日保持前值（阶梯），采收日跳增。

### 7.3 PlantGro.OUT（模拟日数据）—— LAI / 生物量 / 物候

每季 `_seasons/<season>/PlantGro.OUT`，`*RUN N` 分块，`@YEAR DOY DAS DAP ... LAID LWAD SWAD ... WSPD WSGD`：
- `LAID` 为每日模拟值（连续曲线）。

### 7.4 SOIL.SOL（土壤剖面）

bundle 内的 `SOIL.SOL`，剖面 `IBTM910017`，8 层（20/40/60/80/100/145/175/203 cm）。
- 当前管线正确读入 bundle 的 SOIL.SOL（经 FILEIO 验证）。
- DSSAT v4.8 水平衡中 **SSKS 不影响排水**（排水由 SLDR 控制，持水由 SLLL/SDUL/SSAT 控制）。

## 八、已知的物理 / 数据注意事项

1. **果实含水率（DMFR）固定**：模型对所有处理用恒定 DMFR≈5.2%，而实测含水率因胁迫而异（W1N0 实测仅 3.2%）。导致鲜重接近 1:1 但干重在胁迫处理上系统性偏高。若要改善 dry 的拟合，应将 DMFR 纳入率定。
2. **25FA 秋季失拟**：best179/median179 参数组在秋季模拟产量严重偏低（~521 vs 观测 1100–1587 kg/ha），且全部处理趋同——参数组仅在 25SP+26SP 四角上率定，不适用于秋季。
3. **layermean IC 过冲**：layermean 版率定让 N0/N3 分离从无到过冲（sim 0.34 vs obs 0.74），说明 IC 策略需更精细。
4. **26SP 氮响应弱**：26SP 观测 N0/N3≈0.89（几乎无氮响应），与田间高初始氮一致。

### 13.4 产量动态图算法（GWAD 门控 + FreshWt 重建）

**物理背景**：`FreshWt.OUT` 的 `CHPDT`（累计已采收干果重）在非采收日是阶梯平台；`TOFPW`（植株上鲜果总重）在采收日**骤降**（果实被摘走）。所以"植株累计已产果实"= `CHPDT + TOFPW×DMC` 是锯齿状的。

**已修复的关键 bug**：在当前 DSSAT 输出格式中，采收事件行的 `CHPDT/CHFPW` 已经包含当天采收增量，但同一行的 `TOFPW` 仍是采收前的植株果重。直接相加会把当天被采收的果实重复计算，第一次采收处产生猛烈假跳变。现在对采收行使用下一日的采收后 `TOFPW`；若采收发生在输出末行，则不再添加未知的采收后挂果量。

**旧法问题**：`cummax(CHPDT + TOFPW×DMC)` 会在两次采收之间出现**平坦段**——因为采收后植株果重骤降，要等几天重新生长超过上次峰值，cummax 一直锁在旧峰值，曲线不平滑。

**当前法**（`_cumulative_fruit_curve()`）：
1. 先读取 `PlantGro.OUT` 的 `GWAD`，检查有效点数、日序列单调性以及与 `FreshWt.OUT` `CHPDT` 的量级一致性；
2. 三项检查均通过时，直接绘制 `GWAD` 日轨迹，不做未记录的单位换算；
3. 检查失败时，取 `raw = CHPDT + TOFPW×DMC`（干）或 `CHFPW + TOFPW`（鲜）；
4. 仅保留**创新高的峰值点**（`raw == cummax(raw)`），再用 `PchipInterpolator` 在完整 DAP 网格上保形插值；
5. PCHIP 超出最后一个峰值后保持末峰值，禁止外推造成假性终端下降；
6. 图中观测采收事件只绘制 W×N 标记和审计后的 ±1 SE 误差棒，不连接实测点；曲线只用于视觉解释，原始事件节点仍用于指标计算。

DMC 用 `_VISUAL_DMC = 0.05`（与率定批次名 `dmc5` 一致）。**纯视觉，绝不进任何指标。**

## 十四、需要协作者协助的难题

以下问题已识别但**未解决**，需要领域判断或额外数据，请协作者评估：

### 14.1 【模型结构】25FA 的 LAI 系统性失拟（最严重）

所有 posterior_soil 系列 + softn 批次在 **25FA 的 LAID** 上 `MSE_s/MSE` 高达 **99%+**，OLS slope 仅 **0.08–0.16**——模拟 LAI 几乎不随处理变化，而实测 LAI 跨处理差异明显。这不是绘图问题，是**模型/参数结构问题**：
- 25FA 是跨年秋季（播种 8 月初，收获至次年 1 月），光温环境与两春季差异大；
- 当前参数在 25FA 上无法复现水氮处理的 LAI 分离；
- **需协助判断**：是否应纳入秋季有效偏移（如 `LFMAX`/`SLAVR` 的 25FA 偏移）？还是 LAI 失拟源于物候（`EM-FL`/`FL-LF` 在秋季的发育进程）？需结合农学判断决定 E05 偏移候选。

### 14.2 【模型结构】25FA 产量处理间差异被压平

25FA 12 个处理的最终 sim dry-cum 几乎全部聚到同一值（如 softn 批 ~767 kg/ha），而实测跨 635–949。`MSE_s/MSE` 在 25FA 达 **60%**，26SP 达 **49%**——系统偏差占主导。25SP 仅 15% 表现良好。
- **需协助判断**：是否因为 25FA 田间高初始氮掩盖了氮响应（交接文档第八节提到 26SP N0/N3≈0.89）？还是果实含水率 DMFR 固定（5.2%）导致胁迫处理干重系统性偏高？

### 14.3 【数据】果实含水率 DMFR 固定 vs 实测变化

模型对所有处理用恒定 DMFR≈5.2%，但实测含水率因胁迫而异（W1N0 实测仅 3.2%）。导致鲜重接近 1:1 但干重在胁迫处理上系统性偏高。当前 `_VISUAL_DMC=0.05` 只是视觉平滑用的固定值。
- **需协助判断**：是否将 DMFR 纳入率定？若纳入，需同批鲜/干重或含水率的质量观测，并定义为独立审计过的观测（不可从 CHFPW+CHPDT 反推后三重计权，见 `参数率定试验矩阵` §2.2）。

### 14.4 【工程】obsgnme 解析的脆弱性

`_load_obs_sigma()` 依赖 `obgnme` 的下划线分段（`25SP_LAIDM_D25120`）。不同批次的物候观测 obgnme 格式不同（如 `25SP_PDAPM` 仅 2 段无日期后缀），已加兼容但若未来新增观测类型仍可能出错。
- **建议**：observation_registry 应直接输出结构化的 `variable`/`date_code`/`harvest_number` 列，而非依赖 obgnme 字符串解析。

### 14.5 【未完成】Track B（R 论文轨道）

当前全部是 Python 诊断图（`timeseries_*`/`scatter_*`，150 dpi PNG，按双轨制**不能进论文**）。论文级图须走 `paper/R/`（`fig_selected_dynamics.R` 等）从冻结 `paper_data` 包渲染，输出 PDF/SVG/PNG + manifest。

### 14.6 【未验证】确定性重跑与 PEST 运行期的一致性边界

当前确定性重跑（best member 单组参数）的拟合与 PEST 运行期 pairs 一致（已验证 dry-cum）。但 LAID/LWAD/SWAD 的日轨迹**未逐日比对** PEST 运行期的 PlantGro.OUT——理论上应一致（同参数同输入），但若 run_dssat 的注入路径有细微差异可能产生偏差。

原有 `scatter_*.png` 能回答“模拟值是否接近观测值”，但不能直接回答“模拟是否保留了 W×N 处理差异”。因此新增 `response_structure_audit.png/.csv`：

### 14.8 产量动态图：连续果实轨迹与采收事件分层表达（2026-08-02）

产量动态图现在明确区分两个时间过程：

- 蓝色实线：模型的连续果实质量轨迹，仅用于展示生长过程；
- W×N 标记 + ±1 SE 误差棒：观测的累计采收量，仅表达实际采收事件，不连接稀疏实测点。

代码会先检查 `PlantGro.OUT` 的 `GWAD` 是否同时满足：

1. 至少有 4 个有效日值；
2. 随 DAP 单调不下降；
3. 末值与同处理 `FreshWt.OUT` 的 `CHPDT` 处于可比量级（当前采用 0.25–4 倍的保守门槛）。

只有通过三项检查时，才直接绘制 `GWAD`。不通过时不做未记录的单位换算，而使用可审计的 `FreshWt.OUT` 重建：

- 干重视觉轨迹：`CHPDT + TOFPW × DMC`；
- 鲜重视觉轨迹：`CHFPW + TOFPW`。

当前 `e02_joint62_softn_response_95pct_dmc5_formal_200x5_20260802` 三季输出中，`GWAD` 均出现采收节点下降，且末值仅约为 `CHPDT` 的 0.014–0.004 倍，因此全部被拒绝为直接累计曲线。具体处理、原因、末值和量级比写入批次根目录的 `yield_curve_source_audit.csv`。

这一动态图及其视觉曲线不参与 RMSE/RRMSE/NSE/Phi 计算；正式评价仍使用原始采收事件配对值。若未来确认某一 DSSAT 模块中 `GWAD` 的单位和语义确实是累计果实干重，应先补充模块级验证，再放宽该自动门控。
