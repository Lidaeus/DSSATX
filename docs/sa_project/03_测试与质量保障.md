# 敏感性分析测试与质量保障

> 文档状态：当前专题规范
> 更新日期：2026-07-15
> 实施状态：P0 建立最小质量门，P1 完成稳定性与收敛测试

## 1. 两类质量检查

SA 必须同时通过：

- **软件质量**：导入、单元测试、格式解析、隔离运行和错误处理正确；
- **科学质量**：参数扰动产生有效输出变化，设计样本执行完整，敏感性指标非退化且稳定。

Lint、类型检查或退出码为 0 都不能替代科学质量检查。

## 2. 测试层级

### L1：纯函数单元测试

覆盖参数名/组映射、固定宽度格式、边界关系、输出解析、缺失值、指标计算、多输出尺度和排名。测试应使用小型固定样例，不依赖本机 DSSAT。

### L2：DSSAT 数值烟雾测试

使用一个最小处理运行基线、单参数扰动和多参数扰动，验证：

- 使用的是本次生成的输入文件；
- 输出时间戳和哈希发生预期变化；
- 关键指标为有限数；
- 至少一个预期指标变化超过容差；
- `-99`、空输出、旧文件和解析错位被判为失败。

### L3：微型 Morris 集成测试

用少量参数和轨迹贯通“构建—运行—解析—后处理—质量报告”。至少设置一个已知有影响和一个无影响参数，以检查排序方向。全零敏感性必须令质量门失败。

### L4：微型 Sobol 集成测试

使用可手工判断的合成函数验证 `S1/ST`，再用少量 DSSAT 参数验证真实入口。检查样本量公式、参数顺序、失败成员处理和置信区间输出。

### L5：案例回归测试

冻结一个小型真实案例的输入和允许区间，比较结构、有效率和指标范围，不要求浮点结果逐位一致。软件或 DSSAT 版本变化时必须更新理由。

## 3. 强制科学质量门

默认阈值写入版本化配置，不能散落在代码中。至少包含：

| 检查 | 失败条件示例 |
|---|---|
| 输入合法性 | 参数越过硬边界、跨参数关系错误、重复名称 |
| 运行有效率 | 低于项目批准阈值 |
| 输出完整性 | 缺列、空文件、`-99`、NaN/Inf 超阈值 |
| 输出变异性 | 所有目标输出方差低于数值容差 |
| 参数作用 | 预期可作用参数扰动后全部输出不变 |
| Morris 非退化 | 全部 `mu*` 为零/缺失，或有效轨迹不足 |
| Morris 稳定性 | 多种子 Top-K 重合/秩相关低于阈值 |
| Sobol 收敛 | 区间过宽、样本扩增后排名不稳定 |
| 可追溯性 | 缺 `run_manifest`、种子、输入哈希或质量报告 |

阈值在 P1 用当前案例和计算预算制定；P0 先实现“明显错误必须失败”的硬门。

## 4. 失败注入

测试必须主动制造以下故障，确保系统不会给出貌似正常的排名：

- DSSAT 可执行文件不存在；
- 模板参数未注入或名称拼错；
- 所有运行读取同一旧输出；
- 输出解析列偏移；
- 某些成员超时或返回 `-99`；
- 参数范围为零或越界；
- 输出为常量；
- 指标量纲差异导致聚合排名被单组完全支配。

每种故障都应在 `quality_report` 中有稳定错误码和可操作说明。

## 5. 重复性与稳定性

Morris 至少使用多个随机种子，报告 Spearman 秩相关、Top-K 重合率和关键参数名次范围。Sobol 至少报告置信区间或 bootstrap 误差，并通过增加基础样本量检查主要结论是否稳定。

随机种子必须记录，但“同一种子结果一致”只证明可重复，不证明结果稳定。

## 6. 多输出检查

聚合前为每个输出保存原始敏感性结果和预声明尺度。测试应构造量级差异明显的输出，证明聚合排名不会仅由单位大小决定。任何尺度变更都需要新配置版本和结果对比。

## 7. 当前命令与实施边界

仓库级代码检查从项目根目录执行：

```powershell
python -m pytest tests -q
python -m compileall src tests tools
```

在 P0 修复标准入口前，本文不把历史 `Workspace/Sensitivity_Analyze` 命令列为正式命令。P0 验收后补充经过 L2/L3 覆盖的 CLI；P1 再补充生产规模 SA 命令。

## 8. 发布条件

一份 SA 结果只有在以下条件同时满足时才能标为 `science_validated`：

1. L2 数值烟雾测试通过；
2. 生产运行有效率和输出完整性通过；
3. Morris 或 Sobol 对应质量门通过；
4. 输入、种子、版本、结果表和图表完整；
5. 参数提案经过人工审核，且与结果 `run_id` 建立关联。
