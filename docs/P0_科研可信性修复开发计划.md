## 1. P0 目标

P0 不追求得到最终茄子参数，也不启动正式论文计算。它只解决一个前置问题：

> 证明项目中的候选参数能够被正确注入 DSSAT、产生可检测的模型响应，并且敏感性分析和 IES 能对这种响应给出非退化、可追溯、失败时会主动中止的结果。

P0 完成意味着“研究流水线具备产生可信结果的必要条件”，不意味着模型已经率定良好，也不意味着参数已经具有唯一生理解释。

## 2. 只读审查基线

以下问题来自本轮只读审查，将作为 P0 的初始失败案例和回归依据。

### 2.1 入口、路径和环境

- README 推荐的 `python src/calibration/build_pest.py` 会因相对导入失败；workspace stub 使用 `exec()`，存在相同问题。
- `build_pest.py::_project_root()` 在当前目录结构下返回 `src/calibration`，导致有效 `--bounds-id` 无法解析。
- `src/reporting/analyze_results.py` 和旧可视化模块仍硬编码 `C:\DSSAT48\Tomato_Cal\Workspace`、固定前缀或固定后验迭代。
- 仓库没有统一依赖清单；当前 `.venv` 缺少 `pyemu`，系统 Python 与虚拟环境能力不一致。

### 2.2 冻结边界

`data/parameter_registry/bounds_frozen/eggplant/eggplant_v14_20260405.csv` 当前有 8 条不满足 `lower <= init <= upper` 或 `lower <= upper` 的记录，例如：

- `WTPSD` fixed 记录的 lower 与 init/upper 不一致；
- `FL-LF`、`SD-PM` 初值高于 upper；
- `SDPDV` lower 高于 upper，且初值越界；
- `PARMAX`、`FINREF` 的初值和上下界关系非法。

该冻结文件含 101 个 active 参数，其中包括大量 SOIL 和 IC 参数，与“实测土壤/初始条件默认固定”的近期研究策略不一致。

### 2.3 当前敏感性分析

- `workspace/runs/test_sa_workflow` 完成了 408 个 Morris 模型运行且进程退出码为 0；
- 但生成的全部 elementary effects、均值绝对敏感度和标准差均为 0；
- `workspace/runs/morris_results/morris_onepage_summary.md` 因此给出全部为 0 的排名；
- 当前流程没有把这一结果判定为失败。

仓库历史版本曾生成非零 Morris/Sobol 结果，说明现有问题更可能来自重构后的参数注入、运行目录或输出回收链，而不是 DSSAT 模型天然不敏感。

### 2.4 当前 IES 率定

`workspace/runs/eggplant_stage2_v14_improved` 的只读统计显示：

- 参数 ensemble 有 80 个 realization、43 个参数，其中 39 列先验存在取值差异；
- 200 个模拟观测列在所有 realization 间均无实质差异；
- observation ensemble 最大标准差约为浮点舍入量级；
- iteration 0–3 的 mean/min/max Phi 均约为 `2.61697e14`；
- iteration 3 参数均值相对 iteration 0 没有变化。

因此该运行不能解释为“收敛”，而应判为前向模型对候选参数无响应或结果回收错误。

### 2.5 权重实现

当前实现需要重点验证：

- 多处将 PEST weight 写成 `1 / sigma^2`。由于 PEST Phi 使用平方后的加权残差，若 sigma 是观测标准差，通常应使用 `1 / sigma`；
- log transform 目前主要改变 effective sigma，没有确保 PEST 比较的是变换后的观测与模拟；
- pwtadj1 计算使用完整观测组名，而 sigma 字典部分使用变量根名，可能导致平衡结果未实际应用；
- 异常路径存在静默 fallback，容易让“已启用改进权重”与实际行为不一致；
- 累积采收观测被作为多个独立点使用，存在时间相关和重复计数风险。

- 修改原始观测数据；
- 删除、覆盖或“清理”现有未提交文件与历史结果。

## 4. 实施原则

1. 先建立失败测试，再修改代码；
2. 不用交换上下界、自动扩边界等方式掩盖非法冻结文件；
3. 不以退出码 0 作为科研任务成功；
4. 不以固定的预期产量值做脆弱测试，优先验证响应方向、非零差异和结构不变量；
5. 外部 DSSAT/PEST++ 测试与纯 Python 测试分层；
6. 现有 dirty worktree 中的用户改动全部保留，P0 只触碰批准范围内文件；
7. 旧冻结边界和旧运行目录保留原样，新结论使用新 ID 和新 run_dir；
8. P0 发现新的科学决策时暂停并提交审核，不擅自改变参数政策。

## 8. 风险与处置

| 风险 | 影响 | 处置 |
|---|---|---|
| 参数写入正确但 DSSAT 输出仍不变 | 可能是参数未被当前品种/过程使用 | 检查 cultivar/ecotype、模型阶段和输出变量，改用已知响应参数；记录结构性不敏感 |
| DSSAT 从全局目录读取输入 | worker 结果交叉污染 | 强制 sandbox 快照和运行时路径证据，比较实际读取文件哈希 |
| 当前 frozen 科学含义不清 | 无法自动修复边界 | 只生成 proposal 和问题表，等待用户审批 |
| 权重修复改变历史 Phi 数值 | 历史版本不可直接横比 | 保留旧结果，使用新 weight policy ID 和新 run ID |
| 单季数据限制验证 | 无法证明跨季泛化 | P0 只做处理块 smoke；P3 再做完整处理块留出，等待新季数据 |
| dirty worktree 与 P0 文件重叠 | 可能覆盖用户改动 | 修改前逐文件检查 diff；发生重叠时暂停并报告 |
| 外部程序测试耗时或不稳定 | 延迟 P0 | 保留纯 Python 门禁，但不豁免必要 DSSAT/PEST++ 冒烟验收 |
