## 4. 需要在下一阶段先修正的合同问题

### 4.1 CANOPY 目标族被重新纳入 Phi

当前实际使用的 `configs/runs/e02_from_scratch_objective_contract_20260826.csv` 将 `CANOPY`、`CANOPY_INCREMENT`、`CANOPY_TERMINAL` 设为正权重；A–E 的 `*_group_weight_audit.csv` 也显示了这些组的正预算。该设置与项目先前已经确认的“删除 CANOPY 目标族、不再考虑 LAIX，仅保留按末次观测日定义的 CANOPY_TERMINAL”不一致。

因此，C/D/E 的 Phi 不能被解释为仅由鲜重、氮响应、过程状态共同驱动。正式率定前必须冻结一份无 CANOPY/LAIX Phi 的目标合同，并重新生成权重审计；否则臂间比较有混杂因素。

### 4.2 目标合同元数据陈旧

各 v46 JSON 的 `shared_parameter_scope` 仍写有“122 active parameters”，而实际 frozen bounds 的 active 数分别为 A/B=4、C=6、D=9、E=7。下一版需让 manifest/JSON 从 frozen bounds 自动生成 active 参数清单，避免审计误读。

### 4.3 A/B 的可识别性失败不能静默通过

在正式流程中应把 `ies_simulation_variation < 1` 直接标为 engineering failure，并禁止进入候选池；需要增加一个小型参数通道测试：每个激活参数取 lower/init/upper，至少验证一个受约束的正权重观测列发生可检测变化。
