# P2 P0-A～P0-D 代码审查（2026-07-18）

## 总体结论

评级：**Needs revision（工程证据可信，但尚未形成完整科研闭环）**。

D0/D1 配对诊断的核心结论可以接受：两次运行使用完全相同的 60 行初始参数 ensemble 和观测 ensemble；D0 删除 1 个成员，D1 保留 60/60；两者末轮 Phi 和参数分布接近，因此当前正式 staged calibration 默认关闭相对 2σ 筛除是合理选择。98/234 的 prior-data conflict 也与 REC 的 98 条名单一致。

但实施记录把 P0-A 写成“已完成”并不准确；P0-B、P0-C 还有入口和状态语义缺口；P0-D 只能认定为工程诊断完成，不能据此继续 S3/S4。

## 主要发现

### [P1] P0-A 没有生成逐成员状态审计

实施记录要求区分 `model_failed`、`high_phi_screened`、`retained` 和 `other_dropped`，但相关源码、测试和 D0 运行目录中都没有 `realization_status.csv`、attrition ledger 或等价机器可读产物。当前只能人工读取 REC 得知成员 4 被 2σ 规则删除。

影响：质量报告只能看到 295/300 个有限 Phi 和 59/60 的保留率，不能证明缺失来自统计筛除而不是真实模型失败。P0-A 应判为 **部分完成**。

### [P1] 工程质量报告仍会错误自称 `science_validated=true`

D1 的 `ies_quality/ies_run_quality.json` 写出：

```json
"science_validated": true,
"status": "pass"
```

而同一运行的 `run_status.json` 和 `calibration_finalize.json` 正确写为 `scientific_status=not_assessed`、`science_status=science_pending`。原因是通用 `QualityReport.science_validated` 把“所有工程检查通过”自动解释为“科研通过”。

影响：人工阅读和仍使用通用 quality report 的工具可能提前消费 D1。必须在下一次正式运行前统一语义。

### [P1] `science_validation_manifest.json` 目前只校验四个布尔值

`finalize_calibration.py` 不校验实际 evidence 文件、SHA-256、run_id、设计或 validation split；只要人工写入四个 `true` 即可把运行升级为 `science_validated`。

影响：当前 finalize 适合保持 `science_pending`，不具备自动科学批准能力。下一轮不应扩展复杂 manifest 框架；在确定性复跑和分组 Phi 的真实文件绑定完成前，直接禁止自动升级最安全、也最简单。

### [P1] staged build 仍可静默绕过观测噪声契约

当前调用为：

```python
observation_noise=bool(design_spec is not None and observation_policies)
```

因此用户提供 `--design-config/--stage`、但漏掉 `--observation-policy-csv` 时，构建不会失败，而会生成没有 frozen observation ensemble 的 staged PST。这与实施记录“分阶段构建会生成噪声 ensemble”不一致。

影响：稳定入口仍可能重现 no-noise 问题。应 fail fast，正式 staged build 必须提供 observation policy。

### [P1] S2/S3 同时把 PWAD 与 PWAI 放入 Phi，增加重复信息

当前配置让累计采收 `PWAD` 和增量采收 `PWAI` 同时进入 S2/S3/S4。两者来自同一采收序列，累计量由历次增量构成，不能视为独立证据。当前 P2 计划正文仍写有“累计采收仅诊断、增量采收进入 Phi”的更简洁规则。

影响：同一采收信息被重复计权，可能加剧 Phi 支配和边界补偿。为减少复杂度，下一设计应恢复 `PWAI` 进入 Phi、`PWAD` 只诊断。

### [P2] 噪声 ensemble 的哈希字段命名和绑定不完整

`observation_names_sha256` 实际计算的是整个 observation ensemble CSV 的哈希，不是观测名称哈希；run manifest 只记录文件名和 seed，没有记录 ensemble SHA-256。

影响：本次配对可由人工复算确认，但正式 provenance 不能仅靠字段名推断。应改成明确的 `observation_ensemble_sha256`，并写入 manifest。

### [P2] prior-only 预检被通用门禁标为工程失败

`NOPTMAX=-1` 预检按设计不会产生 IES 更新轮次，但通用质量门仍因 `ies_iteration_progress` 将其标为 `engineering_failed`。

影响：数据结果可用，但机器状态错误。应增加单一的 `engineering_preflight_completed` 状态或让 prior-only 入口使用独立的轻量检查，不再复用完整率定门禁。

### [P2] coverage 工具对 PDC 文件格式作了过强假设

工具假设 PEST++ PDC CSV 只包含冲突观测，并以 `distance > 0` 作为筛选。当前含噪声预检与 REC 一致，因此 98/234 数字有效；但历史 no-noise PDC 曾包含一条 REC 未判为冲突的正 distance 行。

影响：当前结论不变，但工具应优先使用 REC 名单，或在 PDC 提供 `obs_stat_*`/`sim_stat_*` 时按区间不重叠复算。

### [P2] 观测噪声中 11.14% 的 realization 值为负

本次 60×234 的 frozen observation ensemble 中有 1564 个负值。对于 LAI、生物量和采收量，负值不具有物理意义；在加性高斯误差假设下它不一定是程序错误，但说明部分 `sigma_eff` 相对早期小观测值很大。

影响：98/234 冲突下降不能自动解释为先验变得更科学。下一轮只增加负值比例和 sigma/observed 比值审计，不在本轮引入 log、截断分布或通用误差模型。
