# P2-MVP T2.1 修复记录（2026-07-18）

本轮只修复工具链契约和测试，不启动新的 DSSAT/IES 运行。所有开发配置仍属于
`approval_scope=tooling_development`，最终状态最多为 `science_pending`。

## 已完成

- 建立共享工程门，供 finalize、并行运行器和 `check_run_quality.py` 共用。
  正式 IES 要求成员/进程完整、参数和模拟有变化、Phi 有限且有变化、参数发生更新、
  迭代和成员状态表完整；prior-only 仅豁免迭代推进和参数更新。
- 质量报告缺失必需检查时按失败处理；缺失 Phi 明确报告 `ies_phi_finite` 失败。
- S3 固定 S1+S2 六个参数，S4 固定 S3 的 `XFRT/XFINT`，并要求 `--fixed-from` 来自紧邻上游阶段。
- `--fixed-from` 校验上游 manifest/finalize 的 run_id、design stage、design table、approval scope
  和代表参数文件 SHA-256；代表参数文件修改后会失败。
- finalize 在末轮参数集合上生成 `stage_representative_params.csv`，规则固定为数值列中位数，
  同时记录源文件和输出哈希。manifest 字段采用更新写入，避免重复 finalize 留下旧哈希。
- 成员退出原因改为证据驱动：只有 REC 明确记录才是 `high_phi_screened`，只有 manager/agent
  证据才是 `model_failed`，其余缺失成员统一为 `other_dropped`，并输出首末出现轮次和证据来源。
- `representative_outputs` 明确表示阶段代表解确定性复跑需要保存的输出，不作为零权重 IES 观测。

## 新增负向回归测试

- 退化正式 IES 不得通过工程门；prior-only 无迭代但有扰动时可以通过。
- 无 REC/agent 证据的退出成员不得被推断为筛除或模型失败。
- manifest 与 finalize 的 run_id 不一致失败；S3 不能继承 S1；代表参数文件篡改后哈希校验失败。
- 设计配置检查 S3/S4 的固定参数集合，防止上游参数静默丢失。

## 验收边界

本轮通过测试后，仅表示工具链工程契约可继续接受 T3 smoke。当前参数边界、Phi、
prior-data conflict 和拟合性能仍是开发配置诊断，不构成科研结论；T3 运行前仍需审核本记录。
