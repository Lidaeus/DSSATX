## 3. 定植设置：苗重与根深必须重新解释

### 3.1 PLWT：是单位面积的干物质量

本机 `DETAIL.CDE:140` 将 PLWT 定义为 planting material dry weight，kg/ha。CROPGRO 在移栽分支计算 `TOTWT=SDWTPL/10`，再除以株数得到单株初始干重；初始总重随后分到叶、茎和根。[官方 GROW 源码](https://github.com/DSSAT/dssat-csm-os/blob/d6556cca9f926c40eddffd9adcf77e970db7511b/Plant/CROPGRO/GROW.for#L393)

按当前密度 2.7 株/m²：

```text
PLWT (kg干物质/ha) = 单株总干重 (g/株) × 2.7 × 10
PLWT=9.5  →  0.95 g/m²  →  0.35185 g干重/株
9.5 g干重/株  →  PLWT=256.5 kg/ha
9.5 g鲜重/株  →  PLWT=256.5 × 实测干物质比例
```

因此不能直接认定“9.5 太大”或“9.5 合理”。若用户意图是沿用模型字段 9.5，则可保留，但必须把文档单位更正，并记录对应的单株干重。若意图是实测单株重，则必须确定鲜/干重及是否包含根系后转换。不得凭经验指定一个干物质比例。

工程上还存在一致性问题：`src/common/param_registry.py:199` 的 PLWT 硬边界是 1–20，建议边界是 4–12。若确认需要转换到 256.5，这组边界也要按单位与模型依据重审，不能绕过硬界、截成20或直接放大后继续率定。原文“PLWT/PLDP固定、无参数”也不准确：运行器支持注入这两个参数，只是具体设计不一定启用。

（明确是模型输入值，且值改为15）

### 3.2 PLDP、SPRL、RTDEPI 是三个不同概念

| 字段     | 实际含义                      | 对本项目的处理                                                 |
| ------ | ------------------------- | ------------------------------------------------------- |
| PLDP   | 种植深度，cm；传入 SDEPTH         | 按用户决定保留8cm，但不能称它将初始根深设为8cm                              |
| SPRL   | 块茎初始芽长                    | 不是茎半径，也不是茄子根长；统一8可作为既定输入整理，但不应把它当水氮优化参数                 |
| RTDEPI | 出苗/植株初始化时根系深度，cm；从 SPE 读取 | 当前模板为10.0；ROOTS 初始化执行 RTDEP=RTDEPI。若目标是根深8cm，需要另行明确修改此项 |
| PLPH   | 每穴株数；是否使用依种植分布与作物分支而定     | 按决定填1；PLDS=R时不应再用它重复乘密度                                 |

SPRL 定义来自 [DSSAT FileX 格式说明](https://dssat.net/wp-content/uploads/2011/10/DSSAT-vol4.pdf)；根深调用见 [ROOTS](https://github.com/DSSAT/dssat-csm-os/blob/d6556cca9f926c40eddffd9adcf77e970db7511b/Plant/CROPGRO/ROOTS.for#L499)。当前模板见 `data/templates/genotype/TMGRO048.SPE.base:78`。本轮没有将用户批准的“定植深度8cm”扩大解释为修改 RTDEPI 的授权。

## 4. 磷、钾、耕作：不能只改开关

### 4.1 磷：代码支持 TM，但当前材料不能直接代表茄子磷响应

官方源码的 CRGRO 磷兼容清单包含 TM，并且当前模板有 `*PHOSPHORUS` 节，因此“CROPGRO无法模拟磷”不成立。但模板标题明确写着 **optimized for peanut**，不是经过本项目茄子验证的磷参数。[IPSIM兼容检查](https://github.com/DSSAT/dssat-csm-os/blob/d6556cca9f926c40eddffd9adcf77e970db7511b/InputModule/IPSIM.for#L899)

已有输入并非完全没有磷观测：FileX 的 SOIL ANALYSIS 有 SAPX，例如25SP第一组0–20cm为76.2，26SP第一组为103；问题是 `SMPX=-99`，选定 SOL 剖面也没有相应的分层磷数据块。因此应查明有效输入最终采用哪个检测方法、哪些层的 SAPX，以及深层补齐方式。当前土壤 pH 约8，不能随便把缺失码写成任意提取法。源码针对碱性土提示核查 Olsen 法；这不是把所有已有值直接改标为 Olsen 的依据。[磷初始化](https://github.com/DSSAT/dssat-csm-os/blob/d6556cca9f926c40eddffd9adcf77e970db7511b/Soil/Inorganic_P/SoilPi_init.for)

正式启用前的交付物：

1. 各季各处理的磷分析日期、分析层、SAPX单位、真实提取方法码、pH方法；深层无测量时明确估算来源与不确定性。不要将不同季节相同的数值自动认定为独立实测。
2. 施肥量单位对账：DSSAT `FAMP/FAMK` 是元素 P/K 的 kg/ha。若原始记录是 P₂O₅/K₂O，则分别乘约0.4364/0.8301；若已经转换，不得再次转换。例如150 kg P₂O₅/ha约为65.46 kg P/ha。现有 FAMP=150 与原文“P₂O₅150”的关系必须追溯。
3. 对移栽茄子的 P 浓度阈值、分配、吸收参数做来源检查；没有器官P观测时，不要同时大范围率定这些参数。
4. 固定其他参数，逐季比较 P关闭、P开启实际输入、P开启且供磷充足诊断三组；检查 PlantP/SoilPi、磷胁迫、水氮平衡及警告。确认供P充足时没有不合理的大幅减产，供P不足时响应方向和质量平衡可解释。

用户“全部开启磷”的意图保留为目标配置。输入未通过验收前，旧P关闭配置只可作为有标签的比较基准，不能把仍关闭P的运行声称为已落实统一方案。

### 4.2 钾：继续关闭有明确依据

所核对的官方源码在 CRGRO 路径启用 POTAS 时进入“不支持该模型”的错误分支，CROPGRO 内部 KSTRES 被设为1。填Y不会自动增加茄子的吸钾、钾胁迫或钾毒害能力。[IPSIM](https://github.com/DSSAT/dssat-csm-os/blob/d6556cca9f926c40eddffd9adcf77e970db7511b/InputModule/IPSIM.for#L948)、[CROPGRO](https://github.com/DSSAT/dssat-csm-os/blob/d6556cca9f926c40eddffd9adcf77e970db7511b/Plant/CROPGRO/CROPGRO.for#L466)

建议正式配置保持 POTAS=N，并写明“钾按非限制性养分处理，未建立作物钾响应”。若要核实当前安装版本，可单独做最小兼容性试跑，不能直接在正式率定包里试开。钾模块开发属于新模型扩展任务，不宜混入此次 P0。

## 5. 土壤、初始化、天气与管理的剩余问题

### 5.1 保留派生剖面，但不要把它称为完整的实测砂壤土

用户选择的派生剖面可作为统一工程基准：SOL层底为10/30/60/90/120/150/180cm。但剖面头的质地实际为 `-99`，FileX 的 SLTX 和描述名称不能补足层内质地数据；各层 SLCL/SLSI、SSKS、SCEC 等仍有缺失。与 canonical 比较，不只是层数不同，还改变 SLOC、SRGF、SLDR、SLRO、SLPF 等，会影响水氮解释。

因此保留“180cm/7层派生基准”这一决定，同时补记每一列是实测、传递函数、既往拟合还是缺失。尤其不能用同一个 IBTM910017 标识掩盖实体差异。可在新包内使用有来源说明的新土壤ID，或至少记录选定剖面内容哈希及所有引用关系。

**分层验收须区分四套层：** SOL物理层、FileX初始水氮层、DSSAT运行层、观测采样层。当前25D/26D初值甚至含2cm、4cm层底，不能简单概括成“输入7层”。MESOL=2会修改分层，不能凭一份过时INP断定所有运行始终九层。

建议P0暂保留MESOL=2。若以后改MESOL=3，须重新设计剖面和映射；官方读土程序会对首层厚于5cm给出水分算法稳定性警告，不能直接把现有10cm首层原样切到3就认为更贴近观测。[IPSOIL\_Inp](https://github.com/DSSAT/dssat-csm-os/blob/d6556cca9f926c40eddffd9adcf77e970db7511b/InputModule/IPSOIL_Inp.for#L539)

验收同时核对 `LL < DUL < SAT`、有效初始含水量、深层外推和储量守恒。水储量用各层体积含水量×厚度换算；氮浓度转kg/ha必须带容重和厚度，不能只对浓度算普通平均。0–60cm氮缩放若跨层，应按层段处理，确保60cm以下不变。

### 5.2 ICDAT、SDATE、残体和0.34倍基准要一起核对

已批准26SP的 ICDAT=26073、取消初始残体、0–60cm矿质氮采用一次0.34倍基准、额外ICNS\_26SP=1，应落实。原文“26042比26073晚一个月”方向错误；26042比26071早29天，也不是27天。

更关键的是：三季目前 START=S、SDATE分别25068/26071/25220，均早于拟采用的IC日期25069/26073/25221。**改ICDAT不等于改变真正的模拟起始日。** 官方输入程序在START=S时以SDATE定义YRSIM。应输出“测量日期—模拟起点—基肥—灌溉—耕作—定植”时间轴，确定初值代表哪个时点，然后验收首日有效水氮和播前过程。若决定对齐SDATE与ICDAT，要先处理此前已施入的基肥/耕作；不能机械移起点而漏掉管理事件。

“无初始残体”建议用明确的零质量表达并检查运行结果：26SP ICRT、ICRES均为0；不是只把ICRES删除。原表把其它季节称作“无残茬”也不够精确，实际 ICRT=1。需区分这1 kg/ha根残体与26D的14.77及1000 kg/ha地表/混入残体。取消初始残体不代表取消SLOC或有机质矿化。

0.34倍的权威来源需要写成可执行的输入链：引用用户指定工作簿及工作表、原始值→重分层→一次缩放→下限处理→FileX。不要将已经0.34倍的数据再次缩放；对最终浓度及0–60cm总氮储量同时核对。本文未重新审查该工作簿单元格，因此不声称它与s0p34逐格一致。

### 5.3 追肥、收获和天气

- **追肥10cm：** 按用户决定设置，同时保留正确FACD。现有追肥是AP005（随灌溉水施入），基肥为AP002；FDEP=10不能代表二维滴灌湿润深度。必须核对当天灌溉、肥料形态、面积换算及有效入土氮；不应为了凑深度改成错误施肥方式。
- **25SP收获10次、最后一次虚拟：** 需明确为9个实测事件＋1个仅结束模拟/清理用途事件。25D目前11次，不能随意删最末一行。当前 `run_multiseason.py::_prepare_t10_input_bundle()` 已不重写FileX收获表，故生成器必须直接提供正确日历；D1/D2不会自动修好收获管理。实际读取器按FileT确切日期取FreshWt，而外层docstring仍说d±1，文档与审计字段要同步修正。验收每个实测事件对应的模型采收日、观测日和累计值，虚拟事件不计入实测数量与目标。
- **25FA跨年：** 气象和输出必须覆盖至26006及所需观测日，日期差用日历计算，不把252xx到260xx做整数差。NYERS=1本身不能据此认定跨年一季非法。
- **坐标和海拔：** 用户给定纬度35.16、经度113.8、海拔75m可作为新包元数据。WTH目前纬度35.19、海拔300；“温室所以不影响模拟”不能成立。WTH是气象计算来源，纬度参与天文量；不能只改FileX显示值就称已统一。
- **CO₂与气象方法：** M代表背景CO₂，若无棚内观测可以作为显式假设；若有CO₂施用，需真实输入链。现有WTH有RHUM但无WIND，REFHT/WNDHT=-99；不宜为“增强水响应”直接换到要求更多气象量的蒸散方案。先核实棚内辐射、温度、通风和有效降雨。MESEV=R/S、EVAPO=R/其他方法应在输入足够时逐项对比。
