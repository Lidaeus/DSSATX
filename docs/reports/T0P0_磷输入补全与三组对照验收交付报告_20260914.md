### 1.2 本次代码审查发现的 4 项关键机制缺陷与解决

在推进磷输入补全与 PHOSP=Y 试跑过程中，通过深入审查 DSSAT v4.8 Fortran 源代码（`SoilPi_init.for`、`IPSLIN.for`、`LMATCH.for`、`OPTEMPXY2K.for`）及本地 `DETAIL.CDE`，发现并解决了以下 4 项关键机制问题：

#### 【关键发现 1】SMPX 与 SMHB 的真实语义纠偏（SPINIT 阻断的真正根因）
- **原认知偏差**：前期文档误认为 `SMHB = SA012` 是未定义的未知磷方法码，且误认为 `SMPX = -99` 是一个缺失的“磷吸附参数（浮点数）”。
- **源码实证**：
  - 查阅 `C:\DSSAT48\DETAIL.CDE` 与 `IPSLIN.for` 第 295-296 行：
    ```fortran
    55 FORMAT (I3,I5,3(1X,A5))
    READ (CHARTEST,55) LN, SADAT, SMHB, SMPX, SMKE
    ```
    - `SMHB`：**pH in buffer method code**（`SA012` 代表 KCl 缓冲体系测定 pH）。
    - `SMPX`：**Phosphorus extraction method code**（磷浸提测定方法码，5位字符，`SA001` 代表 Olsen 法）。
    - `SMKE`：**Potassium extraction method code**。
  - 在 `SoilPi_init.for` 第 109 行：`PMethod = SOILPROP % SMPX`。当 FileX 中 `SMPX = -99` 时，DSSAT 将浸提方法读取为 `"-99"`，无法匹配任何浸提方法，导致 `PiLabile` 初始化失败，抛出错误并退出：
    ```fortran
    MSG(NMSG+1) = "Initialization of soil P not possible with data provided."
    MSG(NMSG+2) = "Program will stop."
    CALL ERROR('SPINIT', 1, ' ', 0)
    ```
  - **磷吸附参数的真相**：DSSAT 中根本**不存在**独立的外部输入磷吸附浮点参数！在 `SoilPi_init.for` 第 543-557 行，DSSAT 内部调用 Sharpley et al. (1984, 1989) 经典 pedotransfer 传递函数，依据土壤粘粒含量（`CLAY`）、碳酸钙（`CaCO3`）、有机碳（`SLOC`）和 pH 自动计算有效性指数 `P_AVAILINDEX`。
- **解决方案**：在 FileX `@A SADAT` 行中，将 `SMPX` 填入字符码 `SA001`（Olsen 法，完全对应碱性土壤与用户 D-P1/D-P2 批复），直接激活内部传递函数。

#### 【关键发现 2】FileX `@A` 与 `@F` 段的定宽字符对齐陷阱
- **格式机理**：
  - `@A SADAT` 行格式为 `(I3,I5,3(1X,A5))`，`SMPX` 必须精确占用第 16～20 列（以 1 空格与 SMHB 隔开）。
  - `@A SABL` 层次行格式为 `(I3,F5.0,8(1X,F5.0))`，`SAPX` 必须严格位于第 40～44 列，整行行长必须恒为 56 字符。
  - 若使用普通空白 token 分词替换，由于 `-99`（3字符）被换为浮点数（如 `103.0` 5字符）时吞占后方空格或推挤右侧列，将导致后续 `SAKE`/`SASC` 发生列错位，触发 DSSAT 读取器 `Line Error key: IPSLAN (Invalid format in file)`。
- **解决方案**：建立基于严格 Fortran 列宽的切片重构逻辑（如 `line[:15] + "SA001" + line[20:]`；`line[:39] + f"{sapx60:5.1f}" + line[44:]`），确保每一列的字符位置与总行长严格对齐。

#### 【关键发现 3】追肥 FDEP 深度遗漏与 FAMP 元素 P 换算
- **缺陷溯源**：
  - 原生成脚本在检查追肥深度时仅匹配了 `fmcd == "FE005"`，导致 26SP 中的随水滴施磷肥 `FE300` 和钾肥 `FE018` 的 `FDEP` 滞留在 5 cm，25FA 中滞留在 25 cm，违反决策 D10（“滴灌追肥统一深度为 10cm”）。
  - FileX `@F` 段中的原值单位为 $\text{P}_2\text{O}_5$（25SP 基施 150；26SP 基施 45 + 追施 9/13；25FA 基施 45 + 追施 18/36），未转换为 DSSAT 模型要求的**元素 P**（$\times 0.4364$）。
- **解决方案**：
  - 将所有日期晚于基肥日的滴灌追肥事件（包括 `FE005`、`FE300`、`FE018`）的 `FDEP` 统一规范为 10 cm。
  - 严格按元素 P 折算并对齐施肥事件总额，消除多次追肥的舍入漂移：
    - **25SP**：基施 150 $\text{P}_2\text{O}_5 \rightarrow \mathbf{65.5}\text{ kg P/ha}$。
    - **26SP**：基施 45（19.8）+ 9 次追施 9（9×3.9=35.1）+ 2 次追施 13（2×5.7=11.4）= $\mathbf{66.3}\text{ kg P/ha}$（理论值 152 × 0.4364 = 66.33）。
    - **25FA**：基施 45（19.6）+ 2 次追施 18（2×7.9=15.8）+ 2 次追施 36（2×15.7=31.4）= $\mathbf{66.8}\text{ kg P/ha}$（理论值 153 × 0.4364 = 66.77）。

#### 【关键发现 4】深层 SAPX 延拓的强制性（D-P3 回退机制触发）
- **源码实证**：
  - 查阅 `workspace/diagnostics/dssat-csm-os-v4.8.2-source/Soil/Inorganic_P/SoilPi_init.for` 第 176～193 行：
    ```fortran
    DO L = 1, NLAYR
      ...
      IF (PMeasured(L) < -1.E-5) THEN
        MSG(3) = "Cannot run phosphorus model without some soil P measurement."
        CALL WARNING(3,ERRKEY,MSG)
        CALL ERROR(ERRKEY,1,' ',0)
        RETURN
      ENDIF
    ```
  - 当模型土壤为 7 层（至 180 cm）时，`SoilPi_init.for` 无条件遍历所有 7 层。如果 FileX 仅提供至 60 cm（或 100 cm 为 -99），`LMATCH.for` 将深层标记为 -99，DSSAT 在遍历到底部层时必然触发 `CALL ERROR('SPINIT', 1, ...)` 中断程序。
- **结论**：D-P3 批复的 C 选项（“先只带 60cm 数据跑，若仍拒则回退 A”）在 DSSAT 代码机制上必然被拒。因此系统自动并必须执行回退 A 选项：以 60 cm 实测有效磷延拓至 80、100、120、150、180 cm。
