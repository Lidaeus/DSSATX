# P2 P0-A～P0-D 实施记录（2026-07-18）

## 1. 执行结论

本轮完成了高 Phi 筛除策略的可审计化、观测噪声契约、先验覆盖预检，以及同一初始集合下的 D0/D1 配对诊断。正式分阶段率定默认采用 D1：关闭分布自适应的相对 2σ 筛除，仅保留真实运行失败或预先定义的无效模拟；D0 仅作为诊断对照，不得作为正式后验分布的唯一依据。

本轮没有读取或使用 validation 处理，运行结果不构成 `science_validated` 结论。

## 2. P0-A：成员状态与审计

`build_pest.py` 现在在 run manifest 中记录：

- `bad_phi_sigma` 与 `relative_phi_screening`；
- 观测噪声契约、ensemble 文件、seed 和元数据文件；
- 率定设计、处理角色和观测用途。

成员流失必须区分真实模拟失败、统计筛除、保留成员和其他丢失。D0 的 PEST++ 输出中出现 1 个被 2σ 规则筛除的成员：初始 60 个，末轮保留 59 个（0.9833）；其后 Phi 表存在该成员的空单元，因此质量报告的 `ies_phi_finite` 为 fail，但这不是 DSSAT 运行失败。

## 3. P0-B：冻结观测噪声

分阶段构建会从经过审计的 `raw_sigma` 生成独立正态观测噪声 ensemble，并通过 `ies_observation_ensemble` 注入 PEST++。噪声文件和 seed（`random_seed + 1000003`）已写入 manifest/JSON，D0 与 D1 使用完全相同的噪声文件。SHA-256 已由复核脚本确认一致，但当前字段命名及 manifest 绑定仍需按后续代码审查修正。

这样 prior-data conflict 的判断不再等价于“无噪声的确定性模拟是否覆盖观测”，也不会在每个成员或每次迭代中隐式改变误差尺度。

## 4. P0-C：先验覆盖预检

先运行 `NOPTMAX=-1` 的 prior-only 预检，未设置 `ies_drop_conflicts`，并用 `tools/analyze_prior_coverage.py` 将观测冲突与成员流失分开统计。

运行：

`workspace/runs/p2_n4_s2_priorcoverage2_20260718`

结果：234 个非零权重观测中 98 个存在 prior-data conflict（0.4188）。冲突集中在 LAIX、后期 LWAD、PWADM 的多个收获时点以及部分 CNAM；早期 LAID/LWAD 观测多数未冲突。该结果说明噪声契约已降低原先的“几乎全部冲突”，但当前先验边界/模型结构仍不足以覆盖全部观测，不能通过扩大 2σ 或自动删观测来掩盖。

## 6. 正式运行政策（P0-E）

1. 分阶段正式后验默认 `relative_phi_screening=false`；
2. 仅排除真实运行失败或事先登记的无效模拟；
3. 若研究者显式启用统计筛除，必须同时报告各迭代成员流失、被筛除原因、筛除前后组 Phi，并提供同一初始集合的 no-cull 敏感性对照；
4. D0 结果可用于工程诊断，不能单独用于后验分布、参数相关性或论文结论；
5. 在解决先验覆盖、边界堆积和观测误差定义前，不启动 S3/S4，也不查看 validation。
