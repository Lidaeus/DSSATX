# P1 运行失败原因排查复盘

> 状态：长期维护的故障复盘
> 首次整理：2026-07-16
> 关联运行：`p1_morris_formal_v2_20260715/seed_20260715`

## 1. 为什么启动排查

旧 seed 的 manager 被中断，不能把“进程未完成”与“DSSAT 模型失败”混为一谈。P1-R1 对1740个计划点重新分类：

| 类别 | 数量 | 含义 |
|---|---:|---|
| 成功 | 1434 | DSSAT 和外层模型命令均成功 |
| 真实模型失败 | 46 | DSSAT/模型命令失败，不是中断造成 |
| 运行时失败 | 7 | manager/agent 中断或外层运行故障 |
| 未完成 | 253 | 尚未得到最终状态 |

46个真实失败集中在7条 Morris 轨迹。DSSAT 返回 exit 73，错误位置为 `__libm_logf_e7` 的 floating divide by zero。失败会破坏相邻 elementary effects，因此该 seed 只能用于诊断，不能生成正式排名。

## 2. 排查原则

1. 先区分模型失败、中断、未完成和未知失败；不要按非零退出码一概统计。
2. 从 `.sen.par.csv` 精确恢复候选，不手工重抄参数。
3. 同一候选先完整重放，再按 TN 拆分，定位处理依赖。
4. 反事实只写入诊断目录，不修改权威 FileX。
5. 每次只替换一个因子或一组有明确含义的分量。
6. 失败边界上的“最后变化参数”不自动等于根因。
7. 只有新随机轨迹通过，才能说明候选边界具有外推证据。

## 3. 证据链时间线

### 3.1 首次审计

- 30条理论轨迹中25条完成进程，18条完全有效；
- 46个模型失败分布于轨迹11、12、15、18、20、22、23；
- 失败通常发生于 DAP 116–127；
- 不同遗传/生理参数都可能使联合状态进入或离开失效区，提示高阶交互。

### 3.2 确定性重放

代表候选：`689, 740, 927, 1049, 1165, 1313, 1334`。

- 完整批次：7/7失败；
- 原输入按10个处理拆分：70次中仅TN2的7次失败；
- 12个相邻成功点在TN2继续成功，证明不是环境或运行器随机波动。

### 3.3 IC/MF 反事实

7候选×9变体共63次：

- 只换 IC2→IC3：0/7成功；
- 只换 MF1→MF2：7/7成功；
- 换初始水分、铵态氮、硝态氮或完整 IC 分量均不能稳定消除失败。

结论：IC不是主因，MF相关状态具有决定性影响。

### 3.4 FileX 顺序缺陷

进一步发现 MF2 最后一次施肥行位于施肥段开头，其余 MF2 行位于段末，同一因子水平不连续且日期逆序。

- 原始错序 MF2：7/7成功；
- 只整理 MF2 行、事件值不变：3/7成功；
- MF1 复制 MF2 氮量：同为3/7成功。

完整 DSSAT 输出的季末植株氮也不同，说明原 MF2 并未按逻辑上完整的施肥序列执行。旧输入包因此停用，新包 `xxql2501_20260716` 只重排行，不修改事件多重集。

### 3.5 修正输入后的处理范围

在正确的 MF2 顺序下，7候选×10处理共70次出现12次失败：

- TN2：7；
- TN3：2；
- TN14：3；
- 其他：0。

所以不能再把问题称为“TN2独有”，更准确的描述是有效氮供应、水分/初始状态和参数组合的交互失效。

### 3.6 边界候选

旧 seed 内的参数域诊断提出：

- `XMAGE lower: 5 → 10`；
- `SLAREF lower: 225 → 260`。

两者保留初值13.5和300。代表候选经候选下限处理后，在修正输入和全部10个处理上70/70成功。该结果只支持建立 pending proposal，不能证明57维域全局无失败。

## 4. 已排除或不能推出的结论

- 深层缺失 `SSKS/SLCL/SLSI` 不是本次失败的直接解释；它们不进入 SA，只作为 warning 和论文限制。
- IC2不是主要失败原因。
- 总氮量或最后一次追肥不能单独解释全部失败。
- 轨迹入口参数 `TRIFL/TM3/XMAGE/FL-LF/SLAREF/ATOP` 不是可直接逐一缩界的“根因清单”。
- 70/70代表重放不等于正式 Morris 已通过。
- 不应修改真实施肥数据来迁就模型稳定性。

## 6. 日后遇到失败时的最小流程

1. 保存 `run_status.json`、`.rmr`、`.sen.par.csv`、agent stderr 和失败工件；
2. 运行 Morris audit，先分类再统计；
3. 选择每条失败轨迹的首个失败点与相邻成功点；
4. 按处理重放，确认是否可重复；
5. 只做最小反事实，不修改正式输入；
6. 把候选修复写入 proposal，保留旧版本；
7. 用未参与推导的新 seed 做小规模可行性预检；
8. 预检完整通过后才允许正式 seed；
9. 在论文或报告中披露原始失败率、失败处理政策和参数域变化。
