# P2-MVP T4.4：正式论文包证据链收口

日期：2026-07-19  
范围：正式 R 论文图的输入 provenance 门禁；未运行 DSSAT、IES 或 SA，未改变参数边界、权重、sigma、split 或科研状态。

## 解决的问题

此前 `export_paper_data` 虽验证 run/finalize/quality，但最终 `paper_data_manifest.json` 未包含正式率定所依赖的冻结实验输入、参数边界、观测权重和 validation split 哈希。因此同一 `run_id` 的包无法独立说明其科研配置来源，R 也未对正式率定图的场景类型做硬性判断。

## 实施

- 正式（非 DEMO）导出现在从 `run_manifest.yaml` 强制读取并验证四个 64 位 SHA-256：`input_manifest_sha256`、`bounds_sha256`、`observation_policy_sha256`、`validation_split_sha256`。任一缺失或格式错误即阻止导出。
- 这些值写入 `paper_data_manifest.json` 的 `upstream_validation.frozen_run_inputs`，与 run manifest/quality/finalize 原有 provenance 一同冻结。
- R 在渲染常规率定图前，正式包必须声明 `scenario_type=actual_trial_calibration`，且必须包含上述四类冻结 provenance；DEMO 包仍需显式 `--allow-unvalidated-demo`，不受该正式授权路径影响。
- 新增缺失 bounds 哈希的负向测试，防止日后退化为只看 `run_id` 的弱校验。

## 下一步

本轮只消除了论文数据包进入 R 前的来源歧义。正式科研运行仍需由用户另行冻结参数边界、参与率定的参数范围及审批 ID；在此之前不允许把当前 tooling demo 升级为 `science_validated` 或解读为论文结论。
