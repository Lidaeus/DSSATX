# P1-R1 科研运行可靠性与失效诊断

## 目标

P1-R1 防止“进程结束”被误认为“科研结果可用”。正式 Morris 结果必须同时满足运行完整、模型稳定、轨迹完整、elementary effect 数量平衡和最终汇总存在。中断或失败案例可以用于诊断，但不得进入 Top-K 参数筛选、Sobol 或后续率定。

## 运行状态

`run_status.json` 使用两个相互独立的维度：

- `status`：`prepared / launching / running / stopping / completed / aborted / runtime_failed`；
- `scientific_status`：`pending / validated / failed / not_assessable / not_assessed`。

管理器返回 0 只代表 `completed`。Morris 审计不通过时，进程仍可为 `completed`，但 `scientific_status=failed`。

推荐入口：

```bash
# 后台运行；独立 controller 会等待 manager 并更新最终状态
python tools/parallel/run_parallel.py \
  --run-dir <run_dir> --case sa_sen_morris --mode sen \
  --n-agents 6 --no-wait

# 查询
python tools/parallel/run_parallel.py \
  --run-dir <run_dir> --case sa_sen_morris --status

# 有记录地停止；PEST++ 将剩余任务标为失败，因此结果只能用于诊断
python tools/parallel/run_parallel.py \
  --run-dir <run_dir> --case sa_sen_morris --stop

# 仅在 manager/agent 无响应时强制停止
python tools/parallel/run_parallel.py \
  --run-dir <run_dir> --case sa_sen_morris --force-stop

# 从 case.rns 恢复计算
python tools/parallel/run_parallel.py \
  --run-dir <run_dir> --case sa_sen_morris --mode sen \
  --n-agents 6 --resume --no-wait
```

PEST++ 5.2.16 的真实集成测试表明 `/r` 可以恢复并完成计算，但中断瞬间处于运行状态的候选不一定被重新排队。因此恢复后的 `.mio` 仍必须通过轨迹审计；若缺少任一 elementary effect，正式 Morris 应从干净案例重新运行。

## Morris 正式门禁

`src/sensitivity/morris_audit.py` 读取 `.sen.par.csv`、`.rmr`、agent stderr、`run_status.json` 和 `.mio`，并生成：

- `morris_run_audit.json/.md`；
- `morris_failures.csv`；
- `morris_trajectory_status.csv`；
- `morris_effect_coverage.csv`；
- `morris_run_quality.json/.md`。

正式通过条件：

1. manager 状态为 `completed`；
2. 没有未完成、运行时失败或未知失败；
3. 没有真实模型失败；
4. 每条轨迹全部成功；
5. 每个参数具有请求的完整 `r` 个 elementary effects；
6. 每一步只改变一个参数；
7. `.mio` 存在，且原有非有限值、常数和全零门禁继续通过。

`sa_postprocess_morris.py` 在读取 `.mio` 和绘图前强制执行上述门禁。部分结果统一标记为诊断证据，不生成正式排名。

## 失败重放

```bash
python -m src.sensitivity.replay_morris_failure \
  --case-dir <case_dir> --run-id <id> \
  --out-dir <diagnostic_dir> --split-treatments --execute
```

重放器从 `.sen.par.csv` 精确恢复候选参数，可运行完整批次或按 TN 过滤批次。失败时保留 DSSAT 输入、输出、参数快照和 `failure_context.json`，不再依赖易被下一任务覆盖的 agent 临时目录。

## 正式运行策略

1. 先解释并解决已识别的 TN2 数值失效；在证据形成前不创建 v3 边界。
2. 新边界如确有必要，必须以独立提案提交审核，不自动裁剪或交换参数值。
3. 稳定性试验采用 3 个 seed × `r=4`，要求零真实模型失败。
4. 正式 Morris 先运行两个独立 seed × `r=30`。
5. 项目建议稳定性门槛为总体 Spearman ≥ 0.90、Top-15 Jaccard ≥ 0.80；仅在未达到时增加第 3–5 个 seed。

## 测试

- 单元测试覆盖 Windows 退出码、优雅停止、模型失败/中断分离、轨迹和相邻 effect 计算、候选与单处理批次重建。
- 故障注入验证中断不会被计作 DSSAT 模型失败。
- 可选集成测试 `RUN_PESTPP_INTEGRATION=1` 使用捆绑的 PEST++ 5.2.16 验证后台 controller、中断、`.rns` 恢复和恢复后科研门禁。
