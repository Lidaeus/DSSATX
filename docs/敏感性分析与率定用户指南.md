# 敏感性分析与率定用户指南

> 状态：当前用户指南
> 更新：2026-07-19

## 1. 先理解三个状态

| 状态 | 含义 | 可否用于论文结论 |
|---|---|---|
| `engineering_validated` | 程序完成、产物完整、参数/模拟/Phi 有变化 | 否 |
| `science_pending` | 尚未完成或尚未批准科学审核 | 否 |
| `science_validated` | finalize 明确授权，且正式输入、设计、验证证据齐全 | 是 |

退出码 0 和质量报告 pass 都不等于科研有效。率定只有 `calibration_finalize/calibration_finalize.json` 可以授权正式下游。

## 2. 准备实验文件

FileX、FileA、FileT、SOIL、天气和 batch 必须组成一个版本化输入包。文件位置和导入命令见 [目录与输入资产规范](目录与输入资产规范.md)。输入包一旦生成 `input_manifest.json` 就不再覆盖；修订数据应创建新 bundle。

FileA/FileT 建议继续保存处理均值。各重复的原始数据另存长表，用于计算 `replicate_sd`、`n_effective` 和 `sigma_eff`，不要把共享同一模拟值的重复当作独立 PEST 观测。

## 3. 管理参数范围

参数范围分四层：

1. `src/common/param_registry.py`：物理硬边界；
2. `data/parameter_registry/baseline/`：基线建议；
3. `bounds_proposals/`：待审核建议；
4. `bounds_frozen/<crop>/`：获批版本，也是率定唯一可读取的层。

冻结示例：

```powershell
python tools/freeze_bounds.py `
  --proposal data/parameter_registry/bounds_proposals/<proposal>.csv `
  --crop eggplant --bounds-id <new_bounds_id> `
  --notes "用户审核后的新一轮范围"
```

不要覆盖已有 bounds ID，也不要让程序自动选择“最新”SA 结果。

### 3.1 多季遗传参数分析的当前候选策略

两季春季和一季秋季应分别建立输入 bundle，使用相同遗传参数域、Morris 设计和 seed，先逐季质控再汇总。主遗传 SA 固定实测 SOIL 与 FileX 初始条件；如需评估测量偏差，应在遗传参数收口后另做窄范围 nuisance 分析。

当前候选温度范围为 `TB*=8–12`、`TO1*=20–27.5`、`TO2*=28–33`、`TM*=34–45 °C`；`FL-VS` 只以 100–140 作为结构敏感性探针，缺少末叶/终止生长观测时不进入率定；`XMAGE=8–30` 与 `XFPHT=35–70` 在参数域层面保证顺序。完整依据见 [正式多季参数域设计报告](reports/正式多季遗传参数敏感性分析参数域设计_20260719.md)。

## 4. 敏感性分析

Morris 回答“哪些参数在当前输入、范围和响应定义下稳定影响模型输出”。它不是参数可辨识性或因果结论。

每个 seed 使用独立目录；正式运行必须保留参数范围、输入包、输出 profile 和 Git 哈希。运行后至少检查：

- 模型完成率和有效轨迹数；
- 是否出现全零或结构性零方差响应；
- 每个预声明排名域的跨 seed Spearman 和 Top-K Jaccard；
- 单个处理或输出是否异常支配排名。

只有稳定 Morris 结果可以进入 Top-K 人工审核。Sobol 应在获批 Top-K 上运行，并用至少两个通过质量门的正式尺度判断收敛；单个样本尺度只能称为单尺度估计。

标准命令见根 [README](../README.md)。具体参数以各 CLI `--help` 为准。

## 5. 分阶段 IES 率定

推荐阶段：

- S1：物候与冠层时序；
- S2：氮响应与营养生长；
- S3：结实与增量采收；
- S4：仅重新释放前阶段中确有更新、边界行为可解释的少量参数。

每阶段必须：

- 只读取获批 frozen bounds、输入 bundle、design 和 observation policy；
- 在新 `workspace/runs/<run_id>/` 中构建；
- S2–S4 用 `--fixed-from` 绑定紧邻上游代表参数；
- 保留 `run_manifest.yaml`、质量报告、成员状态、参数 ensemble、Phi 和确定性复跑；
- 先完成工程检查，再由 finalize 决定科研状态。

不建议同时释放大量遗传参数。土壤和初始条件默认固定，除非有独立观测和单独批准。

对实测土壤和初始水分，不要把文献中的宽泛 ±20%–30% 直接当成本场试验先验。优先使用重复测量 SD/SE 或检测方法误差；没有误差记录时，较窄百分比只能用于单独稳健性预检，不能与遗传参数同时率定并据此解释遗传系数。

## 6. 观测误差与权重

目标函数采用：

```text
Phi = Σ (w_i × residual_i)²
w_i = 1 / sigma_eff_i
```

`sigma_eff` 应记录重复测量、模型尺度误差和下限的来源。组倍率默认 1.0；任何调整都必须预声明并有倍率 1.0 对照。当前 pwtadj1 关闭。

默认使用原始物理尺度。log 变换只有在 observation policy 完整声明并保证观测与模拟使用相同定义时才允许。动态 Min–Max 禁止进入目标函数。

完整定义见 [观测误差与权重规范](权重设计方案改进提案.md)。

## 7. 验证与条件参数集合

validation 按完整处理留出，不能把同一处理的日期行随机拆到 calibration 和 validation。diagnostic 不进入 Phi。

正式 finalize 通过后才运行：

- 处理级 RMSE、MAE、bias 等验证指标；
- prior 与 IES conditional ensemble 的收缩和边界诊断；
- Spearman 参数相关；
- 最多 2–3 对“Phi 相近、参数距离较远”的候选解；
- 候选解在 validation/diagnostic 上的确定性预测距离。

只有参数距离和预测距离都满足预声明条件时，才能讨论功能异参同效。

## 8. 图表与成果包

Python 的 `diagnostic_*` 只用于运行诊断。论文图由 R 渲染，必须读取 hash-gated `paper_data_manifest.json`。

正式图需要 `science_validated`、`scenario_type=actual_trial_calibration`，并携带输入、bounds、observation policy 和 validation split 哈希。未验证数据只能通过 `--allow-unvalidated-demo` 生成带水印的布局预览。

图表规范见 [科研图表设计与开发计划](科研图表设计与开发计划.md)。

## 9. 常见错误

- 把退出码 0 当作科研通过；
- 在 `workspace/` 根目录手工放输入并依赖默认查找；
- 覆盖旧输入包或 frozen bounds；
- 将 `1/sigma²` 写入 PEST weight；
- 把累计采收的每个日期当作独立观测重复计权；
- 根据 validation 结果反复挑参数；
- 把 IES ensemble 称为严格贝叶斯后验；
- 用 DEMO 图或历史失败运行支持论文结论。
