## 1. 本轮结论和边界

P1 v4 的稳定 Morris 已足以支持 P2 候选参数讨论。N=128 Sobol 作为单尺度辅助证据保留，但不宣称跨尺度收敛。现有 30-realization IES 和异参同效结果均为工程预检，不进入正式论文结论。

本轮只做四件事：

1. 修复会错误升级科研状态或混淆运行来源的门禁；
2. 冻结小而可解释的分阶段率定设计；
3. 完成一个通过质量门的正式 IES 和完整处理级验证；
4. 从同一冻结运行生成必要的 Fig. 1–5 数据和图。

明确不做：代理模型、t-SNE、自动聚类平台、贝叶斯术语升级、pwtadj1、土壤/IC 联合率定、管理优化/响应面 Fig. 6、通用工作流框架。

## 2. 开工前科学决策 proposal

以下是建议方案，须由用户审批后创建新的 approval/frozen ID。

### 2.1 数据角色划分

建议按完整处理划分，不随机拆时序行：

| 角色 | 处理 | 用途 |
|---|---|---|
| calibration | TN2、TN3、TN4、TN10、TN11、TN12 | 两个水水平 × 三个非零氮水平，用于识别生长、氮响应和采收参数 |
| validation | TN5、TN13 | 两个水水平下的零氮处理，检验对强氮胁迫的外推能力 |
| diagnostic | TN9、TN14 | 不属于完整 2×4 配对，只做中间灌溉/CK 情景诊断，不进入 Phi |

理由：该划分保持完整处理独立，避免同一处理的时间泄漏；同时把最具挑战的 N0 情景留作验证。局限是仍为同一季节内部验证，论文必须明确不能替代跨季/跨点外部验证。

### 2.2 分阶段候选参数

不接受“20 个 Sobol 参数直接变成 14 个同时率定参数”。建议按观测支撑缩减：

| 阶段 | 建议 active | 主要观测 | 暂不释放及原因 |
|---|---|---|---|
| S1 物候/冠层时序 | `EM-FL, TRIFL` | 开花/物候、LAI 时序 | `TB2, TM2, TO12, TO22`：单季温度范围不足以稳定识别多个温度阈值 |
| S2 氮响应/营养生长 | `NSTFAC, RTNO3, NMOBMX, NVSMOB` | 植株氮、生物量、LAI及其处理差异 | `RTNH4`：缺少独立铵吸收约束；`RWDTH`：缺少根系/株宽直接观测 |
| S3 结实与采收 | `XFRT, XFINT` | 增量采收和季末产量 | 累计采收只诊断，不重复进入 Phi |
| S4 小规模联合 | 仅保留 S1–S3 中在 calibration 集上确实更新、无异常边界、相关结构可解释且确定性复跑一致的参数，建议不超过 6 个 | 全部 calibration 组 | 不查看 validation 结果筛参数，不因 SA 排名自动加入新参数 |

每阶段以上一阶段的代表值为固定基线，但保存每阶段独立 bounds snapshot 和上游 run_id。若某参数无稳定更新或只改善 calibration、不改善 validation，则回到固定状态，不扩展参数数量补偿。

### 2.3 观测误差和权重

- FileA/FileT 继续保存处理均值，不把重复记录复制成多个与同一 DSSAT 模拟配对的伪独立观测。
- 若已有原始重复，另存长表并计算 `sigma_eff = sqrt(SD^2/n_eff + sigma_model^2 + sigma_floor^2)`。
- 若当前只有均值，冻结 `assumption_based_sigma_v1`，逐变量记录经验 sigma、来源、模型误差和下限；不得称为测量 SD 或从均值反推 SD。
- PEST weight 固定为 `1/sigma_eff`；物候、冠层、生物量、增量采收组倍率默认均为 1.0。主 policy 中 `PWAIM=1.0`，另建独立 contrast policy 仅把 `PWAIM` 设为1.25；两者分别哈希冻结，不根据拟合结果反复调权。
- log 仅在已有 observation policy 明确启用时双侧同尺度执行；本轮不新增 log 变量。pwtadj1 关闭。

### P2-D1：冻结率定设计

新增并由用户审批：

- `validation_split_id`：处理角色和 SHA-256；
- `observation_policy_id` / `weight_profile_id`：变量、sigma 来源、变换、相关性和组倍率；

验收：一份可手工审阅的设计表即可，不开发通用配置框架。

### P2-E1：执行分阶段率定与统一质量门

每阶段必须输出：

- 每轮 Phi 的 realization 分布和有效/剔除成员；
- `group_phi.csv`：物候、冠层、生物量、增量采收的原始 Phi、占比和观测数；
- 参数 prior/final 分布、更新幅度、边界邻近比例；
- calibration/validation 分角色的 RMSE、MAE、bias、NRMSE；
- 最佳 Phi、集合中位参数各一次独立确定性复跑，并核对输出/Phi；
- run manifest、quality report、results manifest 和 SHA-256。

最低质量门：

1. 进程正常结束，模拟和参数有限；
2. 最终保留 realization ≥90%，剔除原因完整；
3. Phi 有实质变化，参数确实更新；
4. 无观测组因错误权重或数量造成无法解释的支配；
5. 关键参数无未经解释的边界堆积；
6. 确定性复跑能复现对应 realization；
7. validation 指标不出现相对于未率定基线的系统性恶化。

分组 Phi 不设置脱离数据的机械占比阈值；先同时审核观测数、sigma、时间相关性和残差结构。出现单组支配时失败并解释，不启用 pwtadj1 自动遮蔽问题。

### P2-V1：处理级验证与稳健性检查

只做两个必要对照：

1. 未率定基线 vs 正式代表参数，在 calibration/validation/diagnostic 三种角色上比较；
2. 主 sigma profile vs 预声明的增量采收 1.25 profile，判断关键参数方向和验证结论是否稳健。

不做随机 K-fold，不把 TN9/TN14 重新调入训练，不基于验证结果反复选择参数。若 N0 验证失败，应报告模型/参数可迁移限制，而不是把验证处理加回率定后继续称为独立验证。

## 7. 2026-07-18 下一轮实用主义执行计划

本节取代“配置文件已落盘即可开跑”的理解。详细 review 见 [P2-R0 / P2-D1 代码审查报告](reports/P2_D1_代码审查报告.md)。

### N1：让批准的设计真正控制 Pst 构建

只新增一个必要入口：

```powershell
python src/calibration/build_pest.py --design-config <design.json> --stage S1 --out-dir <run_dir>
```

该入口只做四件事：

1. 按 stage 只激活声明参数，其余固定；
2. 只让 calibration treatments 以非零权重进入 Phi，validation/diagnostic 仅保留输出；
3. 按 stage 的 observation-use 选择目标，累计采收固定为 diagnostic、增量采收进入 Phi；
4. 加载明确的 primary/contrast observation policy，并把所有配置哈希写入 run manifest。

构建后输出一张 `calibration_design_audit.csv`：逐处理、逐变量、逐角色列出观测数、非零权重数、sigma、倍率和最终权重。增加负向测试，证明 TN5/TN13、TN9/TN14、PWADM 或非本阶段参数不能静默进入 Phi。

不要开发通用配置框架；只实现当前 JSON schema 和清楚的失败提示。

### N2：把 IES 状态分成工程通过与科研通过

- `run_parallel` 完成后只写 `engineering_validated/failed_quality`；
- 新增一个集中且简单的 `finalize_calibration.py`，负责 group Phi、每轮成员、边界、确定性复跑、角色指标和 results manifest；
- 只有 finalize 全部通过才写 `science_validated`；
- posterior/equifinality/paper export 只接受 finalize 的结果，而不是直接信任 runner 状态。

这比继续给 `run_parallel.py` 堆科研逻辑更简单，也更容易审计。

### N3：整理现有 SA 为可直接引用的证据包

不增加新 SA 计算。新增一个小型 Python 导出入口，把已经通过的 v4 Morris 和 N=128 Sobol 冻结成：

- 双域 Morris 共识排名、跨 seed 稳定性和逐响应 `mu* / sigma`；
- N=128 `S1/ST/CI`，显式标记 `single_scale_not_converged`；
- SA quality/provenance manifest。

随后由R实现 Fig.1、Fig.S1、Fig.S2。Fig.S2只展示单尺度CI和“未完成跨尺度收敛”的事实，不伪造收敛面板。

### N4：依次运行 S1、S2、S3，不接触 validation

每阶段先做小规模工程运行，再按批准规模运行。阶段参数保留只依据 calibration 更新、边界、相关性、过程合理性和确定性复跑。TN5/TN13 在整个阶段选择期间不可查看指标。

S1–S3完成后暂停，提交 survivor proposal。用户批准新的 S4 ID 后再联合率定。

### N5：S4、一次性验证和条件参数集合

S4通过完整 finalize 后，首次计算 TN5/TN13 validation 指标。验证失败就报告局限，不回填训练。

只有这时才运行后验/异参同效：先验—条件集合、收缩、边界、相关、候选远距离解对；选择2–3对做 validation/diagnostic 确定性复跑，以预测距离区分“率定补偿”和“功能等效”。不做自动聚类。

### N6：冻结论文数据并完成必要图表

`finalize_calibration.py` 生成唯一 results manifest。正式 paper export 必须强制读取它并逐文件验哈希、继承 scenario/role/config身份；R端按图族校验 scenario type。

优先完成 Fig.2（Phi/group Phi/成员）、Fig.3–4（率定/验证性能与动态）、Fig.5（条件集合/异参同效）。不开发 Fig.6 管理优化，直到当前单季模型先通过验证。
