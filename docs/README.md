2. [产品定义与系统设计](../项目重构规划.md)：产品范围、科学工作流、质量门和路线图；最高层设计依据。
3. [P0 科研可信性修复开发计划](P0_科研可信性修复开发计划.md)：已实施范围、任务和验收标准。
4. [开发者指南](DEVELOPER_GUIDE.md)：实现约束、开发流程和测试要求。
5. [观测误差与权重设计规范](权重设计方案改进提案.md)：目标函数、误差标准差、变换和相关观测的专题规范。

发生冲突时，以更高层文档为准；实现细节若与产品设计冲突，应先修订文档并由用户审批。

## 5. 文档维护规则

- 每个规范文档必须标记状态、更新时间和实施状态。
- 新设计先修改 [产品定义与系统设计](../项目重构规划.md)，再同步专题规范和开发计划。
- 运行报告必须关联 `run_id`、`run_manifest` 和 `quality_report`；没有质量报告的结果默认未验证。
- 失效文档优先加 `ARCHIVED_` 前缀或显著停用说明，不在多个位置维护互相冲突的规范。
- 文档中的示例命令只有在端到端测试覆盖后才标记为标准命令。
