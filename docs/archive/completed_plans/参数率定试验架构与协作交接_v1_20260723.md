# 参数率定试验架构与协作交接（v1）

> 归档状态：P0-A 至 P0-E 及 E00–E02 主体工作已实施；本文件仅用于追溯 2026-07-23 的工程拆包。

**状态：** 待实施；本文件是 `参数率定试验矩阵与论文逻辑_v1_20260723.md` 的工程交接件。  
**原则：** 复用已经验证的多季节率定积木；只增加试验声明、统一评价和必要的输入审计。不得为了“通用性”重写 PEST++、DSSAT 运行器或论文出图系统。

## 1. 本轮架构决策

现有的 `multiseason_design.py`、`build_pest_multiseason.py`、`run_multiseason.py`、`seasonal_parameters.py`、冻结边界、后验/异参同效导出和 R 图表管线已经覆盖了后续试验的大部分能力。新工作只补三个缺口：

1. 用一个可审计的 `experiment_spec` 固定每个试验的输入、参数集、边界、观测策略、季节角色和数值设置，避免继续复制 T9/T10 专用启动脚本。
2. 用一个无绘图库依赖的原尺度评价模块，给所有试验输出一致的指标与残差诊断。
3. 把多季节构建、DSSAT 收获对齐和运行质量门中的隐式全局状态清除，确保同一进程连续运行多个试验不会串季节、串变量或串边界。

**不做：** 新建第二套多季节 builder、自动依据预率定结果修改边界、重新启用 PWAD/PWAI/HWAM、把鲜果重重新放进 Phi、把每个参数都添加秋季偏移，或在本轮开发通用的工作流编排平台。

这是逻辑目标，不要求一次性移动旧文件。T9/T10 启动器可保留以复现历史运行，但不得再向其中加入新试验分支；新矩阵仅经 `experiment_spec` 进入现有 `build_pest_multiseason.py` 和 `run_multiseason.py`。

## 3. `experiment_spec` 最小契约

每个 spec 至少包含以下字段；缺任何一项均应在 build 前失败：

```json
{
  "experiment_id": "E03_joint23_25sp_25fa",
  "scientific_role": "model_comparison",
  "season_inputs": [
    {"season_id": "25SP", "role": "calibration", "input_manifest": "...", "sha256": "..."},
    {"season_id": "25FA", "role": "calibration", "input_manifest": "...", "sha256": "..."}
  ],
  "parameter_set": "configs/experiments/parameter_sets/sobol23_dryonly_v1.json",
  "bounds_id": "<approved-frozen-id>",
  "bounds_sha256": "...",
  "observation_profile": "configs/experiments/observation_profiles/direct_chpdt_log_v1.json",
  "seasonal_parameterization": null,
  "execution": {"ies_num_reals": 200, "noptmax": 4, "seed": 20260723},
  "representative_rule": "final_ensemble_median",
  "evaluation_profile": "article_rawscale_v1"
}
```

强制规则如下。

- 参数集 JSON 必须含排序后的完整参数名、来源 Sobol/审查文件、来源 SHA-256、适用观测、参数数和批准说明；运行时再从 frozen CSV 计算 active 参数数，两个值不一致即失败。
- 每份 frozen bounds、观察策略、季节输入包和参数 profile 都进入 `run_manifest.yaml` 与 `experiment_receipt.json`；不允许 `DEFAULT_BOUNDS`、`latest` 或代码内隐式回退。
- `direct_chpdt_log_v1` 仅允许 CHPDT 进入 Phi，且目标尺度固定为 `ln(CHPDT + 1)`；CHFPW、PWAD、PWAI、HWAM 必须由预检明确拒绝。原 FileA/FileT 始终保留原始物理值。
- 25SP/25FA→26SP 的前向模拟中，26SP 角色为 `frozen_validation`。一旦在 E02 单季诊断或 E06 池化中使用 26SP，则该 spec 中必须标为 `diagnostic`/`development_calibration`，不能写作独立验证。
- E05 的 `autumn_offsets_v1.json` 必须在运行前非空且批准；参数数限制为 1--3，每项含生理依据、变换类型、范围和冻结原因。DMC 偏移在 CHPDT-only 合同下禁止自由率定。

## 4. 可复用输入与评价接口

### 4.1 多季节与采收事件

继续使用 `run_multiseason.py` 的真实日期→前移模型事件→虚拟末次采收→有界就近读取规则。将该规则抽到单一公共解析接口，供 builder、DSSAT runner 和评价器共同调用；不得让评价器自行复制另一套日期匹配逻辑。

建议公共接口只覆盖必要内容：

- 读取 FileT 的真实连续采收事件；
- 生成模型事件日和虚拟末次事件；
- 从 `PestHarvest.OUT`/相应输出读取、按审计过的容差匹配真实事件；
- 输出含 `season_id`、`treatment`、`event_date`、`harvest_number`、`is_virtual_event` 的配对表。

它不是通用 DSSAT 文件语言；其他旧格式仍保持旧兼容路径。

### 4.2 统一原尺度指标

新增 `src/reporting/metrics.py`，不导入绘图库，并让 `figure_data.performance_metrics()` 和新评价器调用它。对每个 `experiment × season × dataset_role × variable × scale × scope` 输出：

- `n`、RMSE、MAE、MBE（固定为 `simulated - observed`）、RRMSE、NRMSE_range、NSE、Pearson R²；
- MSE、MSE_s、MSE_u、MSE_s/MSE、MSE_u/MSE；
- 斜率、截距、计算状态和不适用原因。

`MSE_s`/`MSE_u` 的 OLS 拟合为 `sim_hat = a + b * observed`，并以数值容差验证 `MSE = MSE_s + MSE_u`。原尺度指标是论文主表；`ln(CHPDT+1)` 指标只用于说明 Phi 优化尺度，不能取代原尺度评价。

`experiment_evaluation.py` 还输出：

- treatment×季节的残差轨迹与末次累计残差；
- 处理为重抽样单位的 MBE bootstrap 区间；
- 每个季节×处理×变量的符号游程检验（去除零残差，事件少于 8 时 `not_tested`）；
- 时间相关与累计观测非独立的显式标签；
- 三类结果表：`comparison_raw.csv`、`metrics_rawscale.csv`、`residual_diagnostics.csv`。

不要对累计采收的所有时间点直接做普通 t 检验，也不要把 `MSE_s/MSE > 0.5` 当成模型结构缺陷的单独证明。

### 4.3 后验、共线性和异参同效

复用 `posterior_summary.py`、`equifinality.py`、`candidate_predictions.py` 及有偏移时的 `export_seasonal_parameters.py`。每一正式试验额外写入：

- 初始/最终 ensemble 的 Q05、Q50、Q95、收缩比例与边界比例；
- Pearson 与 Spearman 相关、PCA/条件数；
- 至多三组“Phi 接近而参数距离大”的候选对；必须经确定性重跑并比较预测轨迹后，才能标为异参同效候选；
- 秋季偏移实验同时导出 `shared_value`、`offset`、`autumn_projected_value`，禁止误报为两套独立遗传参数。

## 5. 协作者工作包与验收条件

### P0-A：观测权重与变换单一入口

**范围：** `src/calibration/observation_policy.py`、`build_pest.py`、相应测试。  
**依据：** `CodeReview_权重与观测策略模块_20260723.md` C1、`CodeReview_BuildPest构建模块_20260723.md` C3。

1. 正式模式只允许 `observation_policy` 生成权重和变换；退役的 `weight_scheme=improved` 不得与之串联，应该明确拒绝或只保留手算 Phi 回归用途。
2. 预检和权重审计必须证明 CHPDT 为 `ln(x+1)`，CHFPW/PWAD/PWAI/HWAM 权重为零且未写入活跃观测。
3. 加入“一个观察只经历一次变换、一次权重赋值”的回归测试。

**验收：** 20 members/1 update smoke 的 PST 与 `group_weight_audit.csv` 可追溯至唯一策略文件；手算 Phi 与 PEST 输入一致。

### P0-B：参数集、边界和试验声明

**范围：** 新增 `experiment_spec.py`、`configs/experiments/`、`freeze_bounds.py` 的轻量接口、测试。  
**依据：** `CodeReview_参数注册表模块_20260723.md` M1、`CodeReview_SA复核与Sobol后处理模块_20260723.md` C1。

1. 建立 `sobol23_dryonly_v1`：不得仅因为某旧文件恰有 23 项便采用；需重新核对其来自**干果重目标**的 Sobol 证据。现有 `eggplant_formal_sobol_top23_v1_20260721.csv` 与早期 T7 清单关于 PM06 存在不一致，必须形成明确审批记录。
2. 建立 `highdim55_dryonly_v1`：以 T9 55 项为候选来源，逐项标注适用性；不是自动有效的正式集合。
3. 正式和预率定均拒绝 `DEFAULT_BOUNDS` 及未登记额外参数；预率定只能输出 bounds proposal，不能改写 frozen bounds。

**验收：** 任何哈希不匹配、参数数不一致、未登记 offset 或禁用变量进入 Phi 的 spec 都在 build 前失败；E00 可生成完整审计 receipt。

### P0-C：消除跨试验全局状态并统一采收对齐

**范围：** `build_pest_multiseason.py`、`run_multiseason.py`、`src/dssat/run_dssat.py`、共享解析模块、测试。  
**依据：** `CodeReview_BuildPest构建模块_20260723.md` O5/M1/O6；`CodeReview_DSSAT执行引擎_20260723.md` C1/C2/O1/O3。

1. 不得修改全局 `USER_INPUT_DIR` 或以模块级注入传递 season context；采用不可变 `SeasonContext`/显式参数。
2. 去除 `HARVEST_VAR` 与 `BATCH_FILE` 的隐式全局依赖，所有调用明确传入。
3. builder、runner、evaluation 对同一 FileT 都生成相同采收审计表；保留前移一天、虚拟末次采收、有界就近读取合同。

**验收：** 单进程顺序构建 25SP、25FA、26SP 不串路径；直接采收配对测试覆盖首末事件、虚拟事件和容差越界；历史 T10 dry-only smoke 不回归。

### P0-D：统一指标与残差诊断

**范围：** 新增 `metrics.py`、`experiment_evaluation.py`、`evaluate_calibration_experiment.py`，最小改造 `figure_data.py`。  
**依据：** `CodeReview_*` 系列对历史指标路径遗留变量的审查结论。

1. 实现第 4.2 节指标，含零均值、零极差、样本不足、常数序列和非有限值的明确状态。
2. 实现 OLS MSE 分解闭合测试、处理级 bootstrap、按处理时序 runs test；累积数据禁止行级独立显著性检验。
3. 新评价器不从 PEST/DSSAT 临时目录猜测数据角色；只读已冻结 comparison/trajectory/receipt。

**验收：** 手算 fixture 精确验证所有指标和 MSE 闭合；输出同时具有 25SP/25FA 分组和 raw/log scale；无 HWAM/PWAD/PWAI 出现在 article profile 正式表。

### P0-E：工程质量门与旧路径处置

**范围：** `engineering_gate.py`、旧 runner、测试和用户文档。  
**依据：** `CodeReview_BuildPest构建模块_20260723.md` C1/C2；此前 IES Phi/保留成员问题。

1. 质量门只因明确的 `model_failed`、缺失输出、NaN/Inf、陈旧输出、输入审计失败而拒绝；高 Phi 仅记录 `phi_outlier`，不自动冻结成功运行的成员。
2. 收敛/保留率阈值必须由 spec 声明并输出失败类别；建议首轮工程最低保留率 0.95，未达标标记 engineering failed，而不是修改科学结果。
3. `eggplant_harvest`、`eggplant_process` 等含未定义变量的 legacy mode 不修补扩展；显式标为 deprecated 并在新入口拒绝。

**验收：** 针对成功但高 Phi、DSSAT 崩溃、NaN、旧输出四类 fixture 的分类正确；新试验入口无法调用 legacy mode。

## 7. 交接给协作者的执行约束

1. 每个 P0 工作包独立提交；提交信息写明工作包编号、变更的科学合同和测试命令。不要把格式化、死代码清理或无关重构混入。
2. 修改前先读取本文件、试验矩阵文档以及对应 CodeReview 文档；若发现契约冲突，停止实现并记录最小复现与两个可选方案。
3. 所有正式试验参数均从冻结 CSV 和 spec 读取，不在 runner 中写死 23、55、季节、权重、路径或 E05 偏移参数。
4. 每个新增模块必须有最小单元测试；每个 spec 必须完成 build-only 与 20×1 smoke。正式 200×4 由项目负责人启动，协作者不得在无审批时替换正式边界或覆盖历史运行目录。
5. 交接时提供 `docs/reports/<work-package>_实施记录_<date>.md`，包含：输入哈希、测试命令和结果、未解决风险、兼容影响、下一包的精确入口。

## 8. 与 Code Review 的处理边界

| Code review 文档 | 本轮处理 | 延后处理 |
|---|---|---|
| BuildPest 构建模块 | 双权重、legacy mode 拒绝、季节上下文、采收对齐 | 非阻塞的样式/重复代码 |
| DSSAT 执行引擎 | `HARVEST_VAR`/`BATCH_FILE` 全局状态、公共对齐解析 | 与新试验无关的历史输出兼容重构 |
| 权重与观测策略 | 单一权重/变换路径、干重目标禁止项 | pwtadj1、动态 Min--Max 等退役 API 清理 |
| 参数注册表 | frozen-only、profile 哈希、默认边界拒绝 | 无调用的 IO 和命名整理 |
| SA 复核与 Sobol 后处理 | Sobol23 来源复核与批准记录 | Saltelli 公式/解释脚本的非阻塞整理 |
| Sobol 工具链 | 保留现有计算，补 profile 输入审计 | 广泛算法重写 |

这保证 code review 中真正会损害跨试验可比性的问题先被解决，同时避免项目被低价值清理拖慢。
