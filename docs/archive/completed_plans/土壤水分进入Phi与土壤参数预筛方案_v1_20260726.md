# 土壤水分进入 Phi 与土壤参数预筛方案（v1）

> 归档状态：土壤水分权重与观测角色已经进入后续 E02 配置；本方案保留为设计演变证据。

**状态：** 已获“土壤体积含水率进入 Phi、每季首测排除”的原则批准；尚未批准任何土壤参数进入正式率定。  
**目标：** 用已测土壤体积含水率约束 DSSAT 的水分过程，同时避免把土壤误差、管理误差和遗传参数误差混为一谈。

## 1. 已冻结的观测规则

1. 土壤体积含水率不写入 FileA/FileT；DSSAT 对应输出为 `SoilWat.OUT` 的分层 `SW1D...SWnD`，单位为体积含水率（mm3/mm3，即 cm3/cm3）。
2. 对每个 `season_id × trno × depth interval` 按日期排序；最早日期标记 `initial_condition_only`，不创建 PEST 观测。它只核验已写入 FileX 的初始 `SH2O`。
3. 其余日期以独立 `SOIL_WATER` 组进入 Phi。每个观测保存均值、样本 SD、重复数、来源工作簿/工作表/行规则、实测深度、DSSAT 层重叠权重和排除理由。
4. 25SP 仅保留 TN `2,3,4,5,9,10,11,12,13,14`；TN `1,6,7,8` 不进入作物或土壤观测，并写入 `treatment_exclusion_audit.csv`。
5. 25FA 的土壤日期由文件名 `20251002` 明确记录为 `2025-10-02`。如果这是该季唯一测量，则它只作初始条件核验，该季 `SOIL_WATER` Phi 观测数为零；不能用猜测日期补成过程观测。

## 2. 最小实现：独立而非另造框架

新增一个小型适配器（建议 `tools/experiments/build_soil_water_observations.py`），输入三季原始土壤工作簿、处理映射和目标 bundle 的 `SOIL.SOL`/FileX，输出：

```text
soil_water_observations.csv
soil_water_layer_mapping.csv
soil_water_match_audit.csv
treatment_exclusion_audit.csv
```

运行器新增只读输出适配，不改变 DSSAT 本身：

```text
SoilWat.OUT -> 按 RUN/日期读 SW1D...SWnD
            -> 以 layer_mapping 加权至实测深度层
            -> PestSoilWat.OUT（@SWTxxx@ token）
```

`build_pest.py` 只在 experiment spec 显式启用 `SOIL_WATER` 时生成相应 `.ins` 和观测；其标准差覆盖仍通过 `observation_policy`，不得从 CSV 直接把 `1/sd` 写入 PST。组内按观测数校正、组间预算与 CHPDT/生长组显式并列，防止土壤观测较多而主导 Phi。

### 2.1 深度层映射

实测层与 DSSAT 层不允许“最近层”静默匹配。对每一个实测层 $m$ 和 DSSAT 层 $l$，以厚度交集计算：

$$w_{ml}=\frac{\operatorname{overlap}(m,l)}{\operatorname{thickness}(m)},\qquad
\theta_{m,sim}=\sum_l w_{ml}\theta_{l,sim}$$

若权重和不为 1、实测层超出 `SOIL.SOL` 轮廓，或输出层数和文件头不一致，停止构建并产出 audit，不进入 Phi。分层 SD 来自实测重复；重复不足时保留缺失/回退方法标记，而不伪造“实测 SD”。

### 2.2 验收测试

- 一个合成两层--一实测层案例验证重叠权重、日期和 token；
- 一个首测案例验证观测数恰少一日期、但 initial-condition audit 保留；
- 一个 25SP 案例验证四个排除 treatment 不产生 FileA/FileT/soil/PST 行；
- 确定性 DSSAT smoke 验证 `SoilWat.OUT` 实际存在、`SWnD` 单位和文件头已解析；
- 20×1 IES smoke 验证 `SOIL_WATER` 进入 Phi、无双权重、无 NaN/缺失 token。

## 3. 是否率定土壤环境参数

**可以考虑，但不能直接把所有土壤参数放进联合率定。** 观测土壤水分首先约束水分过程；将多个分层水力参数同时放开，会让它们与初始水分、灌溉记录、根系和遗传参数相互补偿，反而降低遗传参数可辨识性。

首轮只做小型预筛，候选和否决规则如下：

| 候选 | 作用 | 首轮处理 | 原因 |
|---|---|---|---|
| `SOIL_SLDR` | 轮廓排水率 | 可作为 1 个候选；以实测/现有值为中心的小范围，范围需先由审计表给出 | 直接影响灌后含水率衰减，且当前运行器已支持注入 |
| 表层根区 `SOIL_SDUL` | 水分保持上限 | 仅在敏感性筛选确认可辨识时，以少数深度区的受约束参数进入候选 | 不允许把所有层独立放开；必须保持 `SLLL < SDUL < SSAT` |
| `SOIL_SLLL` / `SOIL_SSAT` | 干端/饱和端边界 | 首轮固定 | 没有覆盖强干旱/饱和区的独立观测时很难辨识 |
| `SOIL_SSKS` | 饱和导水率 | 首轮固定 | 当前部分季节深层值缺失/异常，先修输入而非率定 |
| `IC_SH2O` | 初始水分 | 固定 | 首测已作为 FileX 实测初始条件；重复率定会抵消首测排除的科学意义 |
| `SBDM`、`SLOC` | 实测物理/化学性质 | 固定 | 应保留实测值，不作为吸收模型误差的自由度 |

预筛不是正式高维率定：对固定遗传参数和实测管理，以各候选做小型 Morris/局部扰动，检查后续土壤水分残差是否有可辨识的单调响应，以及候选之间相关性是否过高。只有满足“输出敏感、与其他候选非近乎共线、加入后改善留出处理/日期的土壤水分误差且不恶化 CHPDT”的候选，才可写入 frozen bounds 并进入后续联合率定。

## 4. “土壤综合肥力指数”与 `SLPF` 不能等同

土壤综合肥力指数若是由有机质、pH、N/P/K 等实测指标计算的综合指数，应作为**可追溯的站点协变量/审计数据**保存；DSSAT 没有一个与该指数一一对应的通用输入字段，因此不能把该指数直接当成遗传参数或任意乘子率定。

`SLPF` 是 DSSAT SOIL.SOL 中 0--1 的“土壤肥力/光合生长折减因子”，属于经验模型参数，不是综合肥力指数本身。DSSAT 文档把它定义为 soil fertility factor，并说明它可改变生物量累积斜率；这正说明它会与品种光合、叶面积和氮胁迫误差混淆。[DSSAT soil-file definitions](https://dssat.net/wp-content/uploads/2011/10/DSSAT-vol2.pdf)；[DSSAT calibration concepts](https://dssat.net/wp-content/uploads/2011/10/DSSAT-vol4.pdf)。

因此 v1 的策略是：

1. 将综合肥力指数的原始组成和计算式写入 `soil_fertility_metadata.csv`，不写入 Phi；
2. 先用实测土壤水分和作物干物质检查水分过程；
3. 仅当有独立、可审计的土壤矿质氮或植株氮/干物质证据，并且敏感性预筛显示 `SLPF` 对这些指标有稳定、非冗余响应时，才评估**每个实际土壤轮廓一个共享的 `SLPF`**；
4. 该功能需要先扩展运行器对 SOIL.SOL 表层行 `SLPF` 的固定宽度写入，并新增参数注册、physical bounds、单元测试和一个不影响土壤水分的回归测试；在此之前不得把 `SLPF` 写进 frozen bounds。

这比“综合肥力指数直接进入率定”更保守，也更能区分测得的土壤属性、经验折减和遗传参数。

## 5. 交付顺序

1. 建立三季作物/土壤事实表和 25SP 排除 audit；同步按最近质量日期构造 CHPDT。
2. 完成 `SoilWat.OUT` 读取、层映射和确定性 smoke；先冻结观测链，而不放开土壤参数。
3. 完成 20×1 IES smoke，确认 `SOIL_WATER` 的观测数、sigma、组 Phi 和首测排除。
4. 单独执行土壤参数预筛；形成“可放开/保持固定”的一页结果。
5. 仅对通过预筛并获批准的 1--2 个土壤水分参数建立新的 frozen bounds；`SLPF` 另案评估。

**本方案刻意不做的事：** 不把土壤水分写入 FileT；不率定初始水分；不同时释放所有分层水力参数；不将综合肥力指数直接当作 DSSAT 参数；不让未经审计的土壤观测数量主导整个 Phi。
