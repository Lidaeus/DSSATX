# 土壤/环境参数对比分析：当前率定 vs stage4_full_v12 备份

> 目的：回答「当前所用土壤等环境参数与 `C:\DSSAT48_bak\Tomato_Cal\原始遗传参数备份\stage4_full_v12_best_parameters_fixed.csv` 的差异，以及是否存在土壤参数设置错误导致水氮响应能力差」。
> 对比基准：当前四角率定（`e02_wnstress_fourcorner_formal_200x5_20260801_080700`，best member 179）实际使用的输入与参数。

## 0. 结论摘要（TL;DR）

1. **土壤剖面确实被整体更换过**：stage4 时代（旧版，`data/raw/soil/SOIL.SOL` = `C:\DSSAT48_bak\Tomato_Cal\SOIL.SOL`）的 `IBTM910017` 是 12 层结构；当前所有 25SP/25FA/26SP bundle 共用的是 8 层新版剖面（`Workspace/SOIL.SOL`，commit `66513df`「adopt updated XXQL2501 inputs for P1」引入）。**旧版剖面自身存在物理矛盾**（SSAT≈0.294 远低于孔隙度≈0.438，且旧 DUL 0.198–0.25 无法容纳实测含水率 0.216–0.35），新版是对旧版的物理修正，方向正确。
2. **真正导致水氮响应钝化的头号因素是「初始条件」而非土壤物理参数**：当前 FileX 的初始 NO₃ 为每处理实测值（表层 15.6–51.6 mg/kg），换算成 0–60cm 初始 NO₃-N 库为 **109–348 kg/ha**；其中 **25SP 零氮处理 TN13 初始氮库 171.5 kg/ha ≈ 高氮处理（399 kg/ha 施氮）的 43%；26SP 零氮处理 TN12 初始氮库 298.7 kg/ha ≈ N3 施氮量（361）的 83%**。零氮区播前土壤就"不缺氮"，N0–N3 梯度被初始氮库严重污染——这正是 26SP 氮响应弱、N3 异常的结构性原因。
3. **新版剖面三个值得复查的点**：(a) 0–100cm `SSKS` 固定 0.23 cm/h（偏慢，排水受限，低水处理保水过强）；(b) 表层 0–100cm 纹理/有机质取标准 Orangeburg（SLCL 35/SLSI 30/SLOC 1.03–0.54），与实测土壤分析的一致性未在 bundle 中留证；(c) 低水（W1）处理初始 SH₂O 并不低于高水（W3），水分处理差异主要靠灌溉量（283 vs 481 mm）驱动。
4. **遗传参数在"背锅"**：为拟合低水/零氮处理的减产，率定把根系 N 吸收（RTNO3 0.040→0.0155、RTNH4 0.018→0.0118）、最大根吸水（RWUMX 0.0475→0.0342）、N 再动员（NMOBMX 0.25→0.0485）压到很低，把根衰老阈值（PORPT 0.1575→0.279）推高——这是在用遗传参数补偿"过湿、过肥"的环境供给。若初始条件修正，这些极端值大概率会回摆。

## 5. 诊断：土壤参数是否"设置错误"？

按严重程度排序：

1. **初始 NO₃ 过高且与 N 处理不正交（首要问题，属输入数据问题而非 SOIL.SOL 参数）**
   零氮处理初始 NO₃-N 库 109–299 kg/ha，26SP 可达施氮量的 83%。模型 N 响应必然钝化。这是 26SP N 梯度弱最直接、可量化的解释。

2. **新版剖面 SSKS=0.23 cm/h 偏慢（土壤水力参数，值得复核）**
   0–100cm 统一固定 0.23 cm/h（旧版 -99 自动估计）。砂壤土典型 Ksat 1–5 cm/h，0.23 会显著限制排水，低水处理"干不下去"、高水处理易积水，双向压缩水分处理差异。建议：(a) 用实测导水率或 DSSAT 默认估计替换后对比；(b) 至少做 SSKS 敏感性测试。

3. **新版 SLLL/SDUL/SSAT 与旧版差异巨大，但方向是修正而非错误**
   旧版 SSAT 低于孔隙度 33%、DUL 容不下实测含水率，物理上确有矛盾；新版与孔隙度自洽、PAW 翻倍。**不应回退旧版**，但需意识到"更保水的新土" + "偏高的初始含水"共同降低了水分胁迫发生频率，配合 SSKS 偏慢，W1 处理可能整体不缺水。

4. **遗传参数极端化是环境供给过强的补偿信号**
   RTNO3/RTNH4/RWUMX/NMOBMX 被压到很低、PORPT 推到 0.28——若 1–3 修正，这些值很可能回摆到正常区间，否则说明模型结构（番茄模型模拟茄子）在吸水吸氮环节存在系统偏差。

## 7. 勘误与更新（2026-08-01 SSKS 敏感性测试后）

详见《SSKS与水氮响应敏感性测试报告_20260801.md》。三点修正：

1. **SSKS 不是水分响应钝化的原因**：受控实验证明 DSSAT v4.8 水平衡不使用 SSKS（0.23/1.0/2.0/-99 输出逐字节相同，FILEIO 证实修改已读入）。真正旋钮是 SLDR（排水速率系数）与 SDUL（持水能力）——SLDR 0.9 或 SDUL−0.05 可将 25SP 的 W1/W3 从 0.936 恢复至 0.83/0.61（观测 0.78/0.70），但需以 26SP 不出现虚假响应为约束。
2. **第 2.3 节「SSKS=0.23 偏慢值得复查」作废**；SLDR=0.27 偏慢导致低水处理排水不足的推断仍然成立（SLDR 0.05 场景 W1/W3 差距几乎消失证实了方向）。
3. **FileX 输入链（原报告 P0 断链判定已勘误）**：pipeline 内层 runner 会把 batch 的 FileX 列改写为裸文件名并将 bundle TMX 本地化到 run_dir，DSSAT 从 run_dir（CWD）读取 bundle TMX（验证实验：修改 bundle TMX IC 后输出改变）；`C:\DSSAT48\TOMATO` 陈旧副本仅在绕过 pipeline 直接运行 DSSAT 时被读取，不影响率定。土壤（SOIL.SOL）链路经 FILEIO 验证正确。

## 6. 建议的下一步（按优先级）

1. **复核 IC 数据源**：确认 `2025春/2026春土壤数据集.xlsx` 中 NO₃ 的采样日期（播前 vs 追肥后）、单位（mg/kg 干土 vs 鲜土）、以及零氮区是否施过基肥/前茬施肥史。若零氮区播前 NO₃ 确为 15–50 ppm，则 N 响应分析必须把初始氮库作为协变量，或改用播前本底值。
2. **SSKS 敏感性测试**：把 0–100cm SSKS 从 0.23 改为 DSSAT 自动估计（-99）与 1.0/2.0 cm/h，跑 best179 参数下的 W1/W3 差异，观察水分响应是否恢复。
3. **IC 修正试验**：用备份率定值体系（ic_sno3 ≈ 14.7/5.3/4.9、ic_sh2o ≈ .15–.22）替换当前实测 IC（或对 N0 处理压到 ~10 ppm），重跑四角率定或直接前向模拟，检验 N 梯度是否恢复、遗传参数是否回摆。
4. **将初始 NO₃ 库纳入诊断指标**：每次率定前输出各处理 0–100cm 初始 NO₃-N/ NH₄-N 库，与施氮量并列审查（可加进 preflight）。
5. **核对新剖面表层属性来源**：SLCL=35/SLSI=30/SLOC=1.03–0.54 与标准 Orangeburg 剖面一致，但与实测土壤分析（`2025春土壤数据集.xlsx`）的一致性未在 bundle 中留证；建议在土壤生成器日志中记录每层属性来源与 SHA。
