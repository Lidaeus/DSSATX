# E01 25SP 工程门失败根因与修复方案

日期：2026-07-27

## 1. 结论

`e01_25sp_retry3_20260727` 的 25SP yield-full 与 CHPDT-strict 未达到
`engineering_validated`，直接原因是 7% realization 被 DSSAT 原生失败淘汰，
使最终 realization 对齐率只有 0.93，非有限 Phi 比例分别为 0.0417 和
0.0517。

本轮新增诊断把原生失败进一步定位为：

> 25SP TN2 在高叶面积指数、冠层辐射截获达到单精度 100% 时，
> DSSAT 4.8.2 `SPAM/ETPHOT.for` 对剩余辐射比例执行未保护的
> `LOG(0)`，触发 Intel Fortran `error (73): floating divide by zero`
> 和 `__libm_logf_e7`。

这是 DSSAT 数值保护缺失，不是并发文件锁、FileA/FileT、观测单位、
固定列宽、PEST++ Phi 计算或单一参数越界。高 LAI 是触发状态，但现有
证据不支持通过任意收紧某一个遗传参数来代替数值修复。

## 2. 工程门证据

### 2.1 原 100×5 运行

| 运行 | 最终对齐率 | 非有限 Phi | 工程状态 |
|---|---:|---:|---|
| `e01_25sp_retry3_20260727_yield_full_25sp` | 0.93 | 0.0417 | `engineering_failed` |
| `e01_25sp_retry3_20260727_yield_strict_25sp` | 0.93 | 0.0517 | `engineering_failed` |

两者均完成 5 个更新轮次，参数和模拟有变化；失败项仅为：

- `ies_realization_alignment`；
- `ies_final_realization_alignment`；
- `ies_phi_finite`。

因此不能通过修改状态字段或放宽质量门宣称工程有效。

### 2.2 100×1 保留现场复现

新建隔离诊断运行：

```text
workspace/runs/e01_25sp_rootcause_diag_20260727_yield_full_25sp
members = 100
noptmax = 1
n_agents = 4
DSSAT_KEEP_FAILED_RUNS = 1
```

它精确复现了原 100×5 yield-full 第 1 轮的三个失败 realization：
`4`、`54`、`93`。

每个候选均经历：

- PEST++ 3 次重发；
- 每次模型调用内部最多 4 次 DSSAT 尝试；
- 每个候选共保留 12 份一致的失败现场；
- 三个候选在不同 agent 上仍稳定失败。

这排除了“单 agent/多 agent、端口、文件锁或瞬时进程故障”为本批失败的
主因。

本 100×1 诊断最终仍显示 `engineering_validated`，但实际已损失 3 个
末轮成员：最终对齐率为 0.97，非有限 Phi 比例为 0.015，恰好仍分别满足
当前 0.95 和 0.02 的工程阈值。这只说明质量门按已声明阈值正确分类，
不表示 DSSAT 缺陷已经消失；100×5 中失败继续累积后即降至 0.93 并被
工程门拒绝。

## 3. 决定性失败现场

三个唯一失败参数向量的现场摘要如下：

| realization | TN | 崩溃前 DOY/DAP | LAI | 日截获 | 正午截获 | 原生错误 |
|---|---:|---:|---:|---:|---:|---|
| 4 | 2 | 189/114 | 23.255 | 100.00% | 100.00% | error 73 / `__libm_logf_e7` |
| 54 | 2 | 190/115 | 22.558 | 100.00% | 100.00% | error 73 / `__libm_logf_e7` |
| 93 | 2 | 196/121 | 22.756 | 100.00% | 100.00% | error 73 / `__libm_logf_e7` |

每个现场的 `PlantGro.OUT` 只有 `*RUN 1 ... treatment 2`，即在 TN2 内
崩溃，尚未进入后续三个处理。三个参数向量并不共享一个可单独判非法的
参数值。例如：

- `LFMAX` 分别为 1.310、1.038、1.276；
- `SLAVR` 分别为 316.8、327.1、319.6；
- `KCAN` 分别为 0.615、0.500、0.544；
- `XFRT` 分别为 1.000、1.000、0.918。

这更符合“季节/处理状态 × 多参数组合使 LAI 极高”的触发机制，而不是
某个参数单独越界。

## 4. 源码定位

对 DSSAT 官方 `dssat-csm-os` 的 v4.8.2.0 源码
（commit `6d6ae552db15ca16d78adf348daa02088c67af2b`）核对后，
`SPAM/ETPHOT.for` 有两处相关计算：

```fortran
IF (XLAI .GT. 0.0 .AND. DAYRAD .GT. 0.0) THEN
  DAYKR = -LOG((DAYRAD-DYINTR)/DAYRAD) / XLAI
ENDIF

IF (XLAI .GT. 0.0 .AND. DAYPAR .GT. 0.0) THEN
  DAYKP = -LOG((DAYPAR-DYINTP)/DAYPAR) / XLAI
ENDIF
```

现有保护只检查总辐射和 LAI 是否为正，没有检查：

```text
DAYRAD - DYINTR > 0
DAYPAR - DYINTP > 0
```

当高 LAI 使截获辐射在单精度累计中等于或略大于总辐射时，对数参数变为
0 或负数。失败现场的 `ETPhot.OUT` 在崩溃前已连续显示 100.00% 截获，
与 `__libm_logf_e7` 调用栈完全吻合。

全源码引用检查显示 `DAYKR`、`DAYKP` 只在该子程序中声明和赋值，未参与
后续作物生长、产量、土壤水氮或 Phi 计算。因此为这两个诊断量增加合法域
保护，不应改变模型动力学；仍需通过确定性等价测试确认编译器和新二进制
没有引入其他差异。

官方 v4.8.5.0 和当前 develop 分支的同一位置仍保留上述表达式，不能仅靠
替换为未验证的新版本假定问题已修复。

## 5. 推荐修复

### P0：修补 DSSAT ETPHOT 对数定义域

在项目固定的 DSSAT v4.8.2 源码上建立最小 vendor patch，同时修复短波和
PAR 两处：

```fortran
DAYKR = -LOG(MAX(1.0E-6,
     &       MIN(1.0, (DAYRAD-DYINTR)/DAYRAD))) / XLAI

DAYKP = -LOG(MAX(1.0E-6,
     &       MIN(1.0, (DAYPAR-DYINTP)/DAYPAR))) / XLAI
```

`1.0E-6` 表示把“数值上完全截获”限制为 99.9999%，避免 `LOG(0)`；
上界 1.0 同时防止累计误差产生负的有效消光系数。该常数、编译器版本、
编译选项、源 commit、补丁 SHA 和生成的 EXE SHA-256 必须写入运行
manifest。

补丁应只改这两处定义域保护，不借机修改作物参数、管理数据或其他 DSSAT
方程。

### P0：补全失败分类和去重保全

运行器应对以下组合新增明确分类：

```text
returncode = 73
stderr contains "__libm_logf_e7"
ETPhot LI%D/LI%N = 100%
PlantGro LAI is very high
```

建议分类名为 `canopy_interception_log_domain`。对相同参数 SHA 只保留第一
份完整 `_iso_runs`，后续重试只追加 attempt 记录，避免一次候选产生 12
份大体积重复目录。

### 不采用的“修复”

- 不提高 `ies_phi_finite` 容忍阈值；
- 不把最低保留率从 0.95 降到 0.93；
- 不继续增加重试次数；
- 不把 `model_failed` 改记为 `phi_outlier`；
- 不依据这三个候选直接收紧某一个参数边界；
- 不删除 TN2 或修改真实水氮管理以迁就模型。

这些做法都会掩盖数值缺陷或改变科学问题，不能构成有效修复。

## 6. 验收顺序

1. 用补丁版 EXE 对 realization 4、54、93 的保留现场逐一重放：
   3 个参数向量 × 4 个处理全部返回 0，且不再出现 `LOG` 定义域错误。
2. 用原本成功的控制值和至少 20 个成功成员做旧/新 EXE 对照：
   `PlantGro.OUT`、`FreshWt.OUT`、`Pest*.OUT` 和 Phi 在声明容差内一致。
3. 重新执行 100×1 诊断：
   不再产生 `canopy_interception_log_domain`，initial/final 对齐率为 1.0。
4. 使用新前缀重跑 25SP yield-full 与 CHPDT-strict 100×5：
   `status=completed`、`engineering_status=engineering_validated`、
   最终对齐率不低于 0.95、非有限 Phi 不高于 0.02、5 轮文件完整。
5. 完成已修复 `MDAPM` 策略后的 25SP/25FA organ 与 25FA strict 重跑。
6. 六个子试验全部通过工程门后，才恢复边界贴近率、拟合指标和
   `bounds_proposal` 分析。

## 7. 交接状态

当前可确认：

- `MDAPS=-99` 进入 Phi 是独立问题，策略层已修复但相关 100×5 尚待重跑；
- 25SP yield/strict 的剩余失败根因已定位到 DSSAT ETPHOT 对数定义域；
- 并发、端口和文件锁不是 retry3 失败的主因；
- 当前冻结边界不得因这批失败直接升级或收缩；
- 在补丁版 DSSAT 通过上述验收前，25SP 100×5 结果仍为
  `engineering_failed / not_assessed`。
