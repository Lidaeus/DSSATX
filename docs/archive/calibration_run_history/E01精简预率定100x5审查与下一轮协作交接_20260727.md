## 10. 高并发 DSSAT 崩溃的即时重跑机制建议

当前 `run_multiseason.py` 已有 1 次重试（总尝试次数 2），可升级为最多重试 3 次（总尝试次数 4）。该机制只适用于 DSSAT 进程异常退出、共享资源锁冲突或输出未完整生成等瞬时故障，不能隐藏参数边界导致的确定性模型失败。

建议实现：

1. 每个 season 的 DSSAT 调用失败后，清理本次 `_iso_runs` 和残留 tagged 输出，保留失败摘要，不复用半成品输出。
2. 对 `rc != 0`、Windows 原生异常栈、文件占用/锁错误、输出不完整分类为可重试候选；参数格式、FileX 解析、观测解析和固定输入缺失等确定性错误不重试。
3. 重试同一参数向量，等待 1 s、2 s、4 s（带少量随机抖动），最多 3 次；四次均失败才向 PEST++ 返回非零并标记 `model_failed`。
4. 在 `multiseason_run_status.json` 记录每次尝试的 returncode、耗时、错误分类、参数 CSV SHA-256 和是否成功；最终成功也保留 retry 记录。
5. 通过环境变量或 CLI 显式控制，正式率定默认 3 次重试，并建议同时限制 agent 数量为 4。
6. 只有“并发运行失败、单 agent 重试成功、相同参数单独复现稳定成功”三项证据同时满足时，才将该类归为 transient concurrency failure；否则按真实 DSSAT 模型失败处理。

该机制可以提高高并发下的有效成员保留率，但不能替代降低并发、修复共享目录/文件锁或收紧触发原生崩溃的参数组合。重试成功的成员仍需通过完整工程门禁，不能自动进入论文后验分析。
