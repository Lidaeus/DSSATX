## 1. 工作包定位

E01 预率定（55 参数 high-dim）产出 IES 后验后，需要将后验投影到已审批的参数集（如 `sobol23_dryonly_v1`），计算分位数边界并钳制到物理硬限，产出 `bounds_proposal` CSV，再经 `freeze_bounds.py` 人工审批晋升为 frozen 边界，供 E02/E03 消费。

本工具是 E01→E02/E03 的关键审批桥：**禁止**任何下游率定直接消费未审批的 proposal，也**禁止**本工具写入 `bounds_frozen/`。

### 第 5 轮（a/b）· `60f18bd` + `05cf7dd` fix(calibration): 温度组排序缺口修复

**问题**：独立逐参数分位数提取会产生温度组（TB < TO1 < TO2 < TM）的区间重叠或 init 反转，导致 `assert_valid_frozen_bounds` 拒绝 proposal，freeze 步骤崩溃。

**修复**：
- `60f18bd`：新增 `_enforce_temperature_ordering()`，三遍扫描：
  1. 区间重叠 → 中点对称切分
  2. init 反转 → 回退到已审批 base 边界 init
  3. init 钳制到 [lower, upper]
- `05cf7dd`：扩展支持**混合 active/fixed 组**——fixed 成员作为不可变边界约束，仅调整 active 侧；退化区间回退到 base。新增 `TestMixedActiveFixedGroup` 与真实工件（sobol23 + T9）集成测试。

### 第 6 轮 · 本轮 · CLI 写入后验证 + 文件句柄修复

**问题 1（文件句柄泄漏）**：`main()` 中 active 计数使用 `csv.DictReader(open(out, ...))` 未关闭文件句柄。

**修复 1**：
```python
active = 0
with open(out, "r", encoding="utf-8-sig", newline="") as fh:
    for r in csv.DictReader(fh):
        if r.get("status", "").lower() == "active":
            active += 1
```

**问题 2（早期反馈缺失）**：proposal 写入后不验证可冻结性，用户要到 `freeze_bounds.py` 步骤才发现问题。

**修复 2**：CLI 写入后立即调用 `assert_valid_frozen_bounds(out)`：
- PASS → 打印 `Validation: PASS (freezable)`，退出码 0
- FAIL → 打印错误到 stderr，退出码 1，proposal 文件保留供人工检查
- warnings 单独打印（最多 10 条）

**新增测试**（`TestCLIPostWriteValidation`）：
- `test_cli_exits_zero_on_freezable_proposal`：良好后验 → 退出码 0 + `Validation: PASS`
- `test_cli_exits_one_on_stage_init_violation`：XMAGE.median > XFPHT.median（阶段 init 反转，extract 不强制）→ 退出码 1 + `Validation: FAIL`

## 6. 已知限制与后续

- **STAGE_INIT_ORDER 不在 extract 强制范围**：extract 工具强制温度组排序（TB<TO1<TO2<TM），但不强制阶段 init 排序（XMAGE < XFPHT）。后者由 CLI 写入后验证捕获，proposal 仍会写入供人工检查。这是设计选择——温度组是物理硬约束，阶段排序依赖栽培学判断。
- **退化后验回退**：零方差后验经 `clamp_to_physical` 后退化时，回退到物理包络再回退到 base 行；若仍退化则抛 `ValueError`。
- **待 E01 产出真实后验**：当前测试使用合成后验。E01 完成后需用真实 IES 后验复跑 `test_real_sobol23_t9_freeze_succeeds` 的等价路径。
