# Part A：T0/P0 四个决策点

## D1｜26SP 收获观测的 0.90 数值系：哪一侧是权威？

**事实**：s0p34 bundle 内部，`XXQL2601.TMT`（文本，builder/PEST 实际读取）与 `FileT_values.csv`（审计镜像）对所有收获观测差恰好 ×0.90（TMT=未缩放，如 TN1 终值 67508；CSV=0.90 缩放，60757）。运行时闸门不受影响（PST 忠实镜像 TMT），但 e00 交叉审计与人工核查会被误导。v39 设计文件曾出现 `"initial_condition_policy": "26SP harvest scaled 90%"` 字样，但**未找到版本化的批准记录**。

- **A（推荐）**：0.90 缩放不是获批决策 → 以 TMT（未缩放实测）为唯一权威；重建 s0p34 派生 bundle 时同步重写 CSV=TMT 值，并在 manifest 记录 `observation_value_system: unscaled_measured`
- **B**：0.90 是你批准过的缩放（如单株/小区换算修正）→ 以 CSV（0.90 系）为权威；TMT 需按 0.90 重生成，**且此决定须补写决策记录**（日期、理由、适用范围），所有历史 v48 系运行的观测基准随之改变口径
- **C**：维持双轨但显式声明 CSV 为历史副本（不推荐——审计链持续被误导）

**D1 回复**：A，不进行0.9缩放。之前是尝试性的对26sp的N0处理进行0.9倍缩放进行测试，这可能是当时遗留的问题。可以将0.9倍缩放相关的内容删去或更正。
