## 1. 改动详情

### P0-E.1：高 Phi 仅记录为 phi_outlier，不冻结成功运行（`src/reporting/quality_gate.py`）

**问题**：原质量门无 `phi_outlier` 分类。高 Phi 成员可能与 `model_failed` 混淆，导致成功运行的成员被错误冻结。

**修复**：在 `assess_ies_run` 末尾新增 `ies_phi_outlier` 检查：
- 用 IQR（Q3+1.5×IQR）识别高 Phi 离群成员
- 记录为 `warning=True`（QualityReport 的 "warn" 级别），**永不 fail**
- 这落实文档 §5 P0-E.1："高 Phi 仅记录 `phi_outlier`，不自动冻结成功运行的成员"

### P0-E.2：保留率阈值由 spec 声明（`src/reporting/quality_gate.py`）

**问题**：`run_parallel.py:266` 调用 `assess_ies_run(run_dir, case)` 时用硬编码默认 `FORMAL_IES_MAX_REALIZATION_LOSS_FRACTION=0.02`（即保留率 0.98），不读 spec 的 `min_retention_rate`。这导致之前 joint dry-only 运行 0.97 vs 0.98 卡边界失败。

**修复**：
- 新增 `_retention_loss_from_receipt(run_dir)`：从运行目录的 `experiment_receipt.json` 读 `execution.min_retention_rate`（P0-B 已写入），返回等价 loss 分数（1−rate）。
- `assess_ies_run` 在入口调用此函数，若有 receipt 则覆盖默认阈值。
- spec 默认 `min_retention_rate=0.95`（loss 0.05），落实文档 §5 P0-E.2："建议首轮工程最低保留率 0.95"。
- 无 receipt 的历史运行保持默认 0.02（向后兼容）。

### P0-E.3：legacy mode 显式弃用（`src/calibration/build_pest.py`）

**问题**：`eggplant_harvest`、`eggplant_process`、`eggplant_v13` 含未定义/废弃采收变量，未被标记弃用。

**修复**：
- 在 `build_pest.py` main() 新增 `_DEPRECATED_MODES = {"eggplant_harvest", "eggplant_process", "eggplant_v13"}`，命中时发 `DeprecationWarning`（历史复现仍可跑，但明确警告）。
- 新试验入口 `experiment_runner.run_build()` 只用 `eggplant_stage2`（硬编码），无法触达 legacy mode——`test_experiment_runner_uses_stage2_only` 验证。
- 落实文档 §5 P0-E.3："显式标为 deprecated 并在新入口拒绝"。

## 5. 解决的历史问题

本轮 P0-E.2 直接解决了之前 joint dry-only 率定报告的工程门失败：
- **原问题**：joint 运行 194/200 成员保留（97%），但硬编码阈值 0.98 导致 `engineering_failed`。
- **修复后**：experiment spec 默认 `min_retention_rate=0.95`，通过 `experiment_receipt.json` 传入质量门。同样的 97% 保留率现在会**通过**工程门（97% > 95%）。这是文档明确建议的"首轮工程最低保留率 0.95"。

## 6. 未解决风险

1. **`run_parallel.py` 直接调用 `assess_ies_run(run_dir, case)`** 不传 kwargs——它依赖 `assess_ies_run` 内部读 receipt。若运行目录无 receipt（如旧 T10 runner），仍用 0.02 默认。这是向后兼容设计，非缺陷。
2. **phi_outlier 用 IQR 方法**——对极小集成（<4 成员）不发该检查。n≥4 时 IQR 可能对小样本不够稳健，但作为非致命警告已足够。
3. **legacy mode 仅警告未拒绝**——build_pest.py 层面只发 DeprecationWarning。彻底拒绝在 experiment_runner 层（只用 stage2）。若需在 build_pest 层也硬拒绝，需评估对历史复现脚本的影响。
