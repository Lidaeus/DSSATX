## 2. 代码改动

### 2.1 统一 manifest 标量序列化（Finding 2）

`src/common/quality.py` 新增 `serialize_manifest_scalar(value)` 与 `_strip_manifest_scalar(value)`：

- 字符串渲染为 **YAML 单引号标量**（`'` → `''`，外裹 `'...'`）。Windows 路径反斜杠保持字面，既是合法 YAML，又能被项目自带的 `read_flat_run_manifest_field` 无损往返。
- 不用 `json.dumps` 双反斜杠方案，因为项目的轻量读取器不解释转义，会返回字面 `\\`，破坏往返。单引号标量让两种读取器（项目自带 + PyYAML）都正确。
- `_strip_manifest_scalar` 同时升级：单引号值反转义 `''`→`'`；双引号值保持原行为（向后兼容旧 manifest）。`read_flat_run_manifest_field` 改为调用它。

`src/calibration/finalize_calibration.py::_upsert_manifest_fields` 与 `src/calibration/build_pest.py::_write_run_manifest` 都改用 `serialize_manifest_scalar`，修掉了同源 bug。`_write_run_manifest` 的 list 分支保留原 `repr()` 渲染不动（避免扩大范围）。

### 2.2 上游 run_dir 定位（Finding 1，P0）

`src/calibration/build_pest.py` 新增 `_resolve_upstream_run_dir(source)`，识别两种合法布局：

1. **首选**（finalize 标准产物）：`<run_dir>/calibration_finalize/stage_representative_params.csv` + `<run_dir>/run_manifest.yaml` + `<run_dir>/calibration_finalize/calibration_finalize.json`。
2. **遗留**：代表 CSV 直接放在 run 根目录，manifest 与 finalize 子目录在同级。

旧代码 `run_dir = source.parent` 把代表 CSV 的父目录当 run_dir，在布局 1 下会查找 `calibration_finalize/run_manifest.yaml` 与 `calibration_finalize/calibration_finalize/calibration_finalize.json` —— 这正是审查复现的失败路径。`_fixed_from_provenance` 改为调用新 helper，并额外返回 `stage_representative_params.json` 路径用于三方哈希校验。

**根因复现**（独立脚本，旧逻辑）：在 `<tmp>/s1_run/calibration_finalize/stage_representative_params.csv` 布局下，旧逻辑的 manifest 路径解析为 `calibration_finalize/run_manifest.yaml`（不存在）、finalize 路径解析为 `calibration_finalize/calibration_finalize/calibration_finalize.json`（不存在）。审查原文与之一致。

### 2.3 三方哈希一致（T2.2 任务 4）

`_fixed_from_provenance` 在原有 finalize `stage_representative.sha256` ↔ 文件哈希校验基础上，新增读取 `stage_representative_params.json::output_sha256`，三方任一不一致即 `ValueError`，错误消息指明 file/finalize/metadata 三方各自哈希。metadata 文件缺失时不强制（向后兼容），但 finalize 哈希仍必须与文件一致。

### 2.4 DesignSpec 暴露契约 id + CLI 交叉校验（Finding 4）

`src/calibration/design_config.py::DesignSpec` 新增 `bounds_id`、`input_bundle`、`observation_policy_id` 三字段（默认 `""`，向后兼容），`load_design_config` 从 design JSON 顶层读取。

`src/calibration/build_pest.py` staged 入口分两段校验：

- **段 A**（missing_contract 检查后、fixed_from 前）：`args.bounds_id != design_spec.bounds_id` → `parser.error`。
- **段 B**（`verify_calibrated_input_bundle` 后）：`input_manifest.bundle_id != design_spec.input_bundle` → `parser.error`；`Path(args.observation_policy_csv).stem != design_spec.observation_policy_id` → `parser.error`。policy id 取自 CSV 文件名 stem，因为 policy CSV 本身不携带 id 字段。

校验失败一律走 `parser.error`（与现有 staged 入口的所有用户输入错误处理一致）。
