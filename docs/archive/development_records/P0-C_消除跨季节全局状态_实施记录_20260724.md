## 1. 问题

Code Review 第 6 轮发现两个工程反模式：

**O5 [中·过度设计] multiseason 上下文字典注入模式**：13 个函数/常量通过 `ctx` dict 传递给 `build_multiseason_stage2`。`build_pest_multiseason.py` 可以直接从 `build_pest` 导入这些符号。

**M1 [次要] `USER_INPUT_DIR` 模块全局变异**：模块级全局 `USER_INPUT_DIR` 在 multiseason 循环中被逐季节变异（`main_mod.USER_INPUT_DIR = str(bundle)` + `bp_mod.USER_INPUT_DIR = str(bundle)`），使模块不可重入，且变异可能影响后续 FileX 解析。

## 2. 方案

### 2.1 input_dir 参数化（向后兼容）

为依赖 `USER_INPUT_DIR` 的三个函数添加 `input_dir=None` 参数：

| 函数 | 原签名 | 新签名 |
|---|---|---|
| `_resolve_filex_path` | `(filex)` | `(filex, input_dir=None)` |
| `_soil_source_path` | `()` | `(input_dir=None)` |
| `_build_evaluate_observations_from_filea` | `(batch_entries)` | `(batch_entries, input_dir=None)` |

`input_dir=None` 时回退到模块全局 `USER_INPUT_DIR`（单季节 `__main__` 路径不变）；`input_dir` 非空时优先使用，消除全局变异需求。

### 2.2 SeasonContext 数据类

```python
@dataclass
class SeasonContext:
    season_id: str
    input_dir: Path
    experiment_code: str
    treatments: list[int]
```

替代 `USER_INPUT_DIR` 全局变异——每季节的 FileX/SOIL 解析作用域显式限定到该季节的 bundle。

### 2.3 直接导入替代 ctx 字典

`build_pest_multiseason.py` 直接 `from src.calibration.build_pest import ...` 获取函数和常量，移除 13 符号的 ctx 字典。为避免循环导入，`build_pest.py` 的顶层 `from src.calibration.build_pest_multiseason import build_multiseason_stage2` 改为 lazy import（移入 multiseason 分支内部）。

### 2.4 解锁 --execute 模式

新增 `experiment_runner.run_execute()` 函数，subprocess 调用 `run_parallel.py`。CLI Step 3 从占位符改为实际调用，新增 `--n-agents` 参数。

## 6. 已知限制

1. **`USER_INPUT_DIR` 全局仍存在于单季节 `__main__` 路径**：单季节路径在 `__main__` 中设置 `USER_INPUT_DIR = str(Path(args.input_dir)...)`，函数回退到全局。这是刻意保留的向后兼容——单季节路径无跨季节变异风险。未来若需完全清除，可将单季节路径也改为显式传参。
2. **`_collect_tmt_events_per_run`（build_pest.py 内）未加 `input_dir`**：该函数仅被单季节路径调用，无变异风险。multiseason 路径使用 `build_pest_multiseason._tmt_events_per_run`（已加 `input_dir`）。
3. **`--execute` 实际执行需 PEST++ 二进制和 DSSAT 环境**：`run_execute` 调用 `run_parallel.py`，后者需要 `pestpp-ies` 二进制和 `C:\DSSAT48\`。本包仅解锁 CLI 入口，不包含实际率定执行。
