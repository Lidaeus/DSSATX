## 2. 阻塞性发现

### R0-1：异参同效工具会把工程预检自行升级为 `science_validated`

`assess_equifinality()` 没有读取或验证上游 IES `quality_report.json`，却直接把 `process_completed` 写为 pass；其余检查也都可能为 pass，因此通用 `QualityReport` 会自动推出 `science_validated=true`。真实产物 `workspace/runs/eggplant_stage2_v4_sobol20_p2/equifinality/equifinality_quality.json` 已出现这一错误，而上游 P2 运行实际未通过质量门。

影响：下游导出器可能把预检后验误当正式论文证据。

必须修复：异参同效分析要求同一 `run_id` 的上游 IES manifest 与通过的质量报告；工具自己的诊断状态不得替代上游科研状态。工程预检只能输出 `engineering_preflight`。

### R0-2：P2 IES 报告所称“30/30 完整、0 失败”与持久化结果不符

第 0–3 轮参数集合分别为 30、28、27、25 个 realization，最终只保留 25/30，即损失 16.7%。重新运行现有质量入口后结果为 fail：

- `ies_realization_alignment = 0.8333 < 0.90`；
- `ies_final_realization_alignment = 0.8333 < 0.90`；
- Phi 表 120 个预期单元中只有 109 个有限值。

影响：该运行只能作为工程诊断，不能支持“集合收敛”“异参同效风险低”或后验结论。低 Phi 标准差也可能是集合坍缩和成员淘汰的结果，不能解释为低异参同效。

必须修复：正式 IES 完成后自动执行唯一质量入口；未通过时不得继续后验、论文导出或推荐参数。质量报告必须列出每轮保留/剔除成员及原因。

### R0-3：后验诊断漏掉 7 个坍缩参数，且真实 PEST 参数边界未读入

当前代码把“后验方差大于阈值”当作 active 参数定义，并用这个子集生成全部收缩诊断。14 个实际可调参数中有 7 个在末轮方差为零，因而从诊断表完全消失；零方差应被标记为坍缩/不可评估，而不是被当作固定参数删除。

同时，参数 CSV 被转成大写，但 `pyemu.Pst.parameter_data` 索引为小写，边界查找未统一大小写。真实 `posterior_diagnostics.csv` 中所有 `frac_near_lower/upper` 均为空，现有测试只检查列存在，没有检查真实边界值。

影响：收缩率、边界命中、相关性和“7 个活跃参数”的解释均不完整。

必须修复：从 `.pst` 的 `partrans`/可调参数清单识别 14 个 calibrated parameters；所有参数进入边际诊断，只有零方差列从相关/PCA/VIF 数值计算中单独排除并显式标注。新增真实 Pst 大小写和零方差回归测试。

### R0-4：论文导出器不能真正阻止 Phi/轨迹来自另一个运行

comparison 表的 `run_id` 会被核对，但 Phi 和 DSSAT trajectory 的 `run_id` 是由导出命令写入的，不是从上游证据读取。`read_phi_ensemble()` 不产生 `run_id`，因此导出器中的 Phi run_id 检查实际上不会执行；随后代码直接插入 CLI 提供的 `run_id`。trajectory 也采用同样的外部标记方式。

此外，计划要求的 `scenario_type` 以及 input manifest、bounds、weights、validation split 哈希尚未进入 `paper_data_manifest.json`。当前仍可能把反事实 SA、实际率定和其他运行的文件拼成一个表面上“同 run_id”的正式包。

影响：论文图的来源链不够防错。

必须修复：正式导出只接收一个冻结的上游结果 manifest，所有 comparison/Phi/trajectory/metadata 必须是其登记且哈希匹配的成员；导出器不得替来源文件补写身份。增加真正交换两个运行 Phi/trajectory 的负向测试。

### R0-5：机器生成的“审批”越过了预声明用户审批门

Morris 稳定性文件仍记录 `top_k_proposal_review_status: pending`，但后续配置被写为 `review_status: approved`，率定 bounds 甚至记录 `approved_by: Ceres Architect`。P1 v4 计划明确要求 Top-K/Sobol 预算和正式率定参数集由用户审批，协作者或程序不能替代审批者。

影响：冻结配置的治理语义失真，且 W4 在科学决策未批准前开始了 Sobol-guided 率定。

必须修复：保留现有文件用于追溯，但标为未经用户批准的 proposal/engineering preflight；用户审批后创建新的 approval ID 和 frozen ID，不覆盖旧文件。

## 3. 重要但非立即阻塞的发现

### R1-1：N=128 Sobol 单尺度有效，但“收敛”尚未证明

正式收敛实现要求至少两个通过质量门的正式尺度，并默认要求各域 Spearman ≥0.95、Top-K Jaccard ≥0.75、Top-K 最大位移 ≤2。当前 N=64、N=256 均失败；N=4 是预检，且与 N=128 的水氮域 Spearman 仅 0.77。因此：

- 可表述为“N=128 单尺度估计通过内部质量门并给出 bootstrap CI”；
- 不可表述为“Sobol 已收敛”；
- 在第二个有效尺度完成前，Fig. S2 的收敛结论应保持 pending。

为避免无必要计算，本轮不建议立即重跑 N=256。稳定 Morris 可作为率定初筛的主要证据，N=128 Sobol 只作辅助；若论文需要定量 Sobol 收敛图，再用新 seed 补一个有效尺度。

### R1-2：“功能异参同效”命名和现有结论过度

当前 144 对只满足“率定 Phi 相近、参数距离较远”，`prediction_distance` 全为 NaN。它们只能称为“候选补偿解对”或“率定等效候选”，尚未证明在留出处理/新情景中预测等效。PCA 椭圆轴比接近 1 也不能确认异参同效，只说明标准化线性协方差没有单一主导轴。

正式功能异参同效必须比较同一对解在验证处理或预声明情景上的预测距离，并区分：

- 参数不同、验证预测也不同：率定补偿但不可泛化；
- 参数不同、验证预测仍接近：功能异参同效证据。

### R1-3：20 个 Sobol 参数到 14 个 stage2 参数的说明漏列 `LFMAX`

20 个 frozen active 中实际有 6 个未进入 Pst：`ATOP, FRLFF, FRSTMF, LFMAX, PM06, PORPT`，报告写成“排除 5 个”。更重要的是，SA 重要不等于可率定；单季、无根系直接观测的数据不支持仅凭排名同时释放 14 个参数。
