## 3. 阻塞性发现

### P0-1：正式科研结果与保留证据不一致

三季稳定性 JSON 指向形如 `workspace/runs/formal_morris/XXQL2501/seed_20260729` 的目录，而当前构建目录采用 `XXQL2501/r10/seed_20260729`；前者不存在。JSON 中记录的 `.mio` 哈希也无法在当前工作区的 `.mio` 文件中找到。无论这些 case 是被移动、删除还是由旧版本生成，在缺少原 artifact 和哈希匹配前，都不能声称结果可复现。

要求：先生成只读的 `evidence_inventory.csv` 与 `evidence_inventory.json`，逐 case 记录预期路径、实际路径、run status、`.pst/.mio/.rec`、输入/配置/源码哈希和缺失原因。不得通过编辑 JSON 路径来“修好”证据。

### P0-2：正式运行仍依赖可变工作区，dirty build 被主动绕过

`src/sensitivity/sa_build_sen_case.py` 生成的 model command 使用工作区 `src/sensitivity/sa_model.py`、用户输入目录和输出契约的绝对路径，而不是 case 内冻结副本。`tools/sa/run_all_sa_20260720.py` 又无条件传入 `--allow-dirty`。这意味着构建时记录的哈希不能证明每次 forward run 实际读取的是同一批字节，长时间/并行试验期间工作区改动可能改变结果。

要求：正式 case 的 PST 只能引用 case 内相对路径；源码、输入包、输出契约和必要配置均生成最小、只读、带哈希的运行快照。构建、运行和后处理均拒绝 dirty Git 状态与哈希漂移。开发 smoke 可以使用显式 `tooling_development` 作用域，但其结果永远不得升级为正式科研状态。

### P0-3：T6 和 Sobol 在 Morris 稳定性门之前提前下结论

当前摘要本身已显示 XXQL2502 和 XXQL2601 至少有一个域未通过门限；同时，FileA/FileT 观测尚未进入这轮 SA 输入，T6 所称“对应过程有观测”没有被当前 artifact 审计。季节间 `mu*` 比值在分母接近零时会产生极大数值，不能据“>2 倍”直接强制参数进入率定。

要求：T6 文档改为 `draft_blocked`。只有三季各域达到预先声明的稳定性门、输入和结果证据可复现、观测可辨识性审核完成后，才能形成待用户批准的率定候选清单。参数选择应综合绝对标准化效应、排名稳定性、过程观测覆盖、参数可辨识性和机理必要性，不用单一跨季比值作硬门。

### P0-4：XXQL2601 输入包与正式输出契约不一致

当前 candidate input manifest 含 8 个处理并包含重复/待排除的 TN12，而正式输出契约和设计按 7 个处理定义。构建器正确地要求两者一致，因此当前包不能作为正式 case 输入；旧结果引用的 input manifest 哈希又与当前文件不一致。

要求：从只读原始实验文件派生一个新的、不可变的 7 处理 SA 输入包，明确记录 TN12 的排除理由和源文件哈希。不得静默修改 `data/raw`，不得复用旧 hash 身份。

## 4. 其他需要修复的问题

### P1-1：多 FileX batch 只复制最后一个试验文件

`src/calibration/run_dssat.py` 中复制 `model_files` 的循环缩进在 experiment 循环之外，导致 batch 含多个试验 stem 时只复制最后一个 stem 的 `.TMX/.TMA/.TMT`。当前单 FileX case 会掩盖该问题。

要求：将复制循环移入每个 stem 的循环并增加多试验 batch 回归测试，至少验证两个 stem 均被复制、任一 stem 缺失会在运行前失败。

### P1-2：批量运行器违背自适应扩展和零失败门

当前脚本预先构建三个季节的 r=10/20/30/40 共 27 个 case，并把不超过 2% 的失败率显示为可接受；正式契约却要求零模型失败、完整轨迹，并应根据上一层稳定性结果决定是否扩展。

要求：合并 `run_formal_morris`、`expand_morris_r` 和 `run_all_sa` 的重叠职责，保留一个薄的 campaign runner。每次只批准并构建下一个层级；若扩展设计不能证明嵌套，则必须按独立重跑计算预算和证据，不能称为增量补样。

### P1-3：仓库中仍保留相反的 SYMBI 执行脚本

当前 validator 和已跑通的 XXQL2501 case 采用 `SYMBI=N、POTAS=N`，与非豆科茄子使用情景一致；但 `repair_bundle_symbi_y_20260720.py`、`generate_v2_bundles_20260720.py` 及 `*_crgro_y_v2` 仍会生成/描述 `SYMBI=Y`，并以 FRCNOD 数值作为关闭固氮的依据。这会使后续协作者误用相反输入政策。

要求：只保留 `SYMBI=N、POTAS=N` 的规范输入政策；FRCNOD 对非豆科固定并排除，不宣称其数值是官方“关闭固氮”开关。相反脚本和 bundle 移至淘汰档案或删除生成入口，同时保留迁移说明。

### P1-4：Sobol 方案与实际 CLI/算法不一致

方案把模型调用数写成 `D × (2N + 2)`，而当前实现生成 `N × (D + 2)`；示例使用不存在的 `--out-root`，实际为 `--output-root`；收敛命令也不存在 `analyze` 子命令，应使用重复的 `--case-dir` 并提供 `--campaign-manifest`。文档引用的 Top-23 approval 文件当前不存在。

要求：在 Morris 科学门通过之后重新生成方案，成本表必须由构建设计矩阵的同一函数计算并用测试锁定；所有示例命令进入 CLI smoke test。

### P2-1：默认 pytest 会收集工作区快照中的重复测试

规范命令 `python -m pytest tests/` 通过，但裸执行 `python -m pytest` 会收集 `workspace/formal_source_66513df` 等运行快照中的测试并产生导入冲突。运行快照不应成为源码树的一部分。

要求：增加最小 `pytest.ini`（`testpaths = tests`），并把运行快照限制为最小 runtime bundle，不复制仓库测试和历史垃圾文件。

## 5. 值得保留的实现

- `run_dssat.py` 使用 case 本地 `DSSATPRO.V48`、`TMD` 和显式 `CRGRO048` 模型，避免修改共享 DSSAT 安装目录；方向正确。
- SA simulation-only 观测契约、FileA/FileT 非必需门、SOIL/IC 固定政策符合当前遗传参数 SA 的边界。
- 定长字段精度、参数写入后读回、输出有限性/非退化、Morris 轨迹完整性和负向测试覆盖具有实际价值，应在证据链修复中保留。
- 当前 XXQL2501 单 case 的 560 次运行说明核心 forward model、PEST++ Morris 和输出抽取能够贯通，可作为 T7.0 最小重放的基准。
- 测试结果：`python -m pytest -q tests` 为 252 passed、2 skipped；近期目标测试为 59 passed；`compileall` 通过。测试通过说明基础回归稳定，但不能替代科研 provenance 审核。

## 6. 下一阶段：T7.0 证据链与可复现运行收口

### T7.0-A：冻结现场并盘点证据

1. 不再运行新的 Morris/Sobol/IES，不覆盖任何现有目录。
2. 新增证据盘点工具，只读扫描 formal case 和 result summary，输出 CSV/JSON；不得自动修复或删除。
3. 为每个汇总结果给出 `revalidated`、`stale_evidence`、`incomplete`、`build_only` 四类状态。
4. 把 T6、Sobol 和 SA 图表方案的状态改成 `draft_blocked`，清楚列出解锁条件。

验收：仓库中的每一项“已完成”主张都能定位到存在且 hash 匹配的 artifact；无法定位的结果被明确隔离，下游会拒绝读取。

### T7.0-B：实现不可变 formal case

1. 删除正式入口的 `--allow-dirty`；提交并冻结 bounds、输入 manifest、输出契约和运行源码后才能 build。
2. formal builder 创建最小 runtime bundle，PST 中只允许 case 内相对路径。
3. manifest 记录 Git commit/dirty、runtime bundle、输入文件、bounds、output contract、PST、DSSAT executable、DSSATPRO 和关键模型文件哈希。
4. worker 启动前与后处理前均重新核对哈希；不匹配即失败，不产生 `science_validated`。
5. 正式构建必须绑定一份用户已批准、`formal_execution_allowed=true` 的设计文件；candidate 设计不得执行正式任务。

验收：构建后修改工作区 `sa_model.py`、输入 FileX 或输出契约，不改变 case 行为；修改 case 内冻结文件则在运行前被 hash gate 拒绝。

### T7.0-C：输入、runner 与回归缺陷收口

1. 生成 XXQL2601 新的 7 处理不可变 input bundle，审计 TN12。
2. 归档相反的 `SYMBI=Y` 生成入口，建立唯一输入政策说明。
3. 修复多 experiment 文件复制缩进并添加回归测试。
4. 合并 formal Morris orchestration；只允许“本层质量通过 → 稳定性判断 → 经批准扩下一层”。
5. formal 质量门统一为零模型失败、全部轨迹完整、输出有限且非退化；不再显示 2% 失败为通过。
6. 增加 `pytest.ini` 并清理运行快照的测试发现污染。

验收：全套测试、CLI smoke、两个并行 candidate 的隔离测试和多 FileX batch 测试均通过；工作树干净。

### T7.0-D：最小工程重放门

1. 先做 build-only 和单次 deterministic smoke，不做科学解释。
2. 在独立 case 中并发运行两个不同候选，确认输出、DSSATPRO/TMD、临时文件和日志互不污染。
3. 只重放一个最小 Morris preflight，验证 manifest、哈希、失败分类、轨迹和后处理闭环。
4. 提交运行审计报告并暂停，等待 code review。

验收：case 可从干净 commit 按 manifest 独立重建；完整 artifact 哈希可重新计算并一致；质量报告只授予 engineering 状态，不自动授权科研结论。

### T7.1：T7.0 审批后才进行正式 Morris

1. 每季先执行 r=10、3 seeds；每个 case 逐一满足零失败和可复现证据链。
2. 进行预声明的跨 seed 稳定性评估；未通过的域只扩展下一批准层，不批量预建 r=20/30/40。
3. 三季稳定后重新形成 T6 候选提案，区分“进入率定候选”“固定但写入”“排除”，交用户审批。
4. 用户批准 Top-K 后才建立 Sobol campaign；Sobol 与 IES 仍是两个独立审批门。
