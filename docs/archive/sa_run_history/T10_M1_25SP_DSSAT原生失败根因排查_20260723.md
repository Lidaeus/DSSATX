# T10 M1 25SP DSSAT 原生失败根因排查（2026-07-23）

## 结论

25SP 的失败不是 `TMGRO048.CUL`、`TMGRO048.ECO` 或 `TMGRO048.SPE` 的固定列宽错位。对保留的失败候选作独立重放后，`DSCSM048.EXE` 返回 **73**，原始 Fortran 诊断为：

```text
forrtl: error (73): floating divide by zero
DSCSM048.EXE ... __libm_logf_e7
```

因此，已证实的近端根因是：旧 IES 激进更新所产生的某些**联合参数候选**在 DSSAT 内部触发了未受保护的对数/除法数值分支。DSSAT 可执行文件没有可用的符号和源代码行号，不能可靠地将其归因给某一个具体的遗传参数或生理方程。

这仍是原生 DSSAT 的数值失败；不是 PEST++ 的 Phi 计算错误，也不是文件解析或列宽破坏。

## 可复现证据

### 失败现场保留与重放

- 诊断运行：`workspace/runs/eggplant_t10_m1_legacy_forensics_20260723`
- 设计、随机种子和参数边界均与旧 M1 一致；仅保留旧默认 IES 试探设置：`ies_lambda_mults=0.1,1,10`、`lambda_scale_fac=0.75,1,1.1`。
- 显式设置 `DSSAT_KEEP_FAILED_RUNS=1` 后，25SP 失败候选及其 `pest_params.csv`、CUL/ECO/SPE、原始输出被复制到各 agent 的 `failed_dssat_artifacts/`。
- 将其中一个失败候选复制到 `workspace/diagnostics/m1_25sp_retained_failure_replay_20260723` 后，用同一 `DSSBatch.selected.v48` 单独运行，稳定复现退出码 73。

失败发生在 IES 的更新候选评估阶段；旧 M1 初始 ensemble 中被日志标记的 realization 1 用其初始参数向量单独重放时，25SP 与 25FA 均成功。这排除了“初始输入文件本身恒定损坏”的解释。

### 固定列宽审计

对重放现场的目标记录逐字段核查：

- CUL 的 `TM0008` 记录与基线同为 144 个字符；`CSDL`、`EM-FL`、`FL-SH`、`FL-SD`、`LFMAX`、`XFRT`、`SFDUR` 等写入值均与该候选参数经字段宽度舍入后的预期值一致。
- ECO 的 `TM0001` 记录与基线同为 144 个字符；`EM-V1`、`JU-R0`、`PM06`、`PM09`、`FL-VS`、`TRIFL`、`XFPHT`、`XFINT` 等均写入正确字段。
- SPE 的命名行长度未改变；`WTFSD/PORPT/FRSTMF/FRLFF/ATOP/FRCNOD`、`FINREF/SLAREF/SIZREF/VSSINK/EVMODC`、`RTNO3/RTNH4/RTEXF` 均为预期字段宽度内的舍入值。
- 该候选通过 `validate_candidate_parameters()` 的物理硬边界检查。

所以，“数值处于允许的单参数区间”并不保证多参数组合对 DSSAT 的内部数学函数安全；但现有证据不支持通过收紧某一个参数边界来宣称已修复原因。

## 对率定的处理

1. 只有 DSSAT 不能正常运行的成员标为 `model_failed`；不再用高 Phi 自动剔除运行成功成员。
2. 对 M1 保持已批准的保守 IES 数值配置：

   ```text
   ies_use_approx = false
   ies_lambda_mults = 0.5,1.0,10.0
   lambda_scale_fac = 0.9,1.0
   ies_enforce_bounds = true
   ```

   它缩小更新试探步幅，不改变观测、权重、参数边界或科学目标。
3. 不把本诊断运行用于参数后验、共线性、异参同效或论文结果；其唯一作用是定位工程失败。
4. 以后若再出现模型失败，可在**诊断运行**中设置 `DSSAT_KEEP_FAILED_RUNS=1`。正式运行默认不保留临时目录，以免积累大量中间文件。

## 已实现的可审计性修复

- `src/calibration/run_dssat.py`：诊断开关开启时保留失败隔离目录、参数快照、运行参数，并记录内层 DSSAT runner 的 stdout/stderr。
- `src/calibration/run_multiseason.py`：在季节目录被下一次模型调用清理前，将失败的 `_iso_runs/` 复制到 `failed_dssat_artifacts/`。
- 回归测试：`tests/test_dssat_failure_artifacts.py`。

这项机制用于根因定位，不改变正式率定的模型结果、权重或成员保留规则。
