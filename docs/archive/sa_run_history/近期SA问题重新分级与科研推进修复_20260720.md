# 近期 SA 问题重新分级与科研推进修复

> 日期：2026-07-20  
> 原则：只优先修复会改变模型输入、参数敏感性排序、正式结果可复现性或后续率定结论的问题；纯工程整洁性问题延后。

## 1. 重新分级结论

### P0：必须在新的正式 Morris 前解决

| 问题 | 科研影响 | 处理状态 |
|---|---|---|
| PST 引用可变工作区源码、输入和输出契约 | 同一 case 在运行期间可能执行不同代码/数据，敏感性结果无法复现 | 已修复：case 内冻结最小 runtime，PST 只使用相对路径，每次 forward run 校验全部 SHA-256 |
| formal builder 可用 `--allow-dirty` 绕过版本门 | 结果无法对应唯一 Git 版本 | 已修复：正式构建无绕过选项，dirty worktree 必然拒绝 |
| 旧三季汇总可在上游 artifact 缺失时继续消费 | 可能把不可重验结果传给 T6/Sobol/论文 | 已修复：multi-seed 后处理要求 clean build 和完整 runtime manifest，并重新核对每个冻结文件哈希 |
| `SYMBI=Y` 与非豆科政策冲突 | 改变氮过程，直接影响遗传参数敏感性 | 已修复：正式输入统一为 `SYMBI=N、POTAS=N`；三个正式 contract 均绑定 N bundle；旧 Y 生成入口硬性停用 |
| XXQL2601 TN12 水分因子误录 | 错误造成 W3/N0 重复并缺少 W1/N0，直接改变水氮响应 | 已修复：用户确认 TN12 为 W1/N0；原始 FileX 的 MI 更正为 1，并重新派生带新 ID/哈希的完整 8 处理 bundle |
| 多 FileX batch 只复制最后一个试验文件 | 多季/多试验运行会缺失输入或读取错误文件 | 已修复循环缩进并增加两个 FileX 的回归测试 |
| runner 接受不超过 2% 的模型失败 | 失败轨迹可能改变 Morris 排名 | 已修复：正式门统一为零失败，出现失败立即停止后续季次 |
| 一次性预建 r=20/30/40 | 在 r=10 尚未审核时浪费大量计算，并混淆独立设计 | 已修复：规范 runner 只构建三季 r=10×3 seeds；扩展层入口暂停，必须逐层批准 |

## 4. 最短科研推进路径

当前不再需要先做全面历史证据盘点。新的正式结果将与旧结果使用不同目录，并由代码自动拒绝缺少冻结 runtime 的旧 case。

1. 审核并提交当前必要源码、v3 frozen bounds、三个 N bundle、三个 output contract 和设计配置，使工作树干净。
2. 在新目录 build 三季 r=10×3 seeds；formal builder 会验证 clean Git 和所有输入 manifest。
3. 先对 XXQL2601 新 8 处理修正 bundle 做一次 deterministic baseline smoke；其他两季已有 N bundle 测试基础，可只做快速复核。
4. 对一个 seed 做最小 frozen-runtime forward smoke，核对 runtime manifest、输出数量、有限性和并行隔离。
5. smoke 通过后运行三季 r=10；任一 case 有模型失败即停止，不继续下一季。
6. 三季 case 全部通过质量审计后执行 multi-seed stability。
7. 只有不稳定的季次/域才提交一个下一层扩展方案；稳定则直接重做 T6 候选审核。
8. T6 经用户批准后再决定是否需要 Sobol；不把 Sobol 设为进入率定的强制前置步骤。
