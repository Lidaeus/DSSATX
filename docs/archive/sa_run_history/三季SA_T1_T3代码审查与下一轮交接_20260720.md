# 三季 SA T1–T3 代码审查与下一轮交接

> 日期：2026-07-20  
> 审查结论：有价值的工程证据已形成，但存在 3 项阻塞问题；不得启动正式 Morris、Sobol 或率定  
> 审查范围：三季 baseline smoke、FileX/manifest 修复、季节输出契约、55 参数注入读回、生产运行入口及新增测试

## 1. 总体结论

本轮完成了三季 deterministic baseline、季节输出契约和参数注入预检的主要工程探索，确认了以下事实：

- 三个 controlled bundle 均可产生 8 行 Evaluate、8 个 PlantGro/FreshWt run，现有 baseline 产物完整；
- FileX `@N OPTIONS` 是固定列格式，旧导入函数把整行重新序列化为短 token 行会导致 DSSAT 错读；改为单字符原位替换是正确方向；
- 在当前 DSSAT 4.8.5/CRGRO048 可执行环境中，固定列正确时 `SYMBI=N` 触发 IPSIM，而 `SYMBI=Y` 可以运行；这是本机 A/B 工程证据；
- 三季输出契约均可从 baseline 提取有限值；
- `PM06` 字段精度和 `XFINT` 下界与运行时 guard 的冲突被暴露，建立注入后读回检查是必要的。

但当前实现不能批准进入正式 SA。阻塞项是：生产入口尚未真正使用 smoke 中的路径隔离修复；XXQL2601 不是完整且唯一的 2×4 水氮设计；`SYMBI=Y` 的兼容性事实被错误解释为“FRCNOD=0.05 关闭实际固氮”，且版本化 bundle 被原地修订。另有测试时长、文档漂移和工作区垃圾需要收口。

## 2. Code review 发现

### [P0] 正式 SA/率定入口没有复现 baseline smoke 的运行条件

`tools/sa/run_three_season_baseline_smoke.py` 通过三项特殊处理才运行成功：运行目录本地 `DSSATPRO.v48/CRD`、显式 `--model CRGRO048`、临时移走共享 `C:\DSSAT48\TOMATO` 中同名 FileX。

但生产入口 `src/calibration/run_dssat.py` 目前只新增了说明和未使用常量：

- `_DSSAT_ROOT/_TMD_DIR/_TMD_CONFLICT_*` 没有被调用；
- `_DSSAT_MODEL_CODE` 没有加入实际 `localized_args`；
- `prepare_run_directory()` 复制的 `DSSATPRO.v48` 仍把 `CRD` 指向 `C:\DSSAT48\Tomato_Cal\Workspace`；
- 正式 SA 的 PST 仍经 `sa_model.py → src/calibration/run_dssat.py`，因此 baseline smoke 成功不能证明 Morris worker 会读取同一 bundle。

同时，不能把“每次模型调用移动共享 TMD 文件”直接搬入生产入口。多个 PEST++ agent 并行时会互相竞争、短暂删除安装目录文件，并影响同机其他 DSSAT 任务。需要真正的并发安全隔离方案。

**结论：** 当前正式 SA 仍可能读取共享 TMD 的旧 FileX，属于输入污染风险，必须阻塞。

### [P0] XXQL2601 被误写成完整 2×4 设计，重复处理仍被双重计权

XXQL2601 原始 FileX 中：

- TN9 = `MI3/MF4`；
- TN12 = `MI3/MF4`；
- 不存在 `MI1/MF4`。

当前 contract 只在派生 `WN_*` 中选择 TN12、丢弃 TN9，但两者仍都进入 per-treatment base responses。受控 FileX 已统一 IC，因此 TN9/TN12 的管理和初值完全相同，baseline 输出也相同；保留两者会给 `W3/N0` 双重权重，属于伪重复。

设计 v2 仍声明“每季 8 个处理、完整 `MI1/MI3 × MF1–MF4`”，与实际输入不符。不得通过 contract 注释把缺失组合伪装成完整析因。

**推荐：** 在用户确认前，保留 TN9、删除 TN12，XXQL2601 按 7 个唯一组合运行，并明确缺少 W1/N0；如果用户确认 TN12 的 MI 应为 1，再创建新的版本化修正 bundle，不能直接改原始 FileX。

### [P0] `SYMBI=Y` 的工程兼容性与生物固氮解释混在一起

A/B 运行足以支持“当前 CRGRO048 可执行环境要求 OPTIONS 中 `SYMBI=Y`”这一兼容性结论，但不足以支持“实际生物固氮由 `FRCNOD=0.05` 关闭”。`FRCNOD=0.05` 是官方 tomato SPE 基线值，不是零，也没有本轮模型输出或源代码证据证明它是 off switch。

正确表述应为：

- `SYMBI=Y` 是当前 DSSAT 4.8.5/CRGRO048 的运行兼容设置；
- 茄子仍按非豆科解释，`FRCNOD` 固定、排除 SA/率定；
- 是否存在实际 nodule/fixation 通量必须通过可输出状态量、模型源代码或 DSSAT 官方说明独立审计；审计前不得声称由 0.05 关闭。

此外，controlled bundle 被原地从 `SYMBI=N` 改成 `Y` 并重写 manifest。即使另有 repair JSON，也破坏了“bundle ID 对应不可变字节”的版本化语义。应生成新 bundle ID，并通过 derived-from 哈希连接旧候选。

### [P1] source bundle、controlled bundle、设计与文档相互矛盾

- 三个 source bundle 仍为 `SYMBI=N`，现在会被校验器拒绝，但 manifest 中旧 `science_status` 未反映这一点；
- controlled bundle 已为 `SYMBI=Y`；
- README、CHANGELOG、项目状态、目录规范和两份交接仍要求 `SYMBI=N`；
- 设计 v2 仍写 baseline 未完成，实际 baseline 已完成；
- CHANGELOG 仍写“只导入一季”，实际三季已存在。

任何新运行前必须只有一个当前规范；历史判断应保留在 review/归档中，不得继续作为用户操作指令。

### [P1] 55 参数注入预检不应把任意 5% 相对漂移视为可接受

固定宽度读回是正确的，但 `PRECISION_LOSS_THRESHOLD=5%` 是任意统计阈值，不是 DSSAT 字段分辨率。SA 的边界应先量化为文件可表达值；否则设计空间与实际空间不同，Morris 步长也会偏移。

建议门禁：

- requested 与 readback 必须相同，或差值不超过该字段最后一位有效数字的半个单位；
- 若 proposal 不能表达，修改 proposal 为可表达的十进制值并重新审核；
- 不把“最接近的格式化结果”归类为科研可接受的静默误差。

### [P1] 一个普通单元测试执行完整 165 次文件注入，导致测试套件超时

`test_full_preflight_report_categories()` 在 pytest 中调用真实 `run_preflight()`。本轮该测试在 120 秒内未完成；排除它后为 `249 passed, 2 skipped, 1 deselected`。完整预检应是显式 integration/CLI gate，普通单元测试只验证少量代表参数和报告判定逻辑。

### [P1] baseline 有限不等于输出已适合排名

baseline contract audit 的有限率为 100%，但 ADAPS/PDFPS 在各季处理间恒定，XXQL2502 的 DAP45 LAI 也恒定。处理间恒定不必然表示对参数不敏感，但必须由 lower/init/upper DSSAT 扰动验证，而不是仅靠一次 baseline 宣布 T2 完成。

`FRUITD_DAP50` 实际表示“累计采收达到 50% 的 DAP”，命名容易被误读为“DAP50 时的果实量”。下一版 contract 应改成清晰名称，例如 `CUMHARVEST_DAP50`，并同步导出代码和测试。

### [P2] 一次性修复脚本和运行垃圾尚未清理

仓库根目录出现 `DSSBatch.v48`、`run.log`；`workspace/runs/` 下存在 `_ab_*`、`_stale_*`、`_hybrid_*` 等诊断脚本/副本；`tools/sa/__pycache__` 也存在。一次性 bundle repair 脚本和两个全局 repair JSON 不应成为长期产品入口。保留必要审计摘要，删除可再生垃圾。

## 3. 下一轮任务：T4.0 正式 SA 入口收口

下一轮只解决正式 SA 前的阻塞项，不启动 Morris、Sobol、IES，也不解读参数敏感性。

### T4.0-A：并发安全的 DSSAT 输入隔离

1. 让 `src/calibration/run_dssat.py` 的真实生产路径使用运行目录本地 `DSSATPRO.v48`，将 `CRD` 写为当前隔离目录。
2. 正式 model command 明确传递 `--model CRGRO048`，并由测试检查最终 argv。
3. 禁止生产代码移动、删除或覆盖共享 `C:\DSSAT48\TOMATO` 文件。
4. 选择一个最小安全方案：优先为每个 worker 使用隔离的 DSSAT root/TMD；若采用唯一 FileX 别名，必须证明 DSSAT 文件名约束、batch 固定列和输出身份均正确。
5. 增加两个并发模型调用测试：不同 bundle/参数同时运行，读取各自 FileX 哈希，且共享 DSSAT 安装前后哈希不变。

验收：生产入口（不是 smoke 专用脚本）连续和并发运行三季均成功；manifest 记录实际 FileX、batch、DSSATPRO、模型代码和可执行文件哈希。

### T4.0-B：重建不可变 bundle 与 SYMBI 契约

1. 不再原地修订现有候选；从用户 raw/source 创建新的 `*_crgro_y_*_v2` bundle ID。
2. manifest 记录：DSSAT 版本、`SYMBI=Y` 兼容性原因、A/B 证据路径/哈希、`FRCNOD` 仅固定排除而非“off switch”。
3. source 与 controlled bundle 都必须通过当前校验；旧 `SYMBI=N` bundle 标记 superseded，仅供追溯。
4. 更新 README、CHANGELOG、项目状态、目录规范、用户指南和本轮交接，消除 `SYMBI=N/Y` 冲突。
5. 为 OPTIONS 原位单字符修改增加 CRLF/LF、多个 OP 行、字段缺失和相邻字段字节不变测试。

验收：每个新 bundle ID 从创建后字节不再变化；manifest integrity 和语义校验同时通过。

### T4.0-C：解决 XXQL2601 处理设计

1. 向用户报告 TN9/TN12 重复及缺少 W1/N0；未经确认不得把 TN12 自动改成 MI1。
2. 默认安全方案：新候选暂保留 TN9、删除 TN12，形成 7 个唯一处理；contract、batch、design 全部一致。
3. 若用户确认 TN12 原本应为 MI1，则创建派生修正 bundle，并在 manifest 中记录授权和修改前后哈希。
4. 任何情况下，基础响应和派生响应都不得重复计权同一管理组合。

验收：唯一 `(MI, MF)` 数量等于 treatment 数量；测试使用 equality 而非 subset 检查 contract treatments 与 batch。

### T4.0-D：输出契约和参数读回门收口

1. 基于最终 bundle 重建三季 output contract；更名 `FRUITD_DAP50 → CUMHARVEST_DAP50`。
2. 运行一季 55 参数 lower/init/upper deterministic OAT，并检查：返回码、实际注入读回、每项响应有限性和非恒定性。
3. 把 5% 容差改为字段分辨率门；所有 proposal 边界先量化后再申请 freeze。
4. 将完整 165 次 preflight 移出普通 pytest，作为显式 integration 命令；单元测试使用小型 fixture。
5. 报告无响应参数时先区分注入失败、输出定义不响应和真正低敏感性。

验收：普通全套测试在合理时间内完成；integration preflight 单独产出带哈希 JSON；无 silent clipping/rounding。

### T4.0-E：清理与审查交付

1. 删除根目录 `DSSBatch.v48`、`run.log`、`__pycache__` 和可再生 `_ab/_stale/_hybrid` 诊断文件。
2. 将必要 A/B 证据压缩为一个只读审计报告，不保留会再次修改 bundle 的一次性产品脚本。
3. 提交一份 T4.0 实施记录，列出代码提交、输入 bundle ID、测试结果、未解决科学事项。

## 4. 下一审查门

T4.0 完成后暂停，由 code review 核对：

- 正式 worker 与 smoke 是否走同一执行路径；
- 并发时是否零共享安装写入；
- 三季 treatment 是否无伪重复；
- SYMBI/FRCNOD 表述是否只陈述有证据的事实；
- proposal 是否全部可由 DSSAT 文件精确表达；
- 普通测试与 integration preflight 是否分层。

只有该审查通过，才安排 T4.1 小规模 Morris preflight；仍不自动进入正式多 seed Morris 或 Sobol。
