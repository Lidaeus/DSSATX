## 一、静态分析背景与现状诊断

本项目（DSSAT × PEST++ 番茄/茄子参数率定系统）经过从单体结构到模块化架构（P0~P2、以及 2026 年 7~9 月的多轮科研探索）的高强度演进，仓库内沉淀了大量不同历史阶段的脚手架、临时补丁与试验中间件。

### 静态分析核心发现：
1. **根目录与非受控目录污染严重**：
   - 存在历史整库快照目录（如 `macOS_dssat_n_response_workspace_20260803/`）、错名图表缓存（`figture/`）、外部 node 依赖（`node_modules/`）及中间运行工作区（`_seasons/`），这些目录虽然大多被 `.gitignore` 忽略，但在本地磁盘依然存在，导致 IDE 索引变慢、代码检索命中大量伪阳性结果，并占用数 GB 空间。
   - 根目录下散落临时重定向文件（`--help.rec`）、未清理的 R 绘图缓存（`Rplots.pdf`）、PEST 输出文件（`Pest*.OUT`）与映射表（`*mapping.csv`）。
2. **`workspace/` 根目录存在大量淘汰脚本**：
   - 除了 3 个被单元测试显式守护的存根（`analyze_results.py`, `build_pest.py`, `run_dssat.py`）外，残留了 15 个 2026-07-21 阶段的一次性调试脚本（如 `generate_pst.py`, `test_exe.py`, `debug_tmtgrow.py` 等），与规范工作流严重脱节。
3. **`tools/` 目录过度膨胀（480+ 个脚本）**：
   - 规范核心工具仅约 11 个（如 `run_parallel.py`, `freeze_bounds.py`, `clean_workspace.py` 等）。
   - 其余约 470 个脚本为 7~9 月科研探索过程中的“一次性试验启动器与单次分析脚本”（集中在 `tools/calibration/` 264 个、`tools/experiments/` 90 个、`tools/analysis/` 54 个、`tools/sa/` 24 个）。此外，`tools/scratch/` 还存在直接用字符串修改源码的临时热补丁脚本。
   - 个别工具（如 `tools/reporting/generate_v46_page25_publication_suite.py`）使用 Python `matplotlib` 绘制正式论文图，直接违背了“R 是论文图唯一渲染器”的双轨制架构铁律。
4. **核心代码库 (`src/`) 存在重大代码重复**：
   - `src/dssat/run_dssat.py` (160KB) 与 `src/calibration/run_dssat.py` (169KB) 存在超过 4000 行几乎逐字相同的参数格式化与 DSSAT 写入代码，后者仅在其末尾增加了基于 `_iso_runs` 的隔离执行与原子回拷逻辑。这种“双头代码”极易导致维护时“改一处漏一处”的科学计算灾难。

## 二、处置分类标准

为确保操作安全且绝不误删有科学复核价值的代码，我们将所有文件划分为四类处置方式：

| 处置类别 | 标识 | 定义与动作 |
|---|---|---|
| **A. 直接删除** | `[DELETE]` | 纯临时垃圾、外部非项目依赖、调试残余、失效的热补丁，在 Git 或生产中无任何保留价值，直接安全删除。 |
| **B. 归档隔离** | `[ARCHIVE]` | 具有历史科研探索记录价值、特定版本试验回溯价值，但不再作为日常运行工具的脚本，统一迁移到 `tools/archive/` 或指定归档目录，移出代码主搜索路径。 |
| **C. 重构/并入主程序** | `[REFACTOR/MERGE]` | 功能具备生产价值或属于核心链路，但存在重复实现或入口混乱，需将其逻辑规范整合并入 `src/` 主程序，消除冗余。 |
| **D. 规范保留与文档标识** | `[KEEP/DOCUMENT]` | 属于当前受测试保护或核心生产链路的脚本，保持原位，补充/更新说明文档或存根标准。 |
