## 1. 推荐的论文战略

### 1.1 优先采用“两篇论文”路线

**论文 A：通用方法/软件论文。** 核心问题是跨作物 CUL/ECO/SPE 参数化是否正确、可复现、易配置，并在相同预算下达到有竞争力的预测和计算表现。较适合 *Computers and Electronics in Agriculture*、*Environmental Modelling & Software* 或同类期刊。

**论文 B：eggplant 科学应用论文。** 聚焦 eggplant 借用 TMGRO/CRGRO 后的参数可辨识性、多季节/多处理预测、管理交互和生理解释。较适合 *European Journal of Agronomy* 等作物学期刊。

这样可以避免用一个高度定制的 eggplant 案例支撑“多数 DSSAT 作物通用工具”这一过强主张，也避免软件架构细节挤占作物科学叙事。

若资源只允许一篇，建议以 4–6 个官方 DSSAT 作物的通用基准为主线，eggplant 仅作为“生物学作物与 DSSAT 模型身份分离、多收获观测和 SPE 扩展”的困难案例。不能以 eggplant 单案例宣称跨作物通用性。

### 1.2 与 2020 DSSAT-PEST 论文的关系

Ma et al. (2020) 的 DSSAT-PEST 通过 R 自动生成 PEST 文件，引入多初值 Monte Carlo、filter ratio 预筛和可调输出权重，并在玉米、大豆、小麦、水稻和棉花上与 DSSAT-GLUE 比较；其报告的 PEST 平均运行时间约为 GLUE 的 65%。作者同时指出需要敏感参数选择、尚未优化土壤参数，而且增加过程变量并非总能改善结果。[论文 DOI](https://doi.org/10.1016/j.eja.2020.126017)

本研究不应只做“将 PEST 换成 PEST++”的增量复刻。更有说服力的贡献是：**版本感知的 CUL/ECO/SPE 安全参数化、层级作用域控制、统一观测/误差契约、可比较的优化后端和证据化跨作物支持声明**。优化算法本身不是主要原创点。

## 2. 可主张的创新与证据门槛

| 候选创新 | 最低证据 | 不应使用的过强表述 |
|---|---|---|
| 描述符驱动的 CUL/ECO/SPE 参数化 | 多版本/多模型族 round-trip、目标字节 containment、错误版本 fail closed | “支持全部 DSSAT 参数” |
| species–ecotype–cultivar 层级率定 | 多 cultivar/环境试验；CUL-only、CUL+ECO、CUL+ECO+SPE 消融；留出验证 | “首次率定 SPE”或“识别真实物种参数” |
| SA-informed/staged PEST++ IES | 与 all-at-once 相同预算、多 seed 对比、边界率与预测结果 | “新优化算法” |
| 统一观测与不确定性契约 | 多变量、多时间尺度、sigma 审计、区间校准指标 | “贝叶斯后验” |
| 工程与科研状态双门禁 | 故障注入、stale output、hash/provenance 检测率 | “杜绝所有错误” |
| 易用性提升 | 独立用户任务试验或至少客观设置步骤/错误/时间统计 | 无用户研究时直接称“user-friendly” |
| 跨作物通用性 | 语料 C2 覆盖 + ≥4 作物/3 模型家族 C4 | 只凭文件被解析就称“科学支持” |

建议将摘要中的创新压缩为三点：

1. 一个版本化、作用域感知且可回读验证的 DSSAT CUL/ECO/SPE 参数描述与注入框架；
2. 一个将观测、误差模型、优化器和执行环境解耦的跨作物率定工作流；
3. 一套同时评估文件正确性、合成恢复、真实留出预测、计算效率和可复现性的证据框架。

## 3. 研究问题与预注册假设

### RQ1：文件层正确性

**问题：** 工具能否在多 DSSAT 模型家族和版本中安全、可逆地定位并修改 CUL/ECO/SPE 参数？

**H1：** 对声明达到 C2 的参数，100% lower/init/upper 试验均满足数值回读容差，且非目标字段零变化；对不兼容版本或歧义锚点 100% fail closed。

### RQ2：参数恢复与可辨识性

**问题：** 在已知“真实参数”的合成数据中，工具能否恢复参数与预测不确定性？

**H2：** 在预设噪声和缺失场景中，主要可辨识参数的归一化误差低于预注册阈值，90% 预测区间覆盖率接近名义水平；弱可辨识参数允许宽区间，而不以点估计接近真值作为唯一标准。

### RQ3：跨作物留出预测

**问题：** 相比 DSSAT 默认参数、GLUEP 和可复现的 PEST/dpest 基线，本工具在相同数据与预算下是否改善独立季节/地点预测？

**H3：** proposed workflow 在预注册主指标上相对默认参数有稳定改善，并与最佳经典工具在预测精度上非劣或更优；优越性必须由效应量和区间支持，不能只看一次最优结果。

### RQ4：计算效率与稳健性

**问题：** PEST++ IES 与现有 worker 架构能否在相同 forward-call 或 wall-time 预算下提高效率，并对 seed、初始 ensemble 和失败运行保持稳健？

**H4：** 随核心数增加，墙钟时间显著下降；实际调用数、失败率和解质量均有完整收据；跨 seed 结论方向稳定。

### RQ5：层级与数据设计贡献

**问题：** ECO/SPE 层、阶段化/SA 策略和过程观测分别对预测、参数稳定性和计算成本贡献多少？

**H5：** 层级扩展只有在跨 cultivar/环境数据足够时改善留出预测；若只改善 calibration fit 而不改善 validation，应判定为过参数化。

### RQ6：易用性（可选但决定措辞）

**问题：** 新用户是否能更快、更少错误地完成一个跨作物率定任务？

**H6：** 相比 GLUEP/脚本型 dpest 的固定任务，新工具降低设置时间和关键错误率。若不做用户试验，论文只能主张“减少配置文件数量/人工步骤”，不能主张总体易用性。

## 4. 基准工具与比较边界

### 4.1 必选基线

1. **DSSAT 默认 cultivar/ecotype 参数**：仅作为预测精度参考，不是优化运行时间基线；
2. **GLUEP 固定 release/commit**：代表并行 GLUE、自动参数边界和 GUI/HPC 路线；
3. **dpest + PEST/PEST++ 固定版本**：代表 Python 模板/指令生成路线；其最新文档已出现 SPE 接口，但首页、论文和版本能力存在差异，必须固定可执行版本并逐项声明功能；
4. **proposed tool + PEST++ IES**：完整方案；
5. **原始/历史 DSSAT-PEST**：仅当代码、依赖和数据能稳定复现时进入定量基准，否则作为文献比较，不用手工近似实现替代。

GLUEP 公开材料强调并行 GLUE、统一控制文件、GUI 和 Windows/macOS/Linux/HPC；2024 论文的四个案例为小麦、玉米、大豆和马铃薯，并报告相对顺序 GLUE 的 87.4%–95.4% 时间降低。[GLUEP 论文](https://doi.org/10.1016/j.compag.2024.109513)、[源码](https://github.com/DSSAT/glue)

DSSAT 官方还列出 GENCALC、GenSelect 和 GLUESelect 等经典工具。若这些工具无法自动化、固定版本或公平分配预算，建议做功能/历史对照，而不是把专家手工操作的某一次结果作为定量赢家。[DSSAT Tools](https://dssat.net/tools/)

### 4.2 公平性合同

所有可执行基线共享：

- 同一 DSSAT binary、输入文件、工作目录隔离和硬件；
- 同一 calibration/validation split；
- 同一参数集合、init、lower/upper、变换和跨参数约束；
- 同一观测值、单位、sigma/权重和缺失规则；
- 同一失败判断、超时和重试政策；
- 同一核心数和 seed 集合；
- 同时报告 **固定 forward-call 预算** 与 **固定 wall-time 预算** 两种比较；
- 设置时间、计算时间和人工干预时间分别报告；
- 参数/预测不确定性只在能够产生 ensemble/分布的算法之间比较，不能惩罚只输出点估计的工具没有“后验覆盖率”。

每次运行保存 `benchmark_receipt.json`：工具版本、commit、DSSAT 版本、参数/观测 hash、seed、名义预算、实际调用数、成功/失败数、CPU 与墙钟时间、核心数和终止原因。

## 5. 作物与数据矩阵

### 5.1 推荐核心作物

| 作物 | DSSAT stem/家族 | 选择理由 | 最低用途 |
|---|---|---|---|
| 小麦 | WHCER / CERES | 与 GLUEP/DSSAT-PEST 文献可比；谷类格式 | C2–C4 |
| 玉米 | MZCER / CERES | 经典多环境基准；与 2020 论文可比 | C2–C4 |
| 大豆 | SBGRO / CROPGRO | CROPGRO 长表头与生育/生长参数 | C2–C4 |
| 马铃薯 | PTSUB / SUBSTOR | 不同模型家族；GLUEP 案例 | C2–C4 |
| 水稻 | RICER / CERES | 文件组合差异；与 2020 论文可比 | C2–C3，数据足够则 C4 |
| tomato/eggplant | TMGRO / CROPGRO | CUL/ECO/SPE、多收获、身份分离困难案例 | C4 应用扩展 |

全 `C:\DSSAT48\Genotype` 语料用于 E0 静态文件试验；真实科学比较只使用数据质量、许可、观测单位、管理信息和独立拆分均通过审计的作物。

### 5.2 数据拆分原则

- 优先按年份、地点或完整试验留出，不能把同一处理的相邻日期随机拆到 calibration 和 validation；
- cultivar-specific 参数需要至少跨环境约束；ECO/SPE 参数需要跨 cultivar/环境约束；
- 若只有一个地点/季节，只能做工程或探索性案例，不能作为通用性/外推主证据；
- 所有 split 在运行前冻结并 hash；模型选择不能查看 validation；
- treatment、water、nitrogen 与 observation role 均由显式元数据给出，不从编号推断。

## 6. 正式试验包

### E0：跨作物静态正确性与覆盖

**目的：** 证明文件参数化本身正确。

**样本：** 本机 56 CUL、56 SPE、51 ECO，以及论文所用版本化 DSSAT 文件副本。

**操作：** 对每个 descriptor 写入 lower/init/upper 和若干边界内随机值；回读；比较 byte span；测试换行、空白、注释、实体顺序和已知版本变体；对锚点缺失、重复、指纹不符进行负向测试。

**指标：** parse 成功率、round-trip 成功率、精确回读率、非目标字段变化率、负向案例检出率、每文件耗时；按 file kind/model family/version 分层。

**退出门槛：** 达到计划中的 C2 覆盖目标；任何静默写错均为 release blocker。

### E1：合成参数恢复

**目的：** 将优化器性能与真实数据模型结构误差分离。

**设计：** 每个核心模型家族选 1 个作物和一组内部真值参数，生成多环境/处理观测；加入至少三档噪声（例如 0、审计 sigma、2×sigma）、两档缺失和可控模型失败。真值不得等于默认或初始中心。

**重复：** 至少 10 个 seed；若成本允许 20 个。使用相同 prior/bounds 和调用预算。

**指标：** 参数归一化绝对误差、参数排名相关、90%/95% 区间覆盖、预测 CRPS/interval score、边界率、失败率和调用数。

**解释：** 预测恢复良好但个别参数恢复差，可能是等效性/不可辨识，不应强行判失败；应报告参数相关与信息增益。

### E2：真实多作物 calibration–validation

**目的：** 回答主要科学/产品问题。

**方法：** 在冻结 calibration 数据上率定，在完全留出的 season/location/experiment 上评价；每种工具至少 5 个 seed，10 个优先。若 GLUEP 的随机样本数与 IES ensemble/iteration 不可直接一一对应，则同时使用固定调用预算和固定墙钟预算。

**主结果：** 每作物预注册一个主要预测变量族和一个主指标；全局结论用分层汇总，不把所有日期当独立样本。

**次结果：** 物候、生物量、产量、多收获、偏差、区间可靠性、参数边界和失败。

### E3：并行扩展与资源效率

**目的：** 分离算法调用效率和并行工程效率。

**设计：** 同一任务在 1、2、4、8 核运行；如有 HPC，再加一个 SLURM 节点规模。至少 3 次独立墙钟重复，固定 DSSAT 输入和存储位置。

**指标：** wall time、CPU time、实际 DSSAT 调用数、吞吐量、speedup、parallel efficiency、初始化/调度开销和失败恢复成本。

不得只报告相对串行 GLUE 的百分比；必须同时给绝对时间、硬件、调用数和精度。这样才能与 2020 DSSAT-PEST 和 2024 GLUEP 的效率结论公平对话。

### E4：seed、prior 与失败稳健性

**设计：**

- 至少 5、优选 10 个随机 seed；
- narrow/wide 两套科学可辩护 prior；
- 预设 0%、1%、5% forward-run 失败注入；
- 对每次运行记录 best/median phi、validation 指标、参数边界率和 ensemble collapse 指标。

**目的：** 防止以单 seed 最好结果作为性能结论，并检验并行失败检查和 retry 是否改变统计分布。

### E5：可用性研究（建议，非必需）

**对象：** 建议 12–20 人，DSSAT 新手与有经验用户分层。

**任务：** 从给定作物数据完成参数发现、CUL/ECO/SPE 选择、观测映射、validation、运行和结果定位。对照工具选择 GLUEP 和/或 dpest，采用交叉顺序并固定训练材料。

**指标：** 完成率、设置时间、关键错误数、求助次数、SUS 和认知负荷简表；记录“工具阻断了一个危险配置”与“用户绕过检查”两类事件。

若不开展 E5，标题和摘要避免使用 “user-friendly”，改用可直接测量的 “schema-driven setup” 或 “reduced manual configuration”。

## 7. 主消融与补充敏感性

消融数量不宜过多。建议正文只保留三项，其他放补充材料。

### A1：参数文件层与作用域

| 变体 | 参数层 | 目的 |
|---|---|---|
| A1a | CUL only | cultivar 参数基线 |
| A1b | CUL + ECO | 增加共享 ecotype 层 |
| A1c | hierarchical CUL + ECO + SPE | 完整层级方案 |

所有变体保持总 forward-call 预算一致，并报告有效参数维数。主要判据是留出预测、参数稳定性与边界率，而不是 calibration phi。若 A1c 只降低 calibration error，却恶化 validation 或导致 SPE 边界堆积，应判为过参数化。

### A2：参数选择与阶段化策略

- all-at-once：所有候选参数同时率定；
- SA-informed joint：只保留预注册敏感参数，联合率定；
- SA-informed staged：物候→生长/产量→共享层级，前阶段不确定性按方案传递。

对比相同调用预算下的验证精度、seed 稳定性、参数边界率和计算开销。不得用最终结果反向选择最有利的 SA 阈值。

### A3：观测信息结构

- end-of-season only；
- + phenology；
- + time-series growth；
- + incremental/cumulative harvest（适用作物）。

该消融检验统一观测契约是否带来信息增益。2020 DSSAT-PEST 已提示加入所有过程变量未必改善结果，因此应允许“增加数据反而暴露模型结构误差”这一结论。[Ma et al. 2020](https://doi.org/10.1016/j.eja.2020.126017)

### 补充消融/敏感性

1. **定位策略：** 绝对行号 vs anchor+context+fingerprint，在受控格式/版本扰动下比较静默错误；
2. **权重：** 等权 vs `1/sigma`，作为科学敏感性而不是切换默认正确性；
3. **质量门禁：** 用故障注入评估检出率，不在正式数据上简单关闭门禁制造“消融”；
4. **ensemble size/迭代数：** 给出性能–成本曲线；
5. **prior breadth：** narrow/wide 对预测与参数可辨识性的影响；
6. **SPE 单 cultivar vs 多 cultivar：** 只作为层级可辨识性警示，不用单 cultivar 结果证明物种参数。

## 8. 指标、统计与判定规则

### 8.1 预测点指标

- RMSE、NRMSE（分母定义预注册）、MAE、mean bias；
- Willmott d 或 NSE 可作为辅助指标；
- 观测接近 0 的变量不使用 MAPE；
- 多变量不得无量纲化后又在解释中混回原单位。

### 8.2 不确定性指标

- CRPS；
- 90% prediction interval coverage probability、平均宽度和 interval score；
- 参数 95% coverage 仅用于合成真值试验；
- 对 IES ensemble 明确称为条件 ensemble/近似不确定性，不称严格 Bayesian posterior。

### 8.3 工程与效率指标

- actual forward calls、成功/失败/重试数；
- wall/CPU time、speedup、parallel efficiency；
- exact parse-back、byte-diff containment、baseline deterministic equivalence；
- 任务完成率、resume 正确率和错误诊断分类。

### 8.4 统计单位与区间

- 按 treatment/experiment/season 做 cluster bootstrap，不能把每日观测当完全独立；
- 跨作物汇总采用 hierarchical bootstrap 或混合效应框架，作物和试验作为层级；
- 报告配对差值、效应量和 95% CI，而不是只给 p 值；
- 少量预注册主要比较可用 Holm 校正；探索性比较清楚标注；
- 每种方法报告全部 seed 的分布、中位数和最差/最好范围，不能只挑最好 seed；
- 不建议造一个同时混合精度、时间和不确定性的总分；用 Pareto 图和场景化结论呈现权衡。

### 8.5 成功判定

建议在预注册中设置三类门槛：

1. **安全门槛：** E0 不能出现静默错写；
2. **科学门槛：** 至少在预定多数核心作物上，相对默认参数改善 validation 主指标，且不确定性不过度失配；
3. **产品门槛：** 与最佳可复现基线相比，至少在设置成本、计算预算、文件层能力或稳健性之一有清晰优势，同时其他主要维度不出现不可接受退化。

精确数值阈值应在查看正式 validation 结果前，结合 pilot 的噪声尺度和数据质量另行冻结。

## 9. 论文结构建议

### 标题候选

1. *A descriptor-driven and scope-aware framework for calibrating DSSAT CUL, ECO and SPE parameters across crop models*
2. *Reproducible multi-crop calibration of DSSAT genetic and species parameters with PEST++ ensembles*
3. 若完成用户研究：*An evidence-validated workflow for safe and usable multi-crop DSSAT parameter calibration*

### 摘要结构

1. 背景：DSSAT 参数率定仍受作物文件异构、参数作用域、计算预算和复现性限制；
2. 方法：描述符/crop pack、CUL/ECO/SPE 层级、统一观测契约、PEST++ IES 和验证门禁；
3. 试验：静态语料、合成恢复、4–6 作物留出验证、经典工具、扩展性和消融；
4. 结果：只填预注册主指标、CI 和绝对成本；
5. 结论：说明在哪些作物/版本达到哪一级支持，并明确限制。

### 正文提纲

1. **Introduction**：DSSAT 参数层级与异构；GENCALC/GLUE/GLUEP/DSSAT-PEST/dpest 的贡献与缺口；研究问题；
2. **System design**：身份模型、descriptor、codec、crop pack、观测/优化/执行层和 provenance；
3. **Materials and methods**：作物/数据、baseline、公平性合同、E0–E5、A1–A3、指标和统计；
4. **Results**：先正确性，再恢复与留出预测，再效率/消融/可用性；
5. **Discussion**：参数作用域、SPE 可辨识性、模型结构误差、与 GLUEP/2020 PEST 的互补关系、适用范围；
6. **Software and data availability**：commit、release、pack、manifest、许可和复现步骤；
7. **Limitations**：未覆盖作物/版本、数据量、近似不确定性、用户研究和 DSSAT 结构误差。

## 12. 论文风险与替代路线

| 风险 | 预警信号 | 处理 |
|---|---|---|
| 通用性不足 | 只有 TMGRO 达到 C4 | 改写为架构/案例论文，暂缓“multi-crop”标题 |
| 与 GLUEP 不公平 | 参数、预算或数据不能完全对齐 | 降为功能对照；只报告可验证的共同任务 |
| SPE 导致过参数化 | calibration 好、validation 差、边界堆积 | 限制作用域、加强先验，作为负结果讨论 |
| IES 区间失配 | 覆盖低或 ensemble collapse | 报告失败，调整误差模型/ensemble 设计，不称后验 |
| 用户研究缺失 | 只有开发者演示 | 删除 user-friendly 主张，保留客观步骤统计 |
| 多作物结果异质 | 平均改善由单作物驱动 | 分层报告、避免总平均掩盖、讨论适用条件 |
| 当前 eggplant 科研状态未通过 | 仍为 `science_pending` | 不进入论文结果，只作工程/demo 数据 |

## 13. Go/No-Go 门禁

只有同时满足以下条件才建议开始写结果型论文：

1. E0 达到预定 C2 覆盖，且没有静默错写；
2. 至少 6 作物/4 家族 C3、4 作物/3 家族 C4；
3. 核心 baseline 的 release/commit、配置与运行收据冻结；
4. calibration/validation split 与主指标预注册；
5. 至少一个独立数据审计者确认单位、处理、sigma 和 role；
6. 多 seed、实际调用预算和失败结果完整保留；
7. 代码、crop pack、合成数据和许可允许的真实数据具备复现路径；
8. 当前项目的 paper_data/R-only 门禁通过；
9. 摘要中的每个强主张能映射到一个主试验或消融结果。

若只满足工程正确性，可先发布预览版软件、技术报告或 software note；不要用 demo 图填补未完成的科学证据。

## 14. 审核后建议的研究顺序

1. 审批工具方案的 P0–P1，仅完成 schema、语料和预注册草案；
2. 在正式结果不可见时冻结 RQ、主要终点、公平性合同和 C2–C4 门槛；
3. 完成 CUL/ECO/SPE 静态正确性 E0；
4. 用合成数据 E1 调试 recovery 与不确定性指标；
5. 小规模 pilot 只用于确定运行预算和故障政策，不用于论文结论；
6. 冻结真实数据、baseline 和 seed 后执行 E2–E4；
7. 有资源则执行 E5；
8. 一次性冻结 paper_data，使用现有 R-only 管线出图；
9. 先写方法与限制，再填结果和摘要，避免按最有利结果重塑假设。
