# Eggplant-on-Tomato（以番茄模块为模板的茄子参数开发）开发计划

本计划以 `C:\DSSAT48\Tomato_Cal` 的 DSSAT-PEST 自动率定流水线为基础，将 **Tomato (CRGRO048/TMGRO048)** 的 `SPE/ECO/CUL` 作为“茄子（Eggplant）模块”的承载体进行增删改，并使用试验 `XXQL2501`（当前以工作区文件形式维护：`Tomato_Cal\Workspace\XXQL2501.TMX/.TMA/.TMT`）作为核心率定数据集，形成一套可扩展、可复现的系统调参方案。

本计划的目标不是“把拟合做到最好看”，而是：
- 在生理学合理边界内构造参数空间（避免多解性）；
- 先过程、后联合（Two-step Calibration）；
- 权重可解释（基于误差/方差）；
- 每一步可回滚、可诊断、可审稿。

## 0.1 借鉴 Strawberry 的“迭代版本”率定经验（辩证吸收）

`CROPGRO-Strawberry` 从番茄模板演进的论文给出的核心启发是：不要一开始就把所有参数放进联合优化，而是用“版本迭代”的方式，按机理优先级逐步引入新自由度。

将这一思路迁移到本项目（茄子、无限生长、多次采收）时：

1. Version 0（输入核对）：先确保管理、天气、土壤、种植日期与试验文件一致。
2. Version 1（温度阈值与发育节奏）：优先把影响热时/物候的温度与时间轴对齐机制做正确。
3. Version 2（源端与冠层）：在时间轴可信后，校准 LAI/器官干重，避免“用产量参数替代源端错误”。
4. Version 3（多次采收的季节分布）：当出现“前期产量偏高、后期产量偏低/反之”的结构性偏差时，优先考虑分配机制与果负载时序参数（如 `PODUR`）。若仅靠常数分配参数无法同时匹配季节曲线，应将“动态分配机制（随光热龄/热时变化）”视为模型结构升级任务，而不是继续扩大参数集合。
5. Version 4（管理与应激的结构项）：如存在明显移栽缓苗/整枝去叶等管理效应，可作为结构项显式引入（优先通过管理文件/既有开关实现；必要时再考虑模型层改造）。

注：Strawberry 中通过下调 `TRIFL` 修正叶片发生节奏的策略在茄子上不应照搬。茄子为无限生长型、叶片大小与出叶节律高度受品种与整枝管理影响，`TRIFL` 应仅用于约束“叶数/LAI 的早期斜率”，不用于解释产量季节分布。

参考资料主路径：`c:\DSSAT48\Tomato-Eppglant校准相关资料`，尤其是 `Eggplant_Calibration_Workflow`。

## 0.2 敏感性驱动的优先级—分批率定框架

本计划将 `Workspace\Sensitivity_Analyze\SA_Project_Output` 的 Morris（Screening）与 Sobol（Global Sensitivity Analysis）结果作为“分批率定”的硬依据：先解决主导过程与强交互，再进入联合优化收敛。

关键结论（以总体排序为准）：

1. 结构主导：`TRIFL`（ECO，叶片出现速率）为最高敏感度参数之一，并与 Thermal time（`TB2/TO22/TO11` 等 SPE 温度响应）共同控制发育—冠层的时间轴。
2. 产量主导：`XFRT`（CUL，最大分配上限）对多次采收累计曲线与季末产量目标具有显著总效应（Sobol STi），且与时间轴/冠层参数存在明显交互。
3. 处理响应（G×E 入口）：`FRLFF/FRSTMF/ATOP/PORPT` 等 SPE 根系与水分过程参数在本试验（水-氮梯度）下表现为高敏感度，应优先用于解释处理间差异，并作为后续“应激诊断”与管理项校正的切入点。

建议的分批率定顺序（先时间轴，再冠层结构，最后产量分配，再应激/处理差异）：

- Batch A：Thermal time 与发育节奏（SPE）+ `TRIFL`（ECO）
- Batch B：冠层/株型与源端（ECO/CUL）
- Batch C：产量与多次采收动态（CUL/ECO）
- Batch D：处理响应与应激诊断（SPE + 管理项）

## 0. 关键假设（本计划默认采用）

1. 不在 DSSAT 内新增作物物种条目（避免 GUI/数据库层面改动）。
2. 以 `TMGRO048.SPE / TMGRO048.ECO / TMGRO048.CUL` 为“茄子模块”载体：
   - `CUL` 表达品种差异（面向 `XXQL2501`）；
   - `ECO` 表达生态型/栽培类型与多次采收逻辑（面向“可泛化”）；
   - `SPE` 表达物种层面的生理过程（尽量少动，必须动时要有机制证据）。
3. 当前工程实现以 `TMA`（季末汇总）+ `TMT`（多次采收/过程点）作为观测入口：
   - `TMA`：通过 `Evaluate.OUT → PestEval.OUT / PestGrow.OUT / PestJoint.OUT` 接入；
   - `TMT`：
     - 多次采收：`FreshWt.OUT(CHPDT/CHFPW) + XXQL2501.TMT → PestHarvest.OUT`（`build_pest.py --mode eggplant_harvest`，变量口径由 `--harvest-var` 控制）
     - 过程点：`PlantGro.OUT(LAID/LWAD/SWAD) + XXQL2501.TMT → PestTmtGrow.OUT`（`build_pest.py --mode eggplant_process`）
4. stage2（联合）已支持两类“诊断驱动的工程开关”，用于把结构性偏差从遗传参数中剥离出来：
   - 处理屏蔽：通过替换 batch 文件（例如 `DSSBatch_excl_TN5_TN9_TN13.v48`）显式控制参与率定的处理集合。
   - 根系供氮参数：`RTNO3/RTNH4/RTEXF` 在 stage2 中默认启用；如需临时关闭使用 `--no-include-n-uptake`。
4. 率定核心引擎采用本项目已集成的 `PEST++ IES`，并保留敏感性分析与不确定性量化产出。

## 2. 总体工作流（高层）

1. 数据与实验文件接入：把 `XXQL2501` 的 `TMX/TMA/TMT` 引入工作区，并明确 DSSAT 输出与观测列的对应关系。
2. 建立“茄子载体参数”分层：
   - 先确定 `SPE` 的 Thermal time 响应（`TB/TO/TM` 或 `TB2/TO22/TO11` 等），把时间轴对齐做正确；
   - 再在 `CUL` 中做最小集合（只动能被本数据强约束的阶段热时/源端参数）；
  - 再扩展到 `ECO`（`TRIFL/XMAGE/RWDTH/RHGHT` 等结构与多次采收节奏；`FL-VS` 固定不释放）；
   - 最后（必要时）才触碰 `SPE` 的非 Thermal time 项（光合/呼吸/SLA/根系-水分过程）。
3. 阶段 1（序贯）：
  - 物候弱约束（当前仅接入 `ADAT→ADAPM`）；
  - 冠层与总量约束（当前接入 `LAIX/HWAM/CNAM`）；
  - 过程点弱约束（已接入 `TMT` 的 `LAID/LWAD/SWAD`，建议低权重）；
  - 多次采收产量动态对齐（已接入 `TMT`，通过 `PestHarvest.OUT` 输出并在 `eggplant_harvest` 模式下进入 PEST 观测）。
4. 阶段 2（联合）：把阶段 1 的参数作为先验/初值，进行 WLS（加权最小二乘）联合优化，并输出不确定性与诊断指标网格。
5. 固化可复现工程：把流程、权重、范围与脚本改造全部落盘，支持未来多试验、多年份扩展。
