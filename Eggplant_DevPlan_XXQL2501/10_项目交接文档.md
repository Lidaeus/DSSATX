## 3. 使用教程（从零开始到得到结果）

以下命令默认在 `c:\DSSAT48\Tomato_Cal\Workspace` 下执行。

### 3.1 前置条件（一次配置，后续复用）

**软件与路径**

- DSSAT v4.8+：确保 `c:\DSSAT48\DSCSM048.EXE` 存在。
- PEST++：确保 `c:\DSSAT48\Tomato_Cal\pestpp-5.2.16-win\bin\pestpp-ies.exe` 存在。
- Python：能在命令行使用 `python`。

**工作区关键文件的存在性检查**

- `DSSBatch.v48`：必须存在且至少包含 1 条运行条目。
- `TMGRO048.CUL.base`：CUL 参数边界与初值来源。
- `TMGRO048.ECO`、`TMGRO048.SPE`：ECO/SPE 参数承载文件。
- `build_pest.py`、`run_dssat.py`、`analyze_results.py`：三段式流水线脚本。

### 3.2 数据接入（XXQL2501）

本项目默认观测入口来自两类文件：

- 季末汇总：`XXQL2501.TMA`（通过 DSSAT 输出 `Evaluate.OUT` 进入 `PestEval.OUT / PestGrow.OUT / PestJoint.OUT`）
- 多次采收与过程点：`XXQL2501.TMT`（通过 DSSAT 输出 `FreshWt.OUT / PlantGro.OUT` 与 `.TMT` 联合生成 `PestHarvest.OUT / PestTmtGrow.OUT`）

`DSSBatch.v48` 负责把具体试验文件（`.X`）与处理号（`TN`）喂给 DSSAT 批运行。

### 3.3 快速自检（不跑 PEST，只跑一次前向）

目的：确认“批运行能跑通、输出能回写、Pest*.OUT 能生成”。

- `python run_dssat.py --param-csv pest_params.csv --batch DSSBatch.v48 --harvest-var CHFPW`

期望现象（成功标志）：

- `Evaluate.OUT` 存在且非空，且控制台出现 `Evaluate.OUT generated successfully.`（见 `Tomato_Cal/Workspace/run_dssat.py:1624`）。
- 生成/更新 `PestEval.OUT`、`PestJoint.OUT`、`PestHarvest.OUT`、`PestTmtGrow.OUT`（见 `Tomato_Cal/Workspace/run_dssat.py:1625-1647`）。

### 3.4 构建 stage2 联合率定（推荐入口）

stage2 是多输出联合率定，会一次性纳入：

- 物候（`PestEval.OUT`）
- 冠层/产量等季末指标（`PestJoint.OUT`）
- 多次采收累计（`PestHarvest.OUT`，由 `--harvest-var` 决定用 `CHPDT` 或 `CHFPW`）
- 过程点（`PestTmtGrow.OUT`）

构建 PST（示例 v11，换 `--prefix` 就是新版本）：

- `python build_pest.py --mode eggplant_stage2 --prefix eggplant_stage2_v11 --noptmax 6 --ies-num-reals 40 --batch DSSBatch.v48 --harvest-var CHFPW --param-review-mode off --pwadm-sigma0 500 --pwadm-cv 0.008`

产出（同前缀文件族）：

- `eggplant_stage2_v11.pst`
- `eggplant_stage2_v11_params.csv`（PEST 前向运行模板化写入的参数表）
- `eggplant_stage2_v11_*.ins`、`eggplant_stage2_v11_params.csv.tpl`

### 3.5 运行 PEST++ IES

- `c:\DSSAT48\Tomato_Cal\pestpp-5.2.16-win\bin\pestpp-ies.exe eggplant_stage2_v11.pst`

关键产物与读法：

- `eggplant_stage2_v11.rec`：看 `best mean phi sequence`、`best phi yet`、`analysis complete`。
- `eggplant_stage2_v11.<iter>.obs.csv`：每次迭代的观测集合（用于不确定性与残差诊断）。
- `eggplant_stage2_v11.<iter>.par.csv`：每次迭代的参数集合。
- `eggplant_stage2_v11.<iter>.base.par`：BASE 解（便于快速对照参数漂移）。

### 3.6 结果导出与诊断（推荐两条命令）

### 4.1 `--harvest-var` 的全链路

设计目标：同一条前向命令里，可切换“用干重累计/鲜重累计”生成 `PestHarvest.OUT`。

- `build_pest.py` 会把 `--harvest-var` 拼到前向命令字符串中：`Tomato_Cal/Workspace/build_pest.py:1171-1172`。
- `build_pest.py` 会把 `--harvest-var` 拼到前向命令字符串中：`Tomato_Cal/Workspace/build_pest.py:1174`。
- `run_dssat.py` 必须把该参数传递到 `PestHarvest.OUT` 生成函数：`Tomato_Cal/Workspace/run_dssat.py:1642`。

如果后续发现 `CHFPW` 率定没有生效，优先检查：

- `eggplant_stage2_vX.pst` 的 model command 是否包含 `--harvest-var CHFPW`
- `run_dssat.py` 的 `HARVEST_VAR` 是否被覆盖

### 4.2 参数边界来自哪里

- CUL 参数边界来自 `TMGRO048.CUL.base` 的 `MINIMA/MAXIMA` 行（例如 `XFRT` 上限已调到 `1.00`）：`Tomato_Cal/Workspace/TMGRO048.CUL.base:43-44`。
- ECO/SPE 边界来自 `build_pest.py` 内的显式 bounds 映射（接手者如扩展参数，请优先按该模式扩展）。

### 4.3 固定宽度写入风险

- DSSAT 的 `.CUL/.ECO/.SPE` 属于固定宽度格式，字符串替换容易破坏列对齐。
- `run_dssat.py` 使用“按表头识别列区间 + 定宽格式化”的方式更新数值；接手者修改相关逻辑时要保持列宽对齐策略。

### 4.4 当前卡点与破局思路（v12：`IPDMND` / `XFINT`）

**现象（可复现）**

- 在 `Workspace`（或 PEST++ worker）执行 `python run_dssat.py --param-csv eggplant_stage2_v12_params.csv --batch DSSBatch.v48 --harvest-var CHFPW`，DSSAT 退出码常为 `99`。
- `WARNING.OUT`（通常在 FileX 所在目录，例如 `c:\DSSAT48\TOMATO`）报：`Initial partitioning to pod/fruit in early growth (XFINT) not set properly`，错误键 `IPDMND`。

**为什么这是“路径/目录问题”概率最高**

- 报错明确指向 `TMGRO048.ECO`，而 `XFINT` 在不同目录可能存在多份：
  - `c:\DSSAT48\Genotype\TMGRO048.ECO`（默认 `XFINT=0.20`）
  - `c:\DSSAT48\TOMATO\TMGRO048.ECO`（项目中曾手动改为 `XFINT=0.30`）
  - `Workspace/worker` 目录下也会生成/更新一份（由 `run_dssat.py` 写出）
- DSSAT 寻找 `CUL/ECO/SPE` 的“真源头”受 `DSSATPRO.v48` 的 `CRD` 路径影响；如果 `CRD` 指向了一个未更新或被覆盖的目录，DSSAT 看到的就不是你以为的那份 `TMGRO048.ECO`。

**破局路线（按性价比排序）**

1) 先把“DSSAT 实际读取哪份 ECO”钉死
   - 找到本次运行的 `run_dir`：它等于 `DSSBatch.v48` 中首个 FileX 的所在目录（通常是 `c:\DSSAT48\TOMATO`）。
   - 在 `run_dir` 检查 `DSSATPRO.v48` 的 `CRD` 行，确认 DSSAT 会去哪个目录找 `TMGRO048.ECO`。
   - 在 `CRD` 指向的目录里，打开 `TMGRO048.ECO`，确认 `TM0001` 行最后的 `XFINT` 是否确实在 `0–1` 且格式正常（建议优先用纯文本方式查看，避免不可见字符）。

2) 让前向运行脚本“自带运行环境”，不要依赖外部全局配置
   - 目标：每次前向运行都在一个可控目录里启动 DSSAT，并确保 `DSSATPRO.v48` 的 `CRD` 指向同一目录。
   - 实施要点：
     - 在 `run_dir` 写入/覆盖 `DSSATPRO.v48`，强制 `CRD = run_dir`。
     - 在 DSSAT 启动前，把当前 worker 目录里更新后的 `TMGRO048.CUL/.ECO/.SPE` 复制到 `run_dir`。
   - 验收标准：同一条前向命令重复运行，`WARNING.OUT` 不再出现 `IPDMND`，并能生成非空 `Evaluate.OUT`。

3) 若仍失败，转向“格式/不可见字符”方向
   - `TMGRO048.ECO` 文件末尾存在 `^Z`（0x1A）时，有些 Fortran 读入可能出现异常表现。
   - 固定宽度字段的边界识别如果偏移，会导致 DSSAT 读到 `XFINT` 字段为空/非数，从而报 `Line: 0`。
   - 推荐做一次最小化对照：在同一 `run_dir`，只替换 `TMGRO048.ECO`，其它不动，验证错误是否随文件移动。

## 6. 常见问题（FAQ）

### 6.1 PEST++ 能跑但 `phi` 很大/波动很大

- 首查 `eggplant_stage2_vX.rec` 的 `observation group phi summary`，看是否某一组（常见 `LAIXM`）占比极高。
- 如果新增参数导致初始 ensemble 极差，优先收窄新参数边界或先锁定新参数（用参数复审 CSV 的 `status=fixed`）。

### 6.2 `CHFPW` 没进入率定目标

- 查 `eggplant_stage2_vX.pst` 的 model command 是否包含 `--harvest-var CHFPW`。
- 查 `run_dssat.py` 是否把 `HARVEST_VAR` 传进收获写出函数：`Tomato_Cal/Workspace/run_dssat.py:1642`。

### 6.3 DSSAT 批运行报错或找不到试验文件

- 确保 `DSSBatch.v48` 中的 `.X` 路径正确（相对/绝对都可，但要能从 `Workspace` 解析）。
- `run_dssat.py` 会把批文件复制到试验目录并在试验目录运行 DSSAT（见 `Tomato_Cal/Workspace/run_dssat.py:1545-1601`），因此试验目录必须可写。

### 6.4 报 `IPDMND`：`XFINT` not set properly（v12 当前卡点）

- 典型控制台：`Initial partitioning to pod/fruit in early growth (XFINT) not set properly. File: TMGRO048.ECO Line: 0 Error key: IPDMND`。
- 首要判断：DSSAT 实际读取的 `TMGRO048.ECO` 是否就是你更新的那份（看 `run_dir\DSSATPRO.v48` 的 `CRD`，再去 `CRD` 指向目录核对 `XFINT`）。
- 快速修复方向：让前向运行在 `run_dir` 内自洽（`CRD=run_dir`，且启动前复制更新后的 `TMGRO048.CUL/.ECO/.SPE` 到 `run_dir`）。
- 次要方向：排查固定宽度写入偏移与不可见字符（例如文件末尾 `^Z`/0x1A），必要时用最小化替换法定位是“文件源头”还是“文件格式”。
